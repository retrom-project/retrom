# MAME CHD 与 BIOS 候选验证

本轮实现由 runtime 的 DAT 事实驱动，没有针对单个游戏的分支，也没有数据库结构变更。服务端 Pegasus / gamelist 导入仅在元文件所在目录及子目录发现 CHD；审核支持显示并补齐缺失磁盘。BIOS 扫描按实际成员去重，再按 DAT 匹配数、文件成员数和稳定路径选择，已有安装保持不变。

## 实际产品范围

`mame-chd-bios` PFB 使用实际 ZIP + CHD 游戏完成以下检查：

- Pegasus 扫描导入 13 个游戏，0 失败；代表样本同时获得主 ZIP 与 DAT 要求的 CHD。
- gamelist 两个嵌套元文件分别验证：自身目录内改名的正确 CHD 可识别；父目录和兄弟元文件目录的磁盘不能被借用。
- 缺少 CHD 时进入审核并显示缺项；错误内容 SHA1 上传被拒绝，文件及版本保持不变；正确 CHD 上传后可运行。
- 真实 `coh3002t.zip` 候选具有相同的 6 个文件成员，包装字节不同。选中副本满足 5/5 个 DAT 必需成员。重复扫描保留全部已有 BIOS 安装。
- 已安装但缺成员的 BIOS 明确显示不完整，不被当作可运行；零匹配候选不会伪装成通过校验。
- 审核预览、正式启动、标准 Gamepad API 投币、开始、方向选择、确认、第一关移动与射击、保存、新运行实例恢复和继续操作、退出均通过。输入来自浏览器注入的标准手柄接口，没有物理手柄或移动真机结论。
- 原生即时状态、差异磁盘与 NVRAM 一起保存。封包内部使用 STORE，公共边界只压缩一次。

核心提交后的两次干净构建，97 个资产逐项一致；对应 MAME r6 发布包下载回验通过。重新使用该构建完成第一关存档与新实例恢复。

## 内容读取与缓存

默认按需路径使用有界 CHD Range，实测单次最大 524,288 字节，后续实例复用已读块。显式预加载在冷缓存中用 13 次请求读取完整 25,630,931 字节 CHD，单次最多 2 MiB；断网后继续移动和射击，新实例对 CHD 请求为 0。

发布复验发现预加载曾将 `media` 归为固件、与实际游戏读取的缓存身份不同。已统一为游戏内容，回归先失败后通过；BIOS 仍使用独立固件身份。

## 工程检查与边界

Retrom backend / Web / API / UI 门禁通过；Web 97 个测试文件、483 项测试通过。独立 PostgreSQL 集成及四视口 32 项浏览器回归通过。runtime 最终 334 个测试文件、1,935 项测试，以及 lint、类型、构建、包、固定来源、Provider 和发行聚合检查通过。MAME 14 个构建与打包检查通过。

正式配套输入由 `data/runtime-inputs.json` 固定。PFB 使用开发模块，不能充当正式 Provider 的产物身份证明；正式镜像需要通过 PR 镜像门禁，并在独立环境重跑同一游戏案例后合并。各次发布和部署证据按实际环境分别记录。

支持 CHD v3/v4/v5 完整镜像。需要父 CHD 的差分输入要求改用完整镜像；这不影响游戏需要 Parent ROM ZIP，也不影响运行中产生的差异磁盘随存档恢复。导入只做有界头部身份校验，不保证全部压缩块完整。

真实游戏只验证代表样本，不代表全部 MAME CHD 游戏。其他依赖组合由通用回归覆盖；全核心矩阵、负载、全部故障窗口和移动真机未执行，不提升 T01–T47 总体验收状态。
