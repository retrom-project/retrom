# 界面与产品行为

提供虚拟手柄的核心在普通 Player 顶部工具栏显示独立手柄按钮，使用 Lucide gamepad-2 的圆润双握柄轮廓，通过“隐藏虚拟手柄／显示虚拟手柄”和按下状态表达操作。开启时按钮使用共享选中态的紫色边框、底色和图标色；关闭时恢复普通按钮并显示带斜线的手柄图标。图标、选中态和提示统一读取已应用的显隐偏好，切换成功后同步更新，刷新后保持一致，不仅依赖悬停提示区分状态。默认开启；使用宿主 origin 的 localStorage 按 coreId 保存偏好，同一核心所有游戏共享，不同核心独立。偏好在核心挂载前应用。隐藏立即释放虚拟按键和摇杆，保留游戏原生触控与物理手柄；触摸画面不会覆盖用户关闭选择。暂停、菜单等临时隐藏与持久偏好分别管理，按钮始终可用于重新开启。复用既有 player-control 图标按钮样式与手机触控尺寸。公共方向与模拟摇杆沿用 EmulatorJS 的红色半透明圆形底座与红色圆心，圆心直径为底座的一半；拖动跟随手指，释放、取消、失焦或隐藏时回中。方向摇杆保持八方向输入，模拟摇杆保持连续轴值。

保持共享游戏浏览、管理、私人存档/收藏/最近、账号及独立沉浸模式。手机首页/资料库/我的入口及桌面管理、4K和Player状态以统一docs/design评审源为准。列表采用有界服务端筛选/真实总数；不可恢复存档置灰并展示准确原因；未同步草稿提供重试/丢弃，不假成功。

手机普通浏览器中的后台页面与用户页面均为底部导航保留滚动留白，最后一项内容及操作不能被导航遮挡。

游戏库与收藏页的“整理收藏夹”弹窗挂载到页面顶层，遮罩覆盖卡片收藏按钮和手机底部导航，不受卡片悬停层级或位移影响。窄屏、横屏与长收藏夹列表中，标题和取消／保存按钮保持可见，收藏夹选项在弹窗内独立滚动；关闭后焦点返回原入口。卡片尺寸、封面和导航布局保持原样。

共享确认弹窗（含普通 Player 的退出确认）限制在当前视口内，标题与底部操作区不参与纵向压缩，正文在剩余空间内独立滚动。手机竖屏的操作继续纵向排列；横屏且视口高度不超过500px时，操作优先横向排列，空间不足时换行，保留至少44px的触控高度。同步、取消和退出按钮始终完整可见，启用状态下可点击；长提示不裁切，默认聚焦取消及Tab／Escape交互保持原有行为。

游戏库、我的收藏、我的存档与最近游玩采用向下滚动自动追加加载，每次最多24条，服务端筛选、排序及真实总数不变。按名称排序时统一使用标题字母序：A–Z 在前、# 最后，中文按拼音首字母归入对应字母并与拉丁标题相邻。管理员在游戏发布信息中可填写“排序名”修正多音字，输入框下说明当前所属字母；留空按标题排序。接近列表底部时读取下一页，同一列表不并发拉取下一页；底部显示已加载/总数、加载中、重试或已加载全部，并保留可键盘操作的“加载更多”入口。筛选变更从首批重置，取消旧请求，旧响应不能混入新结果；追加失败保留已加载内容并等待用户重试，空结果或已到总数后停止。删除、改名、收藏整理后按24条一批重新读取已加载范围，保留卡片直到刷新完成；收藏批量选择作用于“全选已加载”。普通存档仍按存档分页，已加载存档按游戏合并分组；沉浸模式存档列表继续由服务端先按游戏分组，再按每批24款游戏追加。

领域细节统一见[http-api-contract.md](http-api-contract.md)，完整验收见[project-acceptance.md](project-acceptance.md)。

安装后的 PWA 面向移动游玩，保留首页、游戏库、我的存档／收藏／最近、账户设置和游戏运行。所有独立窗口均隐藏管理后台入口（含“我的”、侧栏和导航抽屉）及游戏详情的“退回审核”；直接访问后台地址返回首页，识别窗口模式前不挂载后台。管理员身份不改变这一呈现，游戏全屏期间保持用户侧。普通浏览器继续按权限展示管理功能，不因发生安装事件而切换为 PWA 界面。导航、按钮和卡片沿用原布局与共享样式。

账户设置在原账号资料与密码表单下增加“Retrom 应用”面板，复用共享面板、44px按钮与状态标记。浏览器实际提供安装事件时显示“安装 Retrom”，iOS 展示分享菜单的“添加到主屏幕”指引，独立窗口显示已安装。安装需要安全连接；启动入口固定为首页，普通手机页面保留系统方向，游戏继续沿用既有横屏规则。面板明确游玩与同步需要联网。普通浏览页断网显示非模态提示；检测到等待中的新版本显示“点击更新”按钮（靠提示条右侧），不自动刷新。两类提示悬浮在内容列顶部居中、滚动时保持可见（窄屏位于固定顶栏下方），层级高于抽屉／弹层、低于 toast，不占据布局空间、不挤压页面内容。任何 Retrom 窗口处于 Player 或沉浸界面时阻止主动激活更新；用户退出后再次确认，只有发起更新的窗口刷新，其他窗口不被导航。离线文档为独立、无账号资料的居中品牌卡，使用同一字体／颜色／按钮 token，提供连接说明和“重新连接”入口，不加载账号API、运行核心或个人数据。

登录页复用统一认证页样式：暗色画布居中480px单卡、34px内边距、紫色R与Retrom品牌行，“欢迎回来”紫色眉题及独立“登录”主标题。用户名／密码保留共享44px控件、自动填充与键盘提交，紫色登录按钮占满表单宽度；底部分隔线后居中说明“新账号需要管理员邀请。本阶段不提供自助找回密码。”。手机使用16px画布边距和20px卡片内边距，卡片内表单不再叠加第二层内边距，品牌／标题／表单／分隔线保持同一网格，内容可自然纵向滚动；登录失败显示共享错误Toast并保留表单可访问错误描述，提交期间禁止重复操作。用户旧版参考为卡片局部裁剪；4K／150%验收使用2560×1440 CSS视口及DPR1.5，卡片物理宽720px，不把裁剪尺寸当作视口。

未登录访问受保护页面时，登录地址携带原页面路径、查询参数和页内位置；登录失败或刷新登录页保留该目标，登录成功后通过完整页面导航替换当前历史记录返回原页，清空登录前的路由缓存，避免重复追加页内位置。已登录访问带返回目标的登录页同样返回目标；直接登录默认回首页。返回目标仅接受站内绝对路径，外部地址和认证页面回退首页，避免外跳和登录循环。跳转判断使用同一次路由状态的路径与查询参数，不能混用路由路径和提前变化的浏览器地址。

首页“一直喜欢的”有封面时保持原图片展示；无封面时在原5:7封面槽内显示固定居中的装饰性字母R，不使用游戏标题或首字。卡片尺寸、标题与平台文字布局保持不变；手机仍使用独立首页布局。

游戏库与收藏的浏览卡片不展示游戏标签，保持封面、标题、目录信息与原有辅助行的固定排布，不能因标签数量增加卡片高度。首页及最近页保留各自现有卡片布局；标签仍用于筛选，并在游戏详情与管理编辑中展示。图库卡片“最近游玩”读取当前用户真实lastPlayedAtMs，未玩显示—；紧凑日期显示月／日与时分，完整本地时间保留在title中。手机卡片沿用紧凑布局，不显示该辅助行。

首页“换个平台逛逛”仅展示已发布游戏数大于0的目录，保留真实数量与目录入口；没有符合条件的目录时隐藏整个区块。首页平台插画按当前runtime catalog的平台标识解析本地资源；同一硬件家族可复用插画，未知平台或加载失败显示同尺寸手柄占位，不能留下裂图或改变目录卡片高度。

首页顶部固定展示当前用户最近实际游玩的游戏，不因其他游戏有较新存档而替换。通过现有按游戏筛选、按最近排序的存档接口读取该游戏最新一份存档，不受首页全库存档摘要数量限制，也不比较存档是否在最后一次游玩中产生。有存档时保持原上线排版：“继续上次的冒险”、标题、目录与存档类型／完整时间同一信息行、“从存档继续”与详情链接、启动说明、底部“查看存档”。时间、启动目标与右侧截图来自同一份最新存档；不可恢复时禁用继续并引导查看存档详情，不偷偷切换较旧存档。游戏内存档说明启动后在游戏内读取，核心变更保留原确认机制。

只有该游戏完全没有存档时，信息行改为“上次游玩 · 完整时间”，主按钮改为“新的开始”，说明为“本次将启动全新游戏”，右侧展示平台插画。无存档按钮与正常“从存档继续”按钮等宽，复用原按钮尺寸；“查看存档”始终保留。有存档但截图缺失或请求失败时提示截图暂不可用，不冒用其他图片。首页恢复上线前的自然块级排列、字号、内边距和响应式断点，不新增独立存档状态行、上下分组、空白占位或额外卡片高度；手机仍隐藏右侧素材。无游玩历史时引导浏览游戏库。实际running记录、存档语义、API与数据库结构保持不变。


共享控件与布局以 `web/styles/tokens.css` 和 `web/styles/controls.css` 为唯一样式来源；页面只安排间距、尺寸和对齐。按钮、文本框和选择器默认 44px 高，图标与文字垂直居中，组合输入只由外壳绘制边框和焦点环。封面保持 5:7；封面、控件、面板、弹窗分别使用 4/6/8/12px 圆角。桌面侧栏账户行及管理切换按钮均为 44px，账户菜单保留设置/退出图标，服务状态点读取真实 readiness，焦点和悬停均可查看提示。来源扫描与待审核为游戏入库的缩进子项；子项选中时父项保留上下文高亮。左右抽屉统一使用40%深色遮罩、不模糊底层页面；抽屉正文独立滚动，底部动作保持可见。

沉浸入口保留全部游戏、最近游玩、收藏游戏、我的存档及游戏数大于0的人工目录，按当前 API 返回的真实总数展示，已取消的游玩时长和次数不回填。平台卡片文字左对齐，平台名固定单行并省略超长中文或英文，完整名称保留在标题提示与可访问名称中；相邻卡片高clamp(250px,39dvh,560px)，当前卡片高clamp(330px,48dvh,680px)，名称长度不能改变卡片高度。卡片名称使用完整标题行高，入口说明、名称、数量和操作提示不参与纵向压缩；顶部装饰字母显示完整代码（ALL、RECENT、FAV、SAVES 或平台 ID，最多10个字符），在剩余空间内缩放，较长代码按卡片宽度分档缩小，不截断单词；紧凑高度只收紧内部纵向留白，不改变主／相邻卡片的宽高、缩放和位置。装饰字母字号由共享 token 按所在槽位高度限制，当前卡片封面叠层保持 5:7 并受内部高度约束。当前卡片保留最近游戏封面叠层与位置指示；游戏列表标题和收藏标识分别对齐，存档名称留在当前游戏的存档区，不提供上一页/下一页按钮。游戏库、收藏、最近与存档游戏列表均在左侧滚动区域接近底部时自动追加，每次24款；键盘/手柄向下浏览到已加载边缘同样触发追加，保留当前选择和已加载内容。追加失败只显示重试，不自动重发；切换收藏夹或目录重置首批。收藏夹选择器留在列表标题区域；存档截图在主预览区域完整展示。游戏数为0的人工目录不显示入口；全部游戏、最近游玩、收藏游戏与我的存档为空时仍可进入并展示空态，不伪造封面或游戏。

沉浸模式保持大屏横向布局（至少 960×540），不满足时提供返回普通界面的明确入口。标准手柄任意按键认领；键盘方向键也可开始浏览。方向键选择、Enter/A 确认、Escape/B 返回、S/Select 系统菜单、Y 收藏、F 全屏；PageUp/PageDown 或 LB/RB 在游戏列表翻一屏、在平台页跳 5 个入口；按标题排序的全部游戏、目录与收藏列表中，Home/End 或 LT/RT 跳到上/下一个字母分组（A–Z、#，由服务端字母序决定），按住连续触发；最近游玩与存档按时间排序，不提供字母跳转。列表以窗口方式加载：跳到未加载的字母时直接从该分组起点读取一批，不逐页读取之前的内容；向上移动、向前翻页或滚动到列表顶部时补载前一批，选中项按列表位置保持不变，序号显示在完整列表中的位置。字母跳转把目标显示在列表顶部，并在列表上方短暂显示字母与“位置 / 总数”，不拦截指针。高度不低于 720px 时，列表右侧显示实际存在的字母索引，当前字母高亮，点击直接跳转；更矮的窗口隐藏索引，仍可用扳机跳转。底部提示随视图列出适用键位，960 宽度下收紧间距仍完整单行显示。游戏详情封面区以当前封面或存档截图模糊放大作背景并在切换时淡入，清晰封面、视频与存档警告保持在上层；启动按钮位于标题右侧，简介按可用高度只显示完整行，末行省略，悬停可查看全文。Tab 保留正常焦点移动，弹窗约束焦点并支持 Escape。右上全屏恢复入口与时钟同排且不遮挡时钟。系统菜单保留背景音乐与游戏音量/静音、全屏和退出；背景音乐使用已随应用分发的 Insert Coin OGG，自动播放受阻时在顶栏时钟旁显示“启用背景音乐”，下一次键盘或指针操作自动重试；它不遮挡内容、不浮在弹层之上，手柄输入不构成浏览器播放授权，因此保留该按钮；音量或静音立即生效，离开沉浸界面停止播放。游戏音量在运行就绪后通过 Provider 的公开 setVolume 应用，无法调节时报告错误；控件不能以仅写偏好冒充已调节运行音频。

实际有横向溢出的列表、筛选轨、标签栏、类别轨和表格支持鼠标垂直滚轮横移；只有当前方向还能移动时才消费事件，到边界后恢复页面滚动。原生水平手势、Shift滚动、Ctrl/Meta缩放以及指针内的纵向滚动区域保持原行为；自绘横轨与其实际容器共享位置。手机运行依赖统计栏和图库平台栏使用自由横滚，不启用吸附，避免小步滚轮被拉回；触摸可继续自由滑动。

UI 交付门禁为 `make web-ui-check` 与 `make acceptance-case CASE=ACC-RF-BROWSER`，后者使用质量文档声明的独立数据库/runtime/Provider输入。另需比较真实旧新页面及状态：1440×1000、390×844、2560×1440/DPR1.5，覆盖长列表、空态、焦点、弹层及沉浸音频/输入。静态评审稿仅定义设计，不替代实际产品证据。

Player普通模式顶部左侧只保留返回按钮，不显示游戏名称、核心或平台；右侧保留存档状态、调试、创建存档、暂停与更多操作；PC和手机的手动全屏/退出全屏入口统一放在更多操作菜单中，顶部不重复展示。PC鼠标移入顶部整条14px边缘或菜单栏时展开，移开后收起；只悬停不暂停。点击菜单栏任意位置（包括空白和只读操作）请求暂停，重复点击保持暂停；点击游戏画面立即收起工具栏和更多菜单并继续，清除此前的悬停和焦点保持状态；触屏合成悬停不能撑开工具栏，不能因连续点击菜单误恢复。暂停状态仍允许菜单收起，键盘焦点及活动对话框保持控件可达；触屏保留点击把手、暂停/继续控件；主动点击把手展开后保持可操作，点击游戏画面时收起，避免触摸操作中途自动消失。启动按钮在请求Run前使用本次点击请求文档根全屏，审核试玩、重新开始和读档共用；浏览器不支持或拒绝时继续启动并保留手动全屏入口。启动失败释放本次方向锁并只退出本次请求进入的全屏，不改变先前已开启的全屏。展开更多菜单后点击游戏画面将关闭菜单；同源canvas与隔离iframe均需实际点击验证，切换系统窗口或游戏自行获得焦点不能误关闭；工具栏展开期间由透明画面点击层接收收起操作，收起后恢复游戏输入。启动时中央440px面板展示最近三项真实启动任务，进度来自LOAD_TASK实际字节，未知进度使用不定动画，不按定时器伪造百分比。桌面模拟器设置为底部820px工具栏，手机使用右侧抽屉；画面模式、音量/静音和原生设置调用现公开能力。独立下载截图入口已移除，存档缩略图和审核封面仍使用截图能力。

GAME_SAVE自动同步在后台完成：临时导出保持工具栏原有的显示或收起状态，正常上传期间不展示草稿恢复面板，成功不弹出通知。用户主动同步和重试保留明确结果；失败、版本冲突及未同步草稿仍提供重试或导出入口。真实运行状态、存档版本检查、持久化及确认流程保持。

按需加载的游戏内容遇到网络中断或超时，runtime 发出 `CONTENT_NETWORK` 的 WAITING，Player 在工具栏下方居中显示非模态提示“网络连接中断，正在重新连接…”及“恢复后会从这里继续，也可以退出游戏。”（role=status，不拦截游戏输入，普通与沉浸模式一致）；收到 RESTORED、运行失败或退出后隐藏。等待期间游戏停在当前读取处，不结束运行。

普通INSTANT退出先暂停，520px对话框保留标题/说明、内层提示框及“创建存档 / 取消 / 退出游戏”顺序。创建成功后留在对话框并禁用重复创建；失败保留重试入口和草稿。取消按旧版保持暂停，点击画面继续；确认退出时先停止横屏与全屏自动恢复，再释放本次游戏设置的方向锁并返回详情；进入前非全屏时退出游戏全屏，进入前已全屏时保留。方向恢复由设备原有旋转规则决定，退出后不得再次锁回横屏；取消退出继续保持游戏显示状态。沉浸运行不显示普通HUD，以M或Select+Start双击打开620px横排游戏菜单，默认取消，左右选择、Enter/A确认、Escape/B取消；取消需手柄neutral120ms后仅恢复由菜单暂停的运行。GAME_SAVE手动同步和退出检查均使用EXPORT；捕获/上传失败不得自动导航，必须展示失败及再次明确的退出决定。沉浸退出保留全屏并返回原目录、收藏夹、分页与游戏/存档选中项。只有收到Player返回标记时才将焦点交给新沉浸页面，保留手柄身份与120ms松键等待；返回后的B、方向、A必须继续有效，持续按住退出用的A不能自动重新启动。

游戏窗口快捷键由Provider统一捕获并通过同一V1的HOST_SHORTCUT事件交回Host。普通模式策略为Escape菜单与声明允许的P暂停；沉浸策略仅KeyM菜单。运行游戏时单独Select不打开普通菜单或工具栏，保留核心输入；沉浸游戏的Select+Start双组合和沉浸浏览页S/Select系统菜单保持原行为。弹层打开时策略为空并抑制游戏输入，编辑字段、组合输入、修饰键与重复keydown不触发快捷操作。同源与隔离游戏共用公开setHostShortcutPolicy，Host不跨来源窥探或建立旁路消息。

GAME_SAVE（含J2ME RMS）显示“同步存档 / 取消 / 退出游戏”，不得显示即时快照的“创建存档”。说明明确平台只保存游戏已写入的数据，不保存当前画面的即时进度。同步中的菜单锁定操作；已有草稿可从菜单直接重试。顺序固定为EXPORT、浏览器草稿、服务端持久化、Runtime acknowledge；运行中确认失败保留相同commitId草稿，重试不重复创建存档，成功提示在ack后出现。若服务端已持久化且Runtime正常进入EXITING／EXITED，则不再确认已释放的运行实例，确认中被正常退出打断也不生成失败草稿；FAILED仍保留失败。最终退出快照等待正在进行的保存结束，再选择覆盖ID及版本。非菜单卸载等待正在进行的保存，再检查最后的脏数据；同一失败快照复用原草稿，不能生成重复提交。

退出请求只等待公共CHECKPOINTING阶段结束后再按实际运行状态暂停；网络上传期间应立即显示菜单并锁定三项操作，不能把上传等待变成无反馈的返回按钮。等待监听需在成功、失败、退出及卸载时清理，Escape不得同时打开底层更多菜单。

首页接收标准手柄任意按钮的按下边沿，显示“进入沉浸模式？”确认层；摇杆移动或未连接手柄不改变普通首页。触发键需先松开120ms，默认选择取消，左右选择、A/Enter确认、B/Escape取消；取消后经过500ms中立冷却再允许新提示。断开或非标准映射显示准确提示。确认时尝试浏览器全屏并进入沉浸平台页；拒绝全屏不阻断浏览。

游戏修改入口由公开getGameEditor能力决定，仅在RUNNING/PAUSED可用。普通模式位于更多操作，打开前暂停，关闭后仍暂停并将焦点还给更多按钮；沉浸游戏菜单追加“游戏修改”，面板关闭回到原暂停菜单。面板宽880px、最高820px，桌面类别横向滚动、条目内部滚动；手机横屏等高度不超过500px的窗口采用左侧136px类别导航、右侧内容区，两侧独立纵向滚动。搜索、角色切换、说明和条目在右侧同一滚动区，顶部返回按钮始终可见；键盘弹出时面板适应可视高度。使用40项分页和按名称查找；支持金币、物品、装备、变量、开关、角色、技能、状态、职业、队伍和事件独立开关等运行时实际类别。地图和事件读取、修改全部经过公开接口，Host不得读取引擎私有对象。写入成功后才提示，失败可重试；GAME_SAVE说明须在游戏内保存后同步，不能将修改结果称为即时快照。地图选择弹层独立处理Escape/B并回焦点，不能误关闭整个修改面板。

J2ME 在具备触屏指针的设备上由 runtime 显示触屏控件：横屏左侧为固定底座的圆形摇杆，中间保留完整游戏画面，右侧第一排为“左软键／确认／右软键”，下面按手机排列 1–9、*、0、#。确认与数字5独立；软键名称不写死为菜单或返回。摇杆中心有死区，拖动支持四向及斜向双方向，松手、取消或丢失指针捕获后回中并释放。支持摇杆与右侧按键同时触摸，同一动作的多个触点及手柄共同持有时仅在最后一个来源松开后释放。暂停、导出存档、Host 输入抑制、失焦、隐藏和退出时清理触点；恢复后不重放已经清理的触摸。按键有效区域至少44px，使用运行时共享的控件色彩、字号及6px按钮圆角；圆形摇杆是明确的方向操作形状。控件不遮挡画面，Provider 保留核心的响应式缩放。runtime 自身支持竖屏屏下布局；Retrom 手机仍遵守既有横屏游玩提示及方向限制。

待审核右上“快速审批”处理当前筛选的全部页：先取得完整候选快照，每批最多100项检查DAT必需成员、BIOS依赖及CRC提示，审批最多3个并发。必需ROM／Parent／BIOS齐全且无CRC不匹配时可以批准，缺少可选文件不影响；缺少必需成员或大小不符保持待审核，检查错误和版本变更分别报告失败，允许重试。运行期间锁定筛选和分页，进度最多展示前20项失败，结束Toast显示真实计数，包括因CRC提示跳过的游戏数。CRC不匹配的条目保持待审核，由用户手动批准；测试运行可选，不能作为人工批准的前置条件。游戏管理“文件与管理操作”保留替换和删除两项，移除内容文件清单，每项按钮右对齐。

待审核详情顶部使用单一紧凑审核栏：封面在左，标题与目录在中，运行、丢弃、发布在右；手机操作移至下方。所有尺寸移除“游戏内容”区和“已接收/已读取”等重复状态。下方的“运行条件检查”仅按已保存配置展示真实结果、具体内容失败原因和缺失必需文件，提供“管理运行依赖”与“重新检查”；审核侧只展示缺失文件名称与核心；具体“文件校验要求”放在运行依赖对应条目中，按核心分别展示已知要求大小、SHA-256或MD5，未知显示“未声明固定大小或校验值。”，长校验值完整折行；“已安装文件／实际大小”独立展示安装事实，不能把已安装摘要当成要求。快速审批结果可展开查看缺失条目及文件，缺少可选项或检查失败不得误标为缺失必需项。ROM、Parent ROM及BIOS的CRC不匹配在运行条件检查下方独立全宽区域提示，文件名和校验值可折行，详细成员与要求/实际CRC默认折叠且内容区域有界滚动；不增列表列宽、不挤占审核栏。CRC不匹配不阻止导入、准备运行或人工批准；缺失文件和大小不符仍按内容规则处理。DAT必需成员缺失、大小不符、缺少必需BIOS及检查失败时不能发布，服务端批准前按所选核心重新检查并核对游戏版本；CRC差异不限制人工批准，检查通过也不代表完整运行验证。审核详情点击“通过并发布”成功后按统一待审核列表默认名称顺序读取首条，并替换导航到该详情；没有待审条目时返回 `/admin/reviews`。发布失败留在原页，发布成功但后续列表读取失败时提示已发布并返回列表，不能误报为发布失败。切换游戏ID需重新建立详情编辑表单；丢弃入口的原有行为保持。

管理与审核详情在桌面并排时，发布信息及媒体标题栏均以原发布信息56px高度为基准，媒体侧减小上下内边距，通用44px控件不缩小；并排时标题基线与分隔线对齐，手机保持既有纵向堆叠，媒体标题及按钮可增高容纳，不裁切控件。支持 DAT 的核心共用可搜索的“ROM 集（DAT）”控件，按 ROM 集短名称、游戏名称与版本搜索当前核心实际构建配套的 DAT，排除 BIOS、设备和不可运行条目。文件名未匹配时保留未选中；已匹配或自选结果均可修改，也可按文件名重新匹配。选择按核心分别保存，切换核心不带入前一核心的条目；返回时恢复该核心的选择。结果列表有界滚动并分页，长名称折行，键盘可选，旧请求取消且延迟结果不覆盖当前选择。更换 ROM 集或入口后先保存，再按新配置检查或上传 Parent；未保存时禁用父包上传。保存只移除不再依赖且没有被其他核心引用的 Parent，并沿用正常延迟清理；保留原始 ROM 与 BIOS 字节。

街机运行配置按所选核心读取已保存配置的runtime父包事实，展示精确缺失ZIP名和上传入口；Parent候选排除游戏入口自身。上传按当前版本直接保存父包并更新该核心配置，成功后重载详情、文件与版本，并保留当前所选运行核心；新游戏重新选择其默认核心，当前核心被移除时才回默认；应先保存其他资料修改，失败保留重试。缺失检查与实际启动校验分离，上传成功不能声称游戏必定可运行。

标签管理搜索保留“搜索标签名称”占位与可访问名称，隐藏可见的“名称搜索”标签，搜索与筛选行为不变。审核与正式游戏共用标签多选器；已选项持续使用紫色背景和文字，不只显示勾。未选项的悬停使用独立的surface-subtle背景，键盘活动项另有轮廓；鼠标移开仍保留全部已选项状态，取消选择后恢复。已选标签气泡复用tag-chip-label文字边缘裁切与flex居中，删除图标在无额外内边距的20px按钮内居中；字号、字重和20px删除按钮保持原样，标签与图标垂直居中，完整显示中英文。

目录管理提供“一键创建推荐目录”，按旧97项产品模板与当前已安装的平台/核心交集创建；已有slug、相同平台与默认核心、或相同平台与推荐名称的目录均跳过（改过默认核心的同名目录仍保留），保留禁用状态和用户配置，部分失败可重试。标签管理提供“一键创建推荐标签”，补齐旧10个常用类型；现有有效标签跳过，删除后同名标签新建且不恢复历史关联。只有精确的名称冲突才计为并发已存在，其余错误必须报告。

管理导航与页面统一称为“运行依赖”；具体BIOS、RTP等运行文件的名称、要求及校验信息按实际条目展示。页面仅提供依赖列表、上传、替换和移除；BIOS扫描入口与进度统一放在“来源扫描”页，模块显示名不改变内部bios路由或数据契约。

DOS审核与游戏管理的运行配置使用可搜索“启动程序”选择器，按完整包内.exe/.com/.bat路径选择，搜索不区分大小写；显式选择“使用核心启动菜单”才移除entryPath。候选仅在DOS编辑控件挂载时读取当前包。换包保留已有显式入口，失效时显示完整旧路径并要求重新选择，刷新后仍提示；原先选择启动菜单时，即使新包只有一个可执行文件也不自动切换。内容文件身份或entryFile变化刷新候选，过时响应不能覆盖当前列表；读取失败保留选择并提供重试，不冒充入口已失效。


来源扫描页并列“游戏扫描”和“BIOS扫描”：游戏扫描提供“本地扫描”主入口，桌面端另有次要按钮“浏览器上传”（手机不显示）。“本地扫描”打开右侧目录抽屉；在“服务器目录”下方提供必选的“文件组织形式”下拉框，选项为 metadata.pegasus.txt、gamelist.xml 和“散装文件（每个文件或文件夹一款游戏）”。“浏览器上传”打开右侧“浏览器上传游戏”抽屉：必选的文件组织形式（同上三项，选中后显示该形式的组织说明）、可拖放文件或文件夹的虚线区域及“选择文件”“选择文件夹”按钮、已选文件摘要（数量、总大小、前8项及清空）；散装文件形式显示“识别结果”区域（将识别的游戏数与前6个名称；只选一个文件夹时提供“把该文件夹里的每个文件作为一款游戏”勾选，文件夹内只有文件时默认勾选）、超限提示，上传中显示总字节与文件计数进度条并禁止关闭；失败保留会话可“继续上传”，“取消上传”删除会话后关闭。游戏扫描卡片下方的“未完成的上传”列出当前管理员尚未扫描的上传（文件数、组织形式、已上传/总大小、有效期），已传完的显示“待映射目录”与“继续映射”，未传完的显示“未传完”与仅桌面可见的“继续上传”（以原组织形式打开抽屉并要求重新选择路径与大小一致的原文件），均可“放弃”；没有时不显示该区域。上传完成即读取来源集合并回到页面映射目录，映射标题显示“浏览器上传 · N 个文件”而不显示服务器暂存路径，之后的开始扫描、跳转与错误保留规则与本地扫描一致。每次打开均未选中，必须手动选择后才能读取来源集合，随后映射目标目录，点击“开始扫描”并成功创建扫描后立即跳转 `/admin/reviews?scanId=<任务ID>`，不等待扫描完成；scanId仅定位当前游戏扫描进度，不参与游戏来源、批次或列表筛选；启动失败保留当前映射与原错误提示。正常进入待审核而未携带scanId时不展示进度。进度按精确任务ID在扫描列表分页查找（每次最多1000条），不替换成其他最新任务；筛选、翻页和刷新保留scanId。总数尚未确定时使用不定进度，展示已扫描、已导入、跳过和失败计数；完成、部分失败、中断及取消分别说明，终态停止轮询。读取失败或未找到任务可重试并进入来源扫描；处理数、导入数或状态变化时自动刷新审核列表。来源扫描中的游戏任务链接同样携带该ID，BIOS任务仍进入运行依赖。BIOS扫描的“平台范围”“核心范围”标题右侧各有独立“勾选框＋全选”控件，覆盖本组全部平台或核心条目（含滚动区未显示项），全选后勾选框选中并切换为“取消全选”；部分勾选时显示半选状态与“全选”，不影响另一组。目录尚未加载或本组为空时禁用全选，提交期间锁定范围操作。成功后保留现有扫描页行为；共用进度列表按scanType显示对应名称和计数，游戏任务进入待审核，BIOS任务进入运行依赖。目录选择从服务进程的 / 开始，不再选择配置来源根；输入绝对路径后点击“进入目录”或按回车才读取，未应用的输入不能启动扫描。目录列表支持进入子目录、上级和读取失败重试，仅展示服务进程实际可见的挂载与权限。内容替换也填写绝对路径；来源只读，接收后复制到受管存储的所有权不变。

Player启动和正常退出使用替换导航，避免浏览器历史重新进入已结束的Run；默认返回地址保留查询参数与锚点，显式沉浸返回仍保留原选择。存档卡片操作菜单在外部点击或打开另一卡片菜单时关闭；Escape关闭并回到触发按钮，外部点击保持目标原有焦点，重命名和删除仍正常执行。

存档大小统一使用十进制 B／KB／MB／GB／TB（1KB = 1000 字节），保留最多一位小数；普通存档卡、详情页存档卡和沉浸存档缩略图均显示大小，并提供精确字节数提示，最近保存摘要同样显示大小。沉浸模式“我的存档”中，每个有存档的游戏只占一个条目；服务端在分页前按游戏分组，左侧列表与平台入口均按游戏计数。上下选择游戏，左右或可见箭头切换当前游戏的存档，A／Enter 加载选中存档。选中项只滚动其所属的游戏列表或存档缩略图区域，不能带动沉浸外层容器与提示层。截图、名称、时间、大小和冻结核心随选择同步；无法恢复的存档允许查看但不能启动：原因以居中蒙层覆盖大图，缩略图中央使用禁止图标，不在底部资料区重复原因。游戏列表向下追加，单个游戏的存档仍左右切换并有界读取；返回地址以 Game ID 标识游戏、Save ID 标识存档，返回后按24款一批恢复到选中游戏所在范围；跨存档页及退出游戏后保留所选存档；切换游戏等待完整存档列表时，使用该游戏在分组列表中已返回的存档截图维持主预览与缩略图布局，不能闪回封面、视频或重建预览节点；显式指定旧存档时不能改用最新存档作为预览。存档标题栏使用独立的左侧标题/计数、中间操作提示、右侧切换按钮三列；计数区始终占位，未知时显示“— / —”，请求开始/结束与数字位数变化不能推动中间提示或按钮。读取超过500ms才显示“正在读取存档”，快速完成时不显示；切换游戏或存档页重新计时，完成或离开后取消提示。错误立即显示并可重试；读取或错误期间始终禁用继续，只有当前请求成功解析的存档可以启动，不能回退启动最新存档。960×540 下存档区至少 240px 高，缩略图、大小和加载按钮完整可见。缩略图统一 16:10，未选中项缩小但保留大小标签，下方日期使用“月/日 时:分”紧凑格式并在悬停时显示完整时间。平台封面按 Game ID 去重后取最多三张，入口显示真实游戏数，右侧单独显示当前游戏的存档总数。

游戏管理详情的“替换游戏内容”和“删除游戏”操作各自采用左侧标题／说明、右侧按钮的同行居中布局，手机按操作区分行但每个按钮仍与自己的说明同行。“替换游戏内容”确认弹窗说明后台准备完成后生效，可离开页面；提交202后关闭弹窗，在该操作说明下显示真实阶段与可用的“取消内容替换”。等待、准备、转换、检查、打包校验、发布分别说明，接收不显示成功Toast；取消中保留状态直到清理结束，发布阶段禁取消并说明结果确认期间无法取消。完成后才显示成功并刷新资料，失败/中断展示安全中文原因和“刷新游戏资料”。初次进度读取已完成且结果版本新于当前资料时只刷新一次资料，不重复历史成功Toast；相同版本结果保持原样。初次进入管理详情读取当前替换，活动态每两秒串行查询、终态停止；读取失败提供“重试读取进度”，过期/被新操作替代明确提示核对资料。活动期间禁止再次提交，继续使用同一共享按钮、说明文字和操作布局，不增加任务中心。扫描进度遇到CONTENT_NORMALIZATION_FAILED显示“内容转换失败，请检查游戏来源与补丁文件”，不裸显示内部错误码。标签管理从搜索和操作栏直接进入列表，不展示顶部“活动标签”统计容器。Parent 文件等原生多选列表保留滚动和键盘多选语义，不显示单选下拉箭头。

游戏入库与来源扫描首次读取最近100项进度，仅当结果存在pending/running任务时，在上次请求完成3秒后继续读取；空列表、全部终态或读取失败后停止自动请求。页面隐藏时暂停轮询，重新可见时刷新一次；离开页面取消请求和计时器。可用“刷新进度”读取其他管理员新建的任务；本页BIOS扫描成功后立即刷新并按状态恢复轮询。待审核精确scanId进度共用同一轮询节奏，终态仍保留结果。

带有运行配套文件能力的核心在审核页显示统一资源区，上传控件接受 runtime 声明的扩展名；Parent ZIP 与 CHD 光盘分别列出缺失或关联路径，光盘不进入 Parent 多选框。保存入口变更后按当前核心重新检查并清理无其他引用的旧 Parent；审批前试玩保持可选。

已发布游戏详情返回导航行的右侧提供管理员专属“退回审核”次要按钮，游戏管理详情右上同样提供。提交时禁用重复操作；成功后替换导航到同一Game ID的审核详情，失败留在原页并刷新版本。退回后普通游戏库隐藏，保留文件、媒体、配置、标签及私人存档／收藏／最近关系。审核中的DAT缺件独立显示文件名、核心、ROM集、要求大小及缺失／大小不符；五项以内默认展开，多项可折叠且正文最高20rem滚动，长成员名完整折行，不挤压顶部操作栏。正常启动保留既有检查，不新增完整性门禁。

Player启动或游玩失败沿用居中错误面板，先显示按失败类别生成的可读提示，再逐行呈现Provider保留的核心错误原因，包括明确的缺失成员名。版权、普通进度、可恢复警告和JavaScript堆栈不作为错误正文；运行码及脱敏堆栈保留在诊断事件中。没有原生原因时使用类别提示，不猜测具体缺件。长文件名自然折行，错误面板仍受视口高度限制。核心报错清理后不得被mount Promise的通用错误码覆盖；采集诊断不新增DAT启动检查或修改游戏资源。 工具栏与更多菜单以运行状态为先：FAILED显示“游戏运行失败”，EXITING显示“正在退出…”，EXITED显示“游戏已结束”，旧存档提示或同步状态不得覆盖这些状态，也不显示同步中的动画。

存档核心版本变化是可尝试恢复的风险提示，不能显示禁止图标或禁用继续。普通存档卡的黄色“核心版本已变化”标记叠放在截图左上角，游戏详情紧凑卡显示“核心已变化”；继续按钮使用原有尺寸和文字，内含小警示图标，并通过悬停及可访问描述说明风险。首页继续和游戏详情启动入口共用按钮提示，不增加独立提示行。沉浸缩略图以黄色标签提示且保留大图；点击继续后确认“尝试加载旧存档？”，说明可能失败或运行异常、原存档保留及后续进度另存。取消默认获得焦点，普通模式键盘可操作，沉浸模式左右选择、A/Enter确认、B/Escape取消；弹层接管输入，打开/关闭需手柄松键120ms，不能穿透或反复启动。确认在请求全屏前；若服务端发现列表读取后的新核心变化，在加载核心前补充确认，取消释放该Run。ROM变化（含核心同时变化）仍禁用，明确游戏文件与创建存档时不一致；格式不可读、原核心或文件不可用仍显示真实原因。跨版本运行首次真实保存创建新档，后续同步更新新档，本次运行禁止覆盖来源存档。

核心版本警告不得改变卡片正文或操作区高度：同一列表中有／无警告卡片的截图、日期和按钮保持对齐，手机底部启动栏不因警告加高。沉浸模式缩略图保留角标，继续按钮也只放行内警示图标；完整说明由点击后的确认弹窗承载。

游戏管理概览显示受管物理文件数量；一个项目包不被显示为只有一个逻辑成员。项目入口选择继续使用包内路径，不能把 game.zip 作为入口候选。通用项目入口每页最多读取 100 个逻辑文件，保留当前已选路径；“浏览项目文件”默认收起，展开后可按字面路径前缀筛选、进入下一页或返回第一页。筛选重置游标，读取可取消且旧响应不得覆盖当前页，错误可重试。控件沿用共享 field、select、details 和 secondary button；RPG Maker 与 ScummVM 继续使用各自 runtime 权威入口／选择投影。

游戏库平台筛选按钮按中英文统一字母序排列：中文使用不带声调的拼音排序键，英文忽略大小写，数字自然排序，同名以ID稳定排序；目录与标签下拉菜单共用此规则，“全部”固定首位。按钮显示启用目录中的已发布游戏总数，同平台跨目录累加，不随搜索/标签条件改变；数量为0的平台隐藏快速筛选按钮，超过1000显示999+，悬停可见准确数量。收藏页共用排序与空平台隐藏规则，但不把全库数量显示为收藏数量。

审核详情的发布操作与运行条件区共用同一检查结果；检查中、检查失败、版本变化或必需文件/BIOS不满足时不能发布。CRC差异允许手动放行，但点击发布先弹出共享确认框，说明可能无法启动或运行异常、建议试玩且试玩不是强制条件，显示ROM/Parent/BIOS差异项数，并提供“测试运行”“返回检查”“确认风险并发布”。取消默认聚焦，Escape返回，试玩复用当前核心的审核运行；切换核心、保存配置、文件变化或重新检查会关闭旧确认框并重置检查。

RPG Maker 审核与管理的入口候选由 runtime 按当前版本和活动文件投影。MV/MZ 仅列同目录含对应核心脚本的 index.html，保留 www/index.html 等完整路径；导入同版本多项目时默认选择唯一的根目录 index.html，其他有效入口可下拉切换；混合版本或缺少唯一根入口仍要求明确选择。XP/VX/VX Ace 仅列 Game.ini，2000/2003 仅列 RPG_RT.ldb。唯一有效且已选中的入口仅显示只读路径，不显示识别成功提示；未选择且只有一个候选时自动选中，多个候选使用共享下拉选择器，不允许手动输入路径。运行配置字段按顶部对齐；读取状态或错误提示只占用自身字段下方空间，不能拉伸相邻选择器，控件沿用共享尺寸与手机字号，不随相邻提示拉伸。失效的原入口保留完整路径和错误提示，必须明确选择替代项；无候选提示检查内容/版本，读取失败单独提示并可重试。文件或版本变化刷新候选，过时响应不得覆盖当前列表；后端保存和启动使用同一 runtime 规则校验。

运行依赖列表将已安装但包内成员不完整或无法校验的 ZIP（街机按 DAT 成员，RPG Maker RTP 按 runtime 声明的标志目录／文件）列入“需要处理”，状态明确区分安装与校验结果；展开文件校验要求展示“包内成员匹配”数量和未满足成员。每行的“替换文件”“移除”按钮上下排列且等宽，手机上占满整行。安装操作与已有安装保留规则不变。

游戏目录的 FBAlpha 推荐名称为“FBAlpha 游戏”，说明保留“使用 FBAlpha 0.2.97.44 运行的街机游戏。”。推荐名称仅用于新建目录；已创建目录按已保存名称显示，再次一键创建时跳过已有目录，不自动改名或覆盖自定义配置。

启动过程中，核心通过公共契约声明需要选择时，Player 在原加载层展示入口名称列表和“取消启动”。键盘方向键与标准手柄方向选择，Enter/A 确认，Escape/B 取消；复用共享按钮、焦点管理和导航模型。长列表在面板内滚动，取消始终可见。选择阶段保持启动中，不能把选择菜单计为游戏就绪；选择完成后恢复正常加载反馈，游戏实际画面与输入就绪后才开始计时。
