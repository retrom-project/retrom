## 2. 信息架构

### 2.1 用户侧导航

- 首页
- 游戏库
- 我的存档
- 管理后台（侧边栏底部）

游戏详情不是一级导航，不出现在侧边栏。它通过游戏库卡片、首页最近游玩或存档的“查看详情”进入；详情打开时“游戏库”保持高亮。

### 2.2 管理后台导航

- 游戏入库
  - 导入文件 / 目录
  - 任务进度
  - 待审核
  - 审核历史
- 游戏管理
- 平台目录
- BIOS 管理

“游戏入库”是可点击的父级总览，不是折叠标题。四个子菜单始终位于同一缩进层级，并用左侧竖向导引线、短横连接线和较小行高明确表达从属关系；进入任一子页时仅该子项使用强高亮，父项保留弱上下文高亮。

进入管理后台后左侧菜单整体切换，并在底部提供“返回用户侧”。基础平台、Core 和 PlatformCore 由代码种子管理；平台目录由用户在后台维护。

## 3. 视觉方向

- 现代桌面应用框架，不大面积使用像素字体或霓虹效果。
- 左侧深色导航，右侧低对比中性色内容区。
- 紫色为主操作色，青色为运行/系统状态辅助色。
- 封面、截图和游戏画面体现复古；表单与表格保持现代和清晰。
- 正文使用系统无衬线字体，封面小标题可局部使用等宽字体。
- 表格不使用密集竖线，卡片圆角 12–16px，常规图标 16px。

## 4. 桌面与 4K

- 目标窗口宽度 1280px 及以上；一期不承诺移动端。
- 常规侧栏 224px，顶部栏 64px，内容内边距 24px；缩进子菜单不能压缩到省略核心页面名称。
- 常规桌面内容最大 2160 CSS px；`2600px` 以上 viewport 可扩展到 2560 CSS px并居中。
- `1280–1599px`：224px 侧栏、24px 内容内边距、游戏库 4 列、存档/管理卡片 3 列；管理宽表只能在自身带可见滚动提示的容器内横向滚动，不能造成页面级横向溢出，行首标识与行末主操作使用 sticky 固定且键盘可达。
- `1600–2599px`：248px 侧栏、32px 内容内边距、游戏库 6 列、存档 4 列。
- `2600px+`：280px 侧栏、44px 内容内边距、游戏库 8 列、存档/管理 5 列。
- 4K 基准正文 16px；表格/徽标/辅助文本不低于 12px，输入框和按钮不低于 14px、42px 高。
- 详情 Hero 为“封面 / 元信息 / 启动配置”三列，启动面板不漂移到物理屏幕最右侧。
- Player Shell 不受普通内容最大宽度限制。stage 固定占满 `100vw × 100dvh`；工具栏 56px，四周安全留白在 1280–2599px 为 24px、2600px+ 为 48px。画布容器可用宽高分别为 `100vw - 2×留白` 与 `100dvh - 56px - 2×留白`。
- EJS canvas 的 CSS 宽度为 `min(可用宽度, 可用高度 × 当前 drawing-buffer 宽高比)`，CSS 高度由同一宽高比反推，且 `max-width/max-height: 100%`、水平/垂直居中。ResizeObserver 在 drawing buffer 比例变化时更新 CSS custom property；不得用 `vh` 直接当宽度、拉伸到容器两边或裁切画面。只有 CoreArtifact 的版本化兼容配置可以调整 backing buffer，不能改变此 contain 布局。
- UI 验收覆盖最小桌面 `1280×800` CSS viewport、`2560×1440` CSS viewport，以及 3840×2160、系统缩放 100% 的 4K viewport。

## 5. 全局状态

每个列表和详情资源均定义：

- Loading：骨架或局部加载。
- Empty：原因和下一步操作。
- Error：可理解错误和重试。
- Disabled：说明不可用原因。
- Warning：允许继续但明确风险。
- Blocking：解决前不能继续。

后台异步任务使用 SSE 更新，不以整页轮询闪烁替代。

## 6. 用户侧页面

### 6.1 首页

展示总游玩时长、游戏数、手动存档数、最近一次可继续游戏和最近游玩列表。

交互分流：

- “继续游戏”使用 `createdAtMs` 最大且当前仍可部署的未删除存档；相同时按存档 ID 降序确定唯一结果。它直接启动、默认全屏，不先进入详情页；没有兼容存档时隐藏该操作并显示 blocker。
- 最近游玩的普通卡片进入详情页。
- 最新存档引用旧 revision 时直接使用旧 GameVariantRevision。

### 6.2 游戏库

包含搜索、基础平台筛选、平台目录筛选和排序。先选基础平台后，目录筛选只展示该平台的 PlatformInstance。

卡片展示封面、标题、基础平台、平台目录、年份和状态。只显示 `PUBLISHED` 游戏；缺少必需 BIOS 时仍可见但标记“缺少 BIOS”。

点击卡片进入游戏详情，不直接启动。

### 6.3 游戏详情

Hero 展示封面、标题、基础平台/平台目录、年份、开发商、类型、玩家数、简介、总时长、存档数和最近游玩。

启动面板包含：

- 核心下拉框，默认选中平台目录默认核心。
- Core 主状态：目录默认、兼容、需验证、缺少依赖、不兼容；“缺少依赖”再按 reason 明确写“缺少 BIOS”或“缺少 parent ROM”，不混用。若锁定旧 DAT 快照仍可运行但后台重校验为 `PENDING/FAILED`，另显示“待重校验/重校验失败”提示，不把主状态误降为不可运行。
- DOS 启动程序下拉框。
- ROM、parent、BIOS 和环境预检摘要。
- “开始游戏”按钮。

规则：

- 点击“开始游戏”后直接进入加载中的运行壳、自动启动并默认全屏；不会再到一个带 Start 按钮的等待页。
- 全屏目标固定为当前文档根节点并在原始 click handler 中同步请求；不得对隐藏/稍后才 mount 的播放器节点请求，也不得等 launch API 返回后再请求。
- “需验证”核心在同一次启动流程中投递/复用 Variant 验证 Job；加载壳显示“验证核心兼容性 / 生成依赖包”，成功后自动继续创建 Launch，不增加确认页或第二个开始按钮。用户可退出本次等待并退出全屏，但这只断开当前订阅；同 digest Job 可能被其他 Launch 共用，不能从 Player 取消它。
- 缺 BIOS/不兼容时按钮禁用并显示具体文件或原因。
- BIOS hash 不一致是 Warning，允许一次点击继续。
- 切换核心只影响本次 LaunchSession，不修改平台目录。

详情下方提供存档、介绍和详细信息。某条存档的“继续”直接启动并锁定存档核心/revision；另设“查看详情/兼容性”用于检查，不复用继续按钮。

### 6.4 我的存档

卡片包含截图、名称、游戏、保存时间、核心、保存时累计时长和“从这里继续”。

- “从这里继续”直接启动、默认全屏，不先跳游戏详情。
- 点击游戏标题或“查看详情”才进入详情。
- 不可用存档原位显示 blocker。
- 支持重命名、删除和兼容性信息；删除需二次确认。

### 6.5 游玩页

正常启动后页面已经在运行或加载 EmulatorJS，不显示二次 Start/Play Now。

- 默认请求浏览器全屏，并隐藏普通侧边栏和顶部导航。
- 加载层只展示 Variant 验证/依赖物化、预检、Core/WASM、ROM、BIOS、存档恢复等进度。验证 Job 失败时退出全屏并返回来源上下文，不自动无限重建 Job。
- 运行工具包含保存进度、控制器、全屏切换和退出。
- `Escape` 仅退出浏览器全屏，不结束游戏。
- 显式退出时刷新持久存档、结束 PlaySession，并返回发起本次启动的详情页、存档页或首页。
- 若另一会话已推进同一 PersistentSave，当前保存以冲突停止，不能覆盖服务器版本或自动死循环；加载层/退出面板必须保留本地 bytes，提供“下载当前保存”和“退出后重新启动”，在用户处理前不谎报“保存成功”。

浏览器拒绝全屏或深链接没有用户激活时的例外行为见 [运行时与游玩数据](./runtime-and-play-data.md)。

## 7. 管理后台页面

### 7.1 游戏入库

父级“游戏入库”进入总览页，不直接显示上传表单。总览只回答“当前入库是否健康、哪里需要处理、最近发生了什么”：

- KPI：运行中任务、待审核条目、异常条目、本周发布。
- 流水线快照：上传与去重、文件识别、元信息刮削、等待审核和本周发布的条目数。
- “需要处理”按阻塞范围排序，并直接进入任务进度、待审核或审核历史。
- 最近任务只显示摘要；完整操作统一进入任务进度页，避免总览演变成第二套任务管理。

“导入文件 / 目录”是聚焦的新建任务页：

- 以“选择内容 → 确认配置 → 上传并验证文件”三步表达上传准备，不在页面内再切换任务或历史 Tab；`UPLOAD_FINALIZE` 完成后才出现“创建导入任务”，不能把 UploadSession 与 ImportJob 合并成一个含糊状态。
- 支持拖放、选择文件和选择目录；保留 Chrome 目录上传的相对路径。
- 分块上传齐备后显示独立的“正在验证与入库文件”阶段，通过当前 `finalizationNo` 对应的 UPLOAD_FINALIZE Job 快照/SSE 显示文件计数和 bytes；只有 UploadSession 进入 COMPLETE 才启用“创建导入任务”。缺失/损坏 part 列出精确文件与 partNo，允许仅重传这些分块；再次完成会显示递增的终结轮次并保留旧轮次历史，不能把旧失败 Job 改成新输入。取消 FINALIZING 需表示为有界取消，不伪装已立即删除正在处理的文件。
- 必选目标平台目录，并立即展示推导出的基础平台、默认 Core、EmulatorJS/Core artifact 和 Arcade DAT。
- 元信息源为 Hasheous 哈希查询或“不刮削”；DAT 不出现在元信息源选择中。
- 提交区固定展示将被冻结的任务快照；未选择内容时主按钮禁用并说明原因。

“任务进度”是运行态工作台：

- 提供运行中、排队中、需处理摘要，以及状态/平台目录筛选。
- 任务行显示阶段百分比、条目分布、心跳/更新时间、配置快照和错误数量。
- 选中任务后在同页显示阶段事件；取消、条目重试和进入待审核均在此发起。
- 分组前被拒绝的文件（如多 primary、nested archive、7z/RAR/TAR）在本页按文件名和稳定 reason 展示“重新打包后重新上传”；它们没有 ImportItem，不能错误地提供“进入审核/重新归组”。
- 审核决策与字段 diff 不放在本页，避免把 Worker 运行态和业务审计混在一起。

完整任务和恢复规则见 [导入、刮削与审核](./import-and-review.md)。

### 7.2 待审核与审核历史

`/admin/reviews` 首先是可浏览的全局待审队列，不得直接把第一条详情冒充整个页面。队列支持关键字、导入批次、平台目录、Blocker 和更新时间排序；每行至少展示来源文件/目录、草稿标题、所属 ImportJob、目标平台目录、Validation 状态、候选数量和更新时间。任务页的“进入待审核”必须带 `importJobId` 筛选进入该批次，用户也能清除筛选查看所有批次，并可任意选择条目而不是只能按固定顺序处理。

在 2560/3840 宽度下，页面使用“待审队列 + 文件/候选 + 编辑/发布”的三栏工作台；选中条目后 URL 更新为 `/admin/reviews/:itemId`，队列筛选、cursor 已加载页和滚动位置保持不变。在 1280 宽度下，`/admin/reviews` 使用完整列表，进入详情后提供明确的“返回待审列表”；浏览器前进/后退必须恢复原筛选和位置。Approve/Discard 后只移除已决条目并聚焦当前筛选下相邻的下一项；队列为空时显示完成状态。未保存草稿切换条目必须阻止导航并让用户选择保存、放弃或留在当前条目。

左侧展示原文件、目标平台目录、哈希、Arcade DAT 依赖结果、当前 ImportItemCoreValidation 及独立的 Hasheous 候选；右侧编辑展示元信息和平台目录，不提供游戏级默认 Core 字段。文件大小使用 B/KB/MB/GB 人可读单位，并以 title 保留精确 bytes；不可变依赖证据首先展示 machine、DAT、闭包、依赖与异常摘要，不以会撑开工作台的原始 JSON 作为主要界面。元信息来源控件允许“Hasheous（重新查询）/不刮削”，每次请求展示独立批次状态；显式 Hasheous 不能静默复用旧缓存，页面原位等待任务终态、显示进度并在结束后 toast 反馈和刷新候选。文本候选与媒体来源分别标注，允许从同一 Item 的已完成批次混合 READY 图片。

底部操作为 Discard、保存草稿、通过并发布。发布或丢弃时按钮显示提交中；成功后 toast 反馈并替换到当前筛选下的相邻条目，队列为空则返回列表，不能在已决条目上无反馈停留。目标目录/default DOS entry 改变或 CoreArtifact/DAT/BIOS 配置漂移后，旧 Validation 明确标为“已过期”，后台新验证完成前“通过并发布”禁用并显示任务入口；只有当前 READY Validation 可发布。“待审核”只显示尚未作出最终决策的队列与审核工作台。

一期不提供批量 Approve/Discard。每个条目的草稿、候选、Validation、ETag、幂等键和最终 ReviewEvent 都独立，必须逐条确认；提高大量 ROM 审核效率依靠可见队列、批次筛选、任意跳转和决策后自动聚焦下一项，不能用一次点击盲目发布整个批次。

“审核历史”是独立的只读审计页，支持按关键字、决策、平台目录和时间筛选；选中记录后展示输入/输出快照、采用候选、字段 diff、平台目录/Core/DAT 快照、决策、Actor 和 Unix 毫秒时间。历史页不能修改旧事件或复用为待审核队列。

### 7.3 游戏管理

列表支持搜索、基础平台/目录/状态筛选，卡片进入 `/admin/games/:gameId`。管理详情不是用户游戏详情复用表单，而是固定四区：

1. “发布信息”：标题、描述、年份、开发商、发行商、类型、玩家数；保存创建新的 MetadataRevision，必须携带当前 ETag。
2. “媒体”：当前封面/背景/截图及替换入口；上传成功创建新 Asset，不原地覆盖旧 Blob。
3. “内容与运行版本”：先展示 Game 当前/历史 GameContentRevision 及用户文件清单，再按 Core 展示稳定 GameVariant、当前/历史 VariantRevision、CoreArtifact、DAT、派生文件、依赖诊断和兼容状态；替换游戏文件先走 upload 会话与可观察 Job，只有新内容对目录默认 core 验证 READY 且配置快照未漂移时才原子切换 Game content 与目标 Variant 两个 current，失败保留旧版本并提供 retryable 重试。
4. “管理操作”：重新刮削只生成候选预览，用户确认后才创建 metadata revision；移动目录先请求基础平台/default core 影响，若返回 `VALIDATION_PENDING` 就在原对话框展示可返回的任务进度并等待，任务完成后自动用新幂等键重新预览，绝不提前移动；软删除要求输入游戏标题确认并展示受影响存档/审核历史，历史引用不级联删除。

所有长任务进入任务进度并可回到此页；成功/失败反馈必须对应实际 revision/job ID。页面不得提供直接编辑 CoreArtifact/DAT hash、宿主路径或物理 Blob 的字段。

### 7.4 平台目录

展示名称、基础平台、默认核心、游戏数和兼容性摘要。支持创建、编辑、排序、默认核心影响预览及删除空目录。完整约束见 [平台目录领域设计](./platform-instance.md)。

### 7.5 BIOS 与 DAT

BIOS 视图默认展示当前游戏库实际所需项，另有核心完整目录；DAT 视图支持上传候选、解析、差异预览、启用和回滚。候选必须显示待解析/解析中/可启用/失败/已取消五种明确文本状态；运行中的用户 DAT 可请求取消，已取消候选只提供删除与重新上传，不显示“重试”造成旧任务复活。浏览器只读取后端物化结果，不现场解析原始 DAT。完整规则见 [BIOS 与 Arcade DAT](./bios-and-arcade.md)。

## 8. 无障碍与键盘

- 所有图标按钮有可读 label；状态不能只靠颜色。
- `Tab` 顺序与视觉顺序一致，焦点样式清晰。
- 下拉框状态文本包含“目录默认/缺 BIOS”等语义。
- 启动后保留 `Escape` 的浏览器全屏语义，并提供明确的退出游戏按钮。
- 动画尊重 `prefers-reduced-motion`。

## 9. 统一验收入口

UI、导航、4K、键盘、待审队列与状态呈现统一执行 [一期项目验收规范](./project-acceptance.md) 的 `ACC-UI-001`–`ACC-UI-008`；游戏管理执行 `ACC-GAME-001`–`ACC-GAME-003`；一次点击启动、默认全屏、存档快速恢复与 DOS 程序选择分别由 `ACC-RUN-*` 和 `ACC-SAVE-*` 联合覆盖。本文不再复制验收清单。
