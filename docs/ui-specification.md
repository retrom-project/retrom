## 1. 设计稿

[打开 Retrom 最终可交互设计稿](./design/retrom-ui-review.html)

账户入口、账户设置、用户管理、服务器 BIOS/Pegasus 导入与游戏详情视频已经合入同一设计源和交互稿；评审稿右上角的“评审场景”可在认证、用户侧与管理后台之间切换，不再维护平行的专题设计稿。

固定 viewport 和页面状态由本文契约及 `web/scripts/capture-ui-design.mjs` 的登记共同维护。该脚本仍可在本地生成静态评审图片，但图片由 `docs/design/.gitignore` 忽略，不提交 Git，也不作为本文链接或事实源。

设计稿是已审定的页面结构、视觉语义和主流程基线，不代表最终封面素材，也不是可复制进产品的 HTML/安全配置。评审导出为了独立打开可加载外部图标脚本并使用宽松 sandbox CSP；正式 Next.js/Player 实现绝不能沿用这些 CDN、inline script 或 CSP，必须遵循 [HTTP API 契约](./http-api-contract.md#2-认证授权与同源写入) 的 nonce/CSP 策略。稿内示例标题、数量和日期只是视觉内容，不是数据库 seed 或 API fixture。

本文负责完整状态和尺寸契约；本地评审图片未展示的错误/空状态仍以本文为准。实现若改变导航层级、直接启动行为、阻断状态或审核流程，应先更新本文档和设计稿源文件，再重新生成 HTML；需要视觉复核时可在本地重新生成图片。

设计源 `design/retrom-ui-review.fragment.html` 是唯一可编辑稿；在 `web/` 运行 `node scripts/export-ui-review.mjs` 重新生成评审 HTML，运行 `node scripts/capture-ui-design.mjs` 可按登记的固定 viewport 生成本地评审图片；只需复核部分页面时，可把一个或多个已登记输出文件名作为 capture 脚本参数。不得手工修改生成 HTML；本地图片不进入 Git。

## 2. 信息架构

### 2.1 用户侧导航

- 首页
- 游戏库
- 我的存档
- 我的收藏
- 最近游玩
- 联机游玩（仅 `netplayEnabled=true`，紧跟“最近游玩”）
- 管理后台（仅 `ADMIN`，侧边栏底部）
- 账户菜单（显示名、`@username`、账户设置与退出登录）

游戏详情不是一级导航，不出现在侧边栏。它通过游戏库卡片、首页最近游玩或存档的“查看详情”进入；详情打开时“游戏库”保持高亮。

### 2.2 管理后台导航

- 游戏入库
  - 导入游戏
  - 本地扫描
  - 任务进度
  - 待审核
  - 审核历史
- 游戏管理
- 标签管理
- 游戏目录
- 用户管理
- 运行依赖

“游戏入库”是可点击的父级总览，不是折叠标题。五个子菜单始终位于同一缩进层级，并用左侧竖向导引线、短横连接线和较小行高明确表达从属关系；进入任一子页时仅该子项使用强高亮，父项保留弱上下文高亮。“运行依赖”是直接进入 BIOS 管理的单一导航项；Arcade DAT 随 release 自动管理，不提供用户页面。

进入管理后台后左侧菜单整体切换，并在底部提供“返回用户侧”。基础平台、Core 和 PlatformCore 由代码种子管理；游戏目录由用户在后台维护。

| 实例/访问者 | 允许入口 | 其他入口 |
| --- | --- | --- |
| `PENDING` | `/setup` | 重定向到 `/setup` |
| `READY`、匿名 | `/login`、`/register`、`/reset-password` | 重定向到 `/login?returnTo=...` |

## 3. 视觉方向

- 现代桌面应用框架，不大面积使用像素字体或霓虹效果。
- 左侧深色导航，右侧低对比中性色内容区。
- 紫色为主操作色，青色为运行/系统状态辅助色。
- 内容画布使用暖中性 `#f5f3ef`，正文 `#182033`、辅助文字 `#5f697b`；主操作紫 `#6250d2`、成功青 `#0f737c`、警告棕黄 `#8a580c`，状态文字与底色组合必须达到 WCAG AA 正文对比度。
- 封面、截图和游戏画面体现复古；表单与表格保持现代和清晰。
- 正文使用系统无衬线字体，封面小标题可局部使用等宽字体。
- 表格不使用密集竖线，卡片圆角 12–16px，常规图标 16px。
- 按钮、链接和可点击卡片的可见操作文案不追加字面量箭头字符 `→`；方向或状态转换只有在其本身承载独立语义时才作为图标或数据分隔符使用。
- 普通页面不保留占高的全局顶部栏或重复面包屑；来自 `/health/ready` 的服务状态缩为个人信息右侧的状态点，普通账号也保持同一位置，正常为绿色、异常为红色，hover 或键盘聚焦显示可读状态与异常详情。“管理后台 / 返回用户侧”独占侧栏最底部一行，不与状态点组成一组。侧栏图标使用同一线性 SVG 体系，不混用 Unicode 符号。
- 主界面优先使用用户能直接理解的中文状态；资源 ID、hash、artifact/revision/job 等工程证据放入“技术详情”渐进披露，不能挤占主任务信息。

## 4. 响应式、桌面与 4K

### 4.1 断点与应用壳

- `320–767px` 为手机：普通页面使用固定 52px App Bar 和五项用户底部导航（首页、游戏库、存档、收藏、更多）；“更多”以底部 Sheet 提供最近游玩、按条件出现的联机/管理后台、账户、退出和服务状态。管理路由不显示用户底部导航，App Bar 菜单打开全高导航 Sheet。
- `768–1279px` 为平板：App Bar 菜单打开左侧 Drawer；用户与管理导航保持同一信息架构，账户和服务状态位于 Drawer 底部。Drawer/Sheet 打开时锁定文档滚动、捕获焦点、支持 Escape/遮罩/可见关闭按钮，并在关闭后把焦点归还触发器。
- `1280px+` 保持桌面侧栏和既有共享画布；断点切换不能改变路由、权限、DTO 或业务状态。手机与平板 App Bar、底栏、Sheet、Drawer 和 sticky 操作必须计入 `env(safe-area-inset-*)`。
- `320px` 下 `document.documentElement.scrollWidth <= clientWidth`。所有可交互目标至少 `44×44px`；局部横滚必须有明确容器，不能把表格最小宽度传播成页面级横向溢出。

### 4.2 普通页面的移动重排

- 首页在手机上依次显示继续游戏、快速入口、最近游玩、最新添加、平台和资料库摘要；横向卡片轨道可滚动并保持标题与主操作可见。游戏库搜索常驻，平台/目录/排序进入条件 Sheet，草稿只有“应用”才写 URL，取消不改查询；游戏卡在 `320–479px` 两列、`480–767px` 三列、`768–1023px` 四列、`1024–1279px` 五列，桌面按既有规则排布。
- 游戏详情按封面/元信息、运行方式、内容说明和存档顺序单列；手机底部 Launch Dock 显示当前存档/运行状态与主启动按钮，并为页面内容预留安全区。我的存档、收藏、最近游玩与联机页面使用卡片或纵向信息组，不以被裁切的桌面表格交付。
- 登录、首次设置、邀请注册、重置密码和账户设置在手机上取消外层装饰性留白，表单单列；键盘弹出、错误和长文本不能遮住提交操作。

### 4.3 管理页面的移动重排

- 列表型管理页面把桌面表格的每一行转为可读卡片，保留行身份、状态、关键证据与主操作；搜索保持在页面，复合筛选进入条件 Sheet。不得通过隐藏关键字段或仅保留横向滚动来宣称适配。
- 新建导入、服务器/Pegasus 扫描、用户/游戏/目录与 BIOS 维护均为单列；桌面 Drawer 在手机上全屏显示，危险确认仍保留影响说明、焦点控制和取消路径。Arcade DAT 是 release 依赖，不提供维护表单。
- 待审核列表与详情在手机上是独立路由。详情用“来源、运行检查、发布内容、审核决定”四步锚点导航，顺序与视觉/Tab 顺序一致；决定按钮保持等高且可触达，实时保存、ETag 和逐项决策契约不变。

### 4.4 Player 移动规则

- 移动或 coarse pointer 环境从用户点击启动时即请求全屏并尝试锁定横屏；锁屏 API 不可用或失败时仍进入方向门禁。配置校验必须先完成，但竖屏期间不得创建 iframe、发出 core/game/persistent content 请求或创建 `PlaySession`。
- 方向需连续稳定 `250ms`。横屏稳定后才进入预检/运行；运行中转回竖屏时显示全屏方向阻断层并释放输入。单机先暂停，回横屏只恢复本门禁拥有的暂停；联机 P1 负责全局 pause/resume，P2 仅本地释放输入并显示等待提示。页面隐藏优先于方向事件，不能提前恢复。
- 横屏 HUD 高 `48px`，自动隐藏后保留至少 `44px` 可操作的揭示柄；标题、Core、座位/同步状态和一个最高优先级上下文操作保留在 HUD，其余操作进入“更多”Sheet。“更多”和换盘 Sheet 必须覆盖在 iframe 游戏画面之上并占满可用高度，不能被 HUD 自身的定位上下文压缩或把点击泄漏给游戏。EmulatorJS 触屏层右上角的原生虚拟手柄菜单入口不显示，设置统一从 Retrom“更多”进入；左右虚拟控制区相对上游默认位置下移 `30px`，最终底边距为 `70px`，给横屏拇指留出更自然的落点。所有 Player 弹层计入横屏刘海和底部安全区，退出路径先解除方向锁。

### 4.5 桌面与 4K

- 常规侧栏 224px，内容区从页面顶部开始并使用 24px 内边距；缩进子菜单不能压缩到省略核心页面名称。
- 侧栏右侧的普通页面共用同一水平内容画布，不再按路由叠加第二层居中最大宽度。`1600–2599px` viewport 下外层内容框最大 2160 CSS px（含两侧 32px 内边距），`2600px+` 下页面有效内容最大 2320 CSS px，外层内容框连同两侧 44px 内边距最大 2408 CSS px；两档都在侧栏后的可用区域居中。同一 viewport 下，首页、游戏库、详情、存档、收藏、最近游玩、联机、账户与全部管理页面的主容器左、右边界误差不得超过 1px。文字段落、导入向导、表单字段、表格滚动区和工作台列仍可在这个共享画布内部设置任务级约束，但不得通过给整页再次设置 `max-width` 改变页面边界。Player Shell 与隔离审核预览不使用普通页面画布。
- `1280–1599px`：224px 侧栏、24px 内容内边距，游戏库与游戏管理按 270–320px 卡宽自动排布，存档卡片 3 列；管理宽表只能在自身带可见滚动提示的容器内横向滚动，不能造成页面级横向溢出，行首标识与行末主操作使用 sticky 固定且键盘可达。
- `1600–2599px`：248px 侧栏、32px 内容内边距，游戏卡继续按共享宽度自动排布，存档 4 列。
- `2600px+`：280px 侧栏、44px 内容内边距，游戏卡继续按共享宽度自动排布，存档 5 列。
- 4K 基准正文 16px；表格/徽标/辅助文本不低于 12px，输入框和按钮不低于 14px、42px 高。
- 详情 Hero 为“封面 / 元信息 / 启动配置”三列，启动面板不漂移到物理屏幕最右侧。
- Player Shell 不受普通内容最大宽度限制。stage 无圆角、无外边距并固定占满 `100vw × 100dvh`；58px 工具栏叠加在画面上方，不能占用 canvas 可用区。
- EJS canvas 的 CSS 宽度为 `min(100vw, 100dvh × 核心报告的画面宽高比)`，CSS 高度由同一宽高比反推并在 viewport 水平/垂直居中；因此竖屏游戏必须贴满可用高度，横屏游戏必须至少有一边贴满屏幕，另一轴只保留必要 letterbox。优先读取 `gameManager.getVideoDimensions("aspect")`，drawing buffer 只作为尚未取得核心比例时的回退；ResizeObserver/画布尺寸观察在 viewport 或比例变化时重算，不得把竖屏内容按横向 backing buffer 留出上下黑边。
- UI 验收覆盖手机 `320×568`、`360×800`、`390×844`、`412×915`，平板 `768×1024`、`1024×768`，移动 Player 横屏 `568×320`、`667×375`、`844×390`、`932×430`，以及最小桌面 `1280×800`、`2560×1440` 和物理 3840×2160、系统缩放 150% 的 4K 场景。4K Playwright 项目必须使用 `2560×1440` CSS viewport、`deviceScaleFactor=1.5`，普通 viewport 截图必须实际输出 `3840×2160` PNG；不得用 `3840×2160` CSS viewport、DPR 1 冒充 150% 缩放。`3840×2160` CSS viewport 只作为补充 ultra-wide 布局检查，不作为标准 4K 截图。首页另覆盖浏览器工具栏或非最大化窗口占用后的代表性 `1920×950` CSS viewport，以及物理 `3129×1380`、150% 缩放所对应的 `2086×920` CSS viewport。

## 5. 全局状态

每个列表和详情资源均定义：

- Loading：骨架或局部加载。
- Empty：原因和下一步操作。
- Error：可理解错误和重试。
- Disabled：说明不可用原因。
- Warning：允许继续但明确风险。
- Blocking：解决前不能继续。

后台异步任务使用 SSE 更新，不以整页轮询闪烁替代。

状态色按语义统一：已就绪/可用/完成使用成功青，处理中/待验证使用信息紫，可继续但需要注意使用警告棕黄，阻断/不兼容/失败/删除使用危险红，未知或停用使用中性灰。业务状态必须先映射语义再选择颜色，不能把所有非 `READY` 状态统一显示为警告，也不能在缺少运行证据时给所有卡片固定显示“可运行”。文字标签必须与颜色同时出现。

高风险或不可逆操作统一使用应用内影响确认对话框，不调用浏览器 `window.confirm`。对话框包含动作标题、普通语言说明、结构化影响摘要、明确的取消按钮和与风险一致的主按钮；默认焦点落在安全操作，`Escape` 关闭且不提交。默认运行方式与游戏目录移动等先预览再确认；删除存档和空目录也使用同一外观。普通成功/失败使用页面内反馈条，跨页面完成态可追加右上角固定 toast；toast 不参与页面布局并在 2 秒后自动消失，不能以持久提示推动或遮挡页面。审核字段使用带 ETag 的防抖实时保存，页面显示“等待保存 / 正在保存 / 已保存 / 保存失败”，因此不再提供手动保存按钮或未保存离页分支。

列表筛选器必须显示可见字段标签，不以 placeholder 代替 label；搜索与选择条件提交后使用固定高度摘要显示“筛选条件已应用”、当前页结果数和“清除全部”，不再生成可能换行并推动结果区的条件标签。提交通过客户端路由只替换结果区和 URL 状态，不做浏览器整页刷新。依赖筛选变化时清除已经失效的子条件。工程筛选名在用户界面转换成“运行检查、处理状态、排列顺序”等普通语言；内部 ID 和枚举只放在技术详情，审核源文件的 hash 属于用户核对文件所需信息，可以在文件大小后紧凑展示并用 tooltip 补全。

## 6. 用户侧页面

### 6.1 首页

首页标题后固定为五层。物理 4K、150% scale 的 `2560×1440` CSS viewport 下五层必须完整铺满首屏，最末层底边距离 viewport 底部不超过 48px；浏览器工具栏占用后的代表性 `1920×950` CSS viewport，以及物理 `3129×1380`、150% 缩放所对应的 `2086×920` CSS viewport 下，也必须让五层完整落在首屏。上述布局都不得产生 document 纵向滚动条；紧凑态优先压缩页面留白、层间距和媒体高度，不能把正文与卡片字号压缩到影响可读性。首页主容器使用第 4 节的共享页面画布，使其距离左侧菜单栏与屏幕右边的间距分别与其他普通页面一致。更小的普通桌面允许页面纵向滚动。首页不展示待审核等管理员 KPI，不按浏览器时间拼接问候，也不显示无法证明的同步时间。

1. 第一层是“最近玩的游戏 + 快速开始”。左侧以 `started_at_ms DESC, id DESC` 选择最后启动的 PlaySession；旧会话稍后结束或补写 heartbeat 不能反向覆盖它。只有 `source_launch_session_id` 等于该 PlaySession 对应 LaunchSession 的未删除手动存档，才能把主操作从“再玩一次 / 本次将从游戏开头启动”切换为“继续游玩 / 本次将从存档位置启动”；此时主视觉右侧同时展示该存档的 16:9 截图和“将从这里继续”，没有本次会话存档时不占用该区域。宽屏布局中的封面、存档截图、文字和操作间距必须按主视觉容器宽度连续缩放，跨越响应式断点时不能突然缩小；达到可用高度上限后才允许停止放大。中间游戏信息与主操作必须以封面右边缘为定位基准，宽屏下间距保持在 23–33px，连续拉宽过程中的间距变化不超过 9px，不能随剩余空间增大而被推向画面中央。4K 布局中封面高度至少占主视觉媒体区的 75%，存档截图宽度至少占媒体区的 24%；主操作和启动说明固定在媒体区底部，底边留白不超过 50px，5:7 封面底边与主操作按钮底边对齐，游戏信息在剩余空间垂直居中。封面图片保持原比例、居中裁切并填满容器，不显示黑边。`2086×920` 紧凑宽屏下主视觉媒体区高度不得塌缩，封面、平台与标题、游玩元数据、启动按钮及可用的存档预览必须全部处于媒体区内并可见。其他会话或无法证明来源的历史存档不能改变主操作；但只要该游戏存在任意未删除历史存档，标题右侧就显示“查看存档”并进入 `/saves?gameId=<当前游戏>`，否则显示“暂无可恢复存档”。主操作直接启动并默认全屏，游戏详情保持次要入口。右侧快速开始原位提供游戏库、最近游玩和我的存档；下方“按平台浏览”展示按可见 PlaySession 数量降序的前 4 个基础平台，热度相同时按平台名称和 ID 确定顺序。平台入口进入 `/library?platformId=<平台>`。
2. 第二层横向展示按 `lastPlayedAtMs DESC, gameId DESC` 排序的最近 10 款游戏，包含封面（缺失时占位）、标题、基础平台、归属目录、最近游玩时间和累计有效时长；“查看全部”进入 `/recent`。内容超宽时保留可见水平滚动条，在轨道上滚动鼠标纵向滚轮时同步横向移动，键盘用户仍可聚焦并滚动轨道。稀疏数据从轨道左侧自然排列，常规桌面单卡宽度不超过 480px，4K 布局不超过 560px，不得把少量卡片拉伸填满轨道。封面容器固定为 5:7；响应式调整只改变宽度，保持该布局原有卡片与封面高度。真实封面保持原比例、居中裁切并填满容器，不显示黑边。
3. 第三层“最新添加”复用最近游玩的 5:7 封面横向卡片与滚轮交互，展示启用目录中按 `Game.created_at_ms DESC, Game.id DESC` 稳定排序的最近 10 款已发布游戏。卡片包含当前封面、标题、基础平台、归属目录和添加时间；“查看游戏库”进入 `/library?sort=ADDED_DESC`。
4. 第四层横向展示全部有启用 Core 的基础平台，服务端按名称和 ID 确定性排序。用户可用图钉置顶，置顶顺序保存在当前浏览器本地，不修改服务端平台或目录排序；平台入口同样进入游戏库的精确平台筛选。
5. 第五层是单行“我的资料库”摘要，只显示可见游戏数、未删除手动存档数和累计有效游玩时长，不使用抢占主任务视觉优先级的大统计卡。

最近游玩、最新添加与主卡使用当前 MetadataRevision 的封面；主卡没有封面时显示可读占位。最后一次游玩产生的存档即使引用旧 GameVariantRevision，也按该 SaveState 锁定环境恢复。

### 6.2 游戏库

`/library` 只在首屏读取当前条件下的前 50 个 `PUBLISHED` 游戏，服务端按 `q/platformId/platformInstanceId/tagId/sort` 完成筛选与稳定排序并返回 cursor。用户滚动到已加载卡片末尾后才读取下一页；同一次停留在底部预加载区只读取一页，哨兵离开再进入后才继续，任一时刻只允许一个续页请求，并保留可点击的重试/继续加载入口。不得为构造客户端列表而循环取完整游戏库。页面从上到下包含：

- 标题使用“我的游戏 / 游戏库”的用户侧层级。
- 固定结构的紧凑筛选面板：第一行是即时搜索、游戏集合（PlatformInstance）、单个活动标签和排列顺序；第二行以带完整游戏数的平台胶囊展示基础平台，末端固定显示“已加载 / 当前匹配总数”。首个无 cursor 响应提供完整可见游戏库的平台、目录和活动标签 facet 及真实计数，因此分页不能导致尚未加载的平台或标签从筛选器消失。选择平台后，游戏集合只保留该平台的目录；切换到不匹配的平台时清除失效的目录条件。搜索可见提示为“搜索游戏、平台或标签”，其余控件也保留明确 accessible name，属于第 5 节可见标签规则的页面特例。
- 搜索、平台、集合、标签和排序通过无整页刷新的首分页请求更新结果，并用 `history.replaceState` 同步 `q/platformId/platformInstanceId/tagId/sort`；快速连续输入会取消旧请求，不插入筛选标签，也不改变工具栏高度。未聚焦编辑控件时按 `/` 可直接聚焦搜索。
- 排序提供最近游玩、最近加入和名称 A–Z，并由服务端游标顺序决定；未游玩游戏排在已游玩游戏之后，所有顺序最终以标题和 Game ID 稳定兜底，跨页和刷新不能重复、遗漏或随机换位。
- 结果标题说明封面是主要识别入口，右侧显示“卡片视图 · `/` 搜索”的键盘提示。

卡片保持 270–320px 固定辨识宽度和 3:4 竖向封面；少量结果从左向右自然排列，不能拉伸填满整行，更多结果再自然向右、向下扩展。真实封面等比裁切填满入口；缺封面时由前端使用标题和推荐 Core 生成 Retrom Classics 海报占位，不读取任何临时设计资源。封面左上角显示基础平台，正文展示标题、游戏目录、前两个活动 Tag（其余为可访问 `+N`）和最近游玩时间；无标签不预留空白，尚无 PlaySession 时明确显示“尚未游玩”。无结果文案同时提示可调整搜索、平台、游戏目录或标签。

封面 hover 或键盘聚焦时在底部显示“查看游戏详情”，点击封面或标题进入详情，不直接启动。标题右侧省略号菜单只收纳“查看游戏详情”和“查看相关存档”等低频入口。列表只显示 `PUBLISHED` 游戏时不重复贴“已发布/可运行”徽标；只有存在真实异常投影时才显示状态。缺少必需 BIOS 时仍可见并标记“缺少 BIOS”，不能把生命周期 `PUBLISHED` 推断为运行就绪。

接口响应的 `generatedAtMs` 是最近游玩相对时间的统一时钟；列表项同时提供推荐 Core、`createdAtMs` 和可空 `lastPlayedAtMs`，避免每张卡追加请求。

### 6.3 游戏详情

详情页使用一屏优先布局：面包屑下方依次是 Hero、七项信息条和“游戏存档”。在至少 `1600×1000` 的桌面 viewport 中，普通长度的 Hero 与最近 3 份存档应完整落在首屏；`2560×1440` CSS viewport（物理 4K 150%）下 Hero 贴合 3:4 封面和启动卡的实际内容高度，启动卡上下留白保持接近平衡且不得被固定高行拉出大块空白，存档以三列大截图卡片填充首屏余量。更大 viewport 使用共享页面画布，Hero 仍以固定封面列、可伸缩元信息列和有界启动列控制阅读与操作距离，不能把单行正文或启动控件无限拉长。Hero 左侧使用 3:4 封面并在下方显示基础平台/年份，中间展示基础平台/游戏目录、标题、全部活动 Tag、年份/发行商/类型、完整简介和累计游玩时长，右侧是启动卡。标签位于标题下和收藏操作上方，可换行；每个 chip 链接 `/library?tagId=<id>`，accessible name 为“查看标签‘名称’下的游戏”，长名称省略但保留 title。genre 与 Tag 分开展示，Tag 不进入七项信息条。简介不做行数截断，必须使用整个中栏宽度并允许 Hero 随内容增高；不能在 4K 下只占左侧固定宽度或依赖 hover 才看全。信息条固定展示游戏平台、游戏目录、发行年份、开发商、发行商、类型和玩家数，缺失值明确显示 `—`。

启动卡优先展示最近一份可用存档：包括保持原比例的 16:9 截图、保存时间、锁定 Core 和“从存档继续”，同时保留“重新开始游戏”。没有可用存档时改为单一“开始游戏”。卡片右上角只显示当前运行状态；底部显示普通启动采用的运行方式。DOS 启动程序属于游戏内容选择，仍可在主路径显示。

启动面板完整能力包含：

- 高级区中的核心下拉框，默认选中游戏目录推荐核心。
- Core 主状态：目录默认、兼容、需验证、缺少依赖、不兼容；“缺少依赖”再按 reason 明确写“缺少 BIOS”或“缺少 parent ROM”，不混用。若锁定旧 DAT 快照仍可运行但后台重校验为 `PENDING/FAILED`，另显示“待重校验/重校验失败”提示，不把主状态误降为不可运行。
- DOS 启动程序下拉框。
- ROM、parent、BIOS 和环境预检摘要。
- “开始游戏”按钮。

规则：

- 点击“开始游戏”后直接进入加载中的运行壳、自动启动并默认全屏；不会再到一个带 Start 按钮的等待页。
- 全屏目标固定为当前文档根节点并在原始 click handler 中同步请求；不得对隐藏/稍后才 mount 的播放器节点请求，也不得等 launch API 返回后再请求。
- “需验证”核心在同一次启动流程中投递/复用 Variant 验证 Job；加载壳显示“验证核心兼容性 / 生成依赖包”，成功后自动继续创建 Launch，不增加确认页或第二个开始按钮。用户可退出本次等待并退出全屏，但这只断开当前订阅；同 digest Job 可能被其他 Launch 共用，不能从 Player 取消它。
- 缺 BIOS/不兼容时按钮禁用并显示具体文件或原因。
- BIOS hash 不一致是 Warning，允许一次点击继续。
- 用户显式切换核心后，浏览器按游戏记住该选择，后续从该浏览器进入游戏详情时优先用于普通启动；选回推荐核心即清除偏好。该偏好不修改游戏目录，存档启动仍锁定存档创建时的运行环境。
- DOS 启动程序或显式“显示程序菜单”只在 Launch 成功创建后按游戏写入浏览器偏好；仅改变下拉框或启动失败都不写。再次进入详情优先恢复该选择，候选已被新 revision 删除/禁用时回退审核默认；审核默认本身不能安全直启时直接回退程序菜单。从状态存档继续不读取也不改写此偏好。
- 使用非默认核心时，“更换运行方式”后显示红色“（未采用默认核心）”，说明文字同步以危险色提示当前游戏已采用浏览器偏好。
- “更换运行方式”使用居中对话框，打开时不改变 Hero 高度。对话框明确说明普通重新开始使用所选 Core，而存档恢复使用存档锁定 Core；选择只在点击“应用”后写入浏览器偏好，点击遮罩、`Escape` 或“取消”放弃本次选择。

详情下方固定展示最近 3 份存档。普通桌面使用三列紧凑横向卡片，`2560×1440` CSS viewport 使用三列纵向大截图卡片；截图始终保持完整比例。卡片正文按设计稿分为三层：保存时间/存档名称和“最近存档/手动”状态，保存位置/锁定 Core/保存时累计游玩时长三项事实，以及整行“从这里继续/恢复此存档”操作；没有可用的游戏内位置时使用真实内容语义“主内容”，不得臆造关卡名称。点击截图打开不裁切的全屏预览。标题区始终显示总数，“查看全部存档”在当前详情页打开右侧 Drawer，按保存时间倒序列出该游戏全部未删除存档；桌面列表项采用约原紧凑行高 1.5 倍的截图行，主色白字的“▶ 继续”固定在每行右下角，不显示尾部文字箭头。关闭 Drawer 后焦点返回触发按钮。详情页标题、正文、存档事实和操作须保持可读字号，并由显式字重区分标题、关键值与辅助文字。独立“我的存档”页面仍可使用 `/saves?gameId=<当前游戏>` 精确筛选，但不再是详情页查看全量存档的必经跳转。

游戏详情 Hero 标题区在不挤占“一次点击开始游戏”的前提下增加收藏按钮和“管理收藏夹”；状态与游戏库、收藏页来自同一服务端投影。

### 6.4 我的收藏

一级导航顺序固定为首页、游戏库、我的存档、我的收藏、最近游玩，“我的收藏”必须紧邻“我的存档”下方；路由固定为 `/favorites`，不出现在管理后台导航。匿名访问沿用 `/login?returnTo=/favorites`，USER 与 ADMIN 都只呈现当前 Profile 的数据。

URL 状态为：

```text
/favorites?scope=ALL|UNCATEGORIZED|FOLDER&folderId=<uuid>&q=<text>&platformId=<code>&sort=FAVORITED_DESC|RECENTLY_PLAYED_DESC|TITLE_ASC|RELEASE_YEAR_DESC
```

`scope` 默认 `ALL`；`scope=FOLDER` 时 `folderId` 必填，其他 scope 禁止携带。空 `q/platformId` 和默认 sort 从 URL 省略。切换 Rail、搜索、平台或排序使用客户端路由更新，不整页刷新；浏览器前进、后退和刷新恢复同一视图。已删除、非法或越权 Folder 显示“收藏夹不存在”及“返回全部收藏”，不得静默回退或泄漏 owner。

页面结构从上到下固定为：

1. 页头：标题“我的收藏”、用途说明、当前可见收藏总数和 Folder 总数。
2. 左侧 Rail：固定的“全部收藏”“未分类”，再按创建时刻/ID展示最多 100 个自定义 Folder；Rail 头部和唯一的“新建收藏夹”入口固定，只有中间列表在自身超高时滚动。
3. 内容页头：当前 scope 名称、真实数量，以及只在自定义 Folder scope 显示的“编辑收藏夹”。
4. 筛选区：带可见 label 的搜索、排序和“批量整理”；平台胶囊、结果数，以及仅在 ALL scope 出现的“整理未分类游戏”。
5. 游戏网格：卡宽 270–320px，不因行内卡片较少而无限拉伸。卡片使用 3:4 封面、标题、平台、年份和最多两个 Folder 标签；更多 Folder 用 `+N` 汇总。
6. 卡片操作：封面与标题进入详情；封面右上角只放圆形爱心收藏按钮，正文右下角放始终可发现的省略号 Folder 管理按钮。收藏/未收藏必须复用同一个固定 18×18 矢量心形及 38×38 居中容器，切换状态不能缩放、偏移或改变按钮几何；已收藏显示红色实心心形，未收藏显示高对比度空心形。卡片右上角不得再放方形收藏夹图标，也不得把“管理收藏夹”藏成仅 hover 可见。
7. 批量栏：选择数、加入收藏夹、只在 FOLDER scope 出现的“从当前收藏夹移除”、取消收藏和取消选择；最多选择 50 项，栏宽不超过 720px且不得遮挡末行。

单游戏 Folder 管理使用锚定触发器、固定尺寸的非模态 `role=dialog`，包含标题、搜索、原生 checkbox、创建入口和“完成”；打开时从 DTO 初始化完整选择集合，保存使用精确替换语义。它不得根据 hover 改变宽高或定位参考，触发器、dialog 与卡片 hover 也不得相互改变布局，从而避免弹层在两种尺寸间反复切换或页面抖动。Folder 管理弹层采用统一设计稿中的宽版布局；窄视口只允许受容器约束，不切换为另一套卡片式弹窗。

从管理框新建 Folder 时携带当前游戏或批量选择作为 `initialGameIds`，成功后回到原上下文并刷新选中状态；从 Rail 创建时使用空数组并进入新 Folder 空状态。重命名、删除只在自定义 Folder scope 可用。版本冲突保留用户输入，刷新真实名称/version 后要求再次提交，不自动覆盖其他标签页。

搜索输入使用 150ms debounce，Rail、平台和排序即时请求；新 query key 发出后取消旧请求，即使旧响应更晚返回也不得覆盖新结果。mutation pending 只禁用相关卡片或 Folder，批量提交期间锁定选择集合；写成功后丢弃分页 cursor 并从首屏刷新 summary/folders/items，失败则恢复提交前状态。401 复用全局认证失效路径，403/5xx 显示明确且可恢复的应用状态。

未收藏爱心点击后原位收藏，并用两秒 toast 提供“加入收藏夹”；已收藏爱心先打开 `alertdialog`，默认焦点在“保留收藏”，文案明确会移除的 Folder 数量且不会删除游戏文件或存档。确认后提供两秒内存 undo。加入 Folder 自动收藏；从最后一个 Folder 移除或删除 Folder 仍保留 Favorite。

页面必须区分并保持稳定尺寸：

| 状态 | 呈现与恢复操作 |
| --- | --- |
| 首次 loading | 保留页头、Rail、筛选区和卡片骨架，不展示上一个账号数据。 |
| 完全没有收藏 | “还没有收藏游戏”，主操作进入 `/library`。 |
| 当前 Folder 为空 | 保留 Folder 名称，提供返回全部收藏或去游戏库添加。 |
| 筛选无结果 | 说明当前条件无匹配并提供“清除筛选”，不暗示收藏为空。 |
| 列表读取失败 | 清空旧结果，显示稳定错误和“重试”，不伪装成空列表。 |
| 写入失败 | 回滚本次乐观 UI，保持触发焦点并显示稳定错误映射。 |
| Folder 冲突 | 保留表单，刷新 version/名称并要求重新确认。 |
| Game 变为不可见 | 从结果与可见计数移除，不宣称用户已取消收藏。 |

游戏库卡片和详情 Hero 使用同一爱心语义、包含游戏标题的 accessible name 与 `aria-pressed`；详情另提供“管理收藏夹”，但不能挤占或改变“一次点击开始游戏”的主操作。首页、最近游玩、存档页和 Player 本期不增加入口。

1280×800 至 4K 不得出现页面横向溢出。1280–1599 的收藏 Rail 为 210px；1600–2599 为 220–250px；2600+ 为 250px，正文至少 16px、辅助文字至少 12px、按钮和输入至少 42px。所有爱心、关闭、更多和选择按钮都要有上下文名称；checkbox 使用原生控件，批量栏/toast 使用 `aria-live=polite`，错误使用 alert。Folder 管理使用不带 `aria-modal` 的非模态 `dialog`，打开时焦点进入但不圈定 Tab，Escape 或离开弹层关闭并返回触发器；创建/重命名使用模态 `dialog`，删除 Folder/取消收藏使用模态 `alertdialog`，后两者圈定焦点。所有弹层关闭时不提交未确认内容，并支持 `prefers-reduced-motion` 和非颜色单一语义。

可维护设计源为 [`design/retrom-ui-review.fragment.html`](./design/retrom-ui-review.fragment.html)，生成评审页为 [`design/retrom-ui-review.html`](./design/retrom-ui-review.html)。收藏主页面、Folder 管理与取消收藏确认仍可由 capture 脚本在本地生成图片复核，但图片不提交、不被正式文档引用；稿内标题、封面和数量也不进入生产 seed、fixture 或默认值。

### 6.5 我的存档

`/saves` 先按 cursor 取完全部未删除手动存档，再在客户端形成完整统计、最近保存和按游戏分组的存档库；不能只展示接口第一页。页面从上到下包含：

- 标题右侧固定显示完整数据集的存档总数和涉及游戏数，不随筛选条件缩减。
- “最近保存”突出完整数据集中最新的一份可用存档，展示大幅保存画面、游戏、基础平台、锁定 Core、保存时间和保存时累计时长；主操作“从这里继续”直接启动并默认全屏，次操作进入游戏详情。该区域不随下方筛选变化；没有可用存档时原位说明并引导查看异常原因。
- 固定高度筛选区支持游戏/存档名称搜索、精确游戏筛选、可用状态筛选和保存时间正/倒序。筛选在客户端即时更新并使用 `history.replaceState` 同步 `q`、`gameId`、`availability`、`sort`，不整页刷新、不追加条件标签，也不推动下方分组跳动；右侧固定显示当前结果数。
- 结果按游戏分组，组头展示基础平台、实际使用过的锁定 Core、存档数、最近保存时间和游戏详情入口。大屏默认预览 5 份，较窄桌面默认预览 4 份，更多存档通过组内“展开全部/收起存档”控制；只有一份存档时用空槽明确说明，而不是把单卡无限拉宽。
- 卡片以保存时刻为主标题，展示保存画面和当时累计游玩时长；自动生成的“手动存档 + 时间”名称不再重复显示，用户自定义名称作为补充信息显示。正常卡片不重复显示“可以继续”；只有存档或运行依赖不可用时才显示红色状态和具体 blocker。
- “从这里继续”置于截图正中央，默认隐藏并在卡片 hover 或键盘 `focus-within` 时显示。不可用存档保留原位但禁用启动。
- 重命名和删除收纳到时间右侧的省略号菜单。重命名在卡片内保持单行高度完成，删除使用统一应用对话框二次确认并说明引用保护期；成功后就地更新列表和统计，使用固定定位 toast，不整页刷新、不插入推动页面的成功提示条。

列表响应的 `generatedAtMs` 是服务端渲染和客户端相对时间的统一时钟；每项同时提供基础平台、游戏目录、锁定 Core、可用状态和截图 URL，避免客户端追加请求拼装卡片。

### 6.6 最近游玩

`/recent` 返回并展示全部有游玩记录的可见游戏，不再截断为最近 50 款；它是一款游戏一行的聚合视图，不是逐次 PlaySession 日志。页面按设计稿从上到下包含：

- 三个等宽摘要卡：最近游玩的游戏数、累计有效游玩时长和总游玩次数；摘要始终基于完整历史，不随当前筛选缩减。
- 固定高度筛选区：按标题/游戏目录搜索、基础平台筛选、最近时间/累计时长/游玩次数/标题排序，以及全部、最近 7 天、最近 30 天时间范围。筛选在客户端即时更新结果，不整页刷新、不追加条件标签，也不推动下方列表跳动；右侧在固定位置显示当前结果数。
- 结果按当前浏览器本地日界线分成“今天”和“更早”；每行展示横向封面、标题、基础平台/游戏目录、最近启动时间、累计有效时长和游玩次数。缺少封面时使用与其他用户侧列表一致的占位图。
- 每行右侧的“再玩一次”直接使用推荐或该浏览器为游戏记住的核心启动并返回 `/recent`；“查看详情”和封面/标题进入游戏详情。筛选无结果时原位展示可恢复的空状态，完整历史为空时说明先从游戏库启动游戏。

接口响应的 `generatedAtMs` 是服务端渲染和客户端 7/30 天滚动窗口、今日分组的统一时钟，避免水合前后跨分钟或跨日造成列表跳动。默认顺序为 `lastPlayedAtMs DESC, gameId DESC`，所有其他排序也必须有稳定的 Game ID 兜底，不能因刷新产生随机换位。

### 6.7 游玩页

正常启动后页面已经在运行或加载 EmulatorJS，不显示二次 Start/Play Now。

- 默认请求浏览器全屏，并隐藏普通侧边栏和顶部导航。
- 加载层只展示 Variant 验证/依赖物化、预检、Core/WASM、ROM、BIOS、存档恢复等进度。验证 Job 失败时退出全屏并返回来源上下文，不自动无限重建 Job。
- 顶部 58px 深色半透明工具栏使用紧凑左右结构：左侧返回按钮先打开退出确认，随后显示完整游戏标题与“运行核心 · 基础平台”；右侧依次是存档状态、调试信息、创建存档、暂停/继续、全屏和更多操作。存档状态以绿/紫/黄状态点配合“可创建存档 / 正在上传存档 N% / 已同步 / 保存失败”等文字表达；BIOS Warning 使用独立黄色提示点，点击后显示可读原因，不能占用一整段工具栏宽度。
- 主操作只保留“调试信息”、创建存档、暂停状态、全屏和更多菜单；“模拟器设置、查看快捷键、查看运行提醒、退出游戏”收进更多菜单，更多菜单不得重复提供顶部栏已有的“创建存档”。除调试信息与光盘菜单外，点击顶部工具栏任意位置或其中任一操作都自动暂停 EmulatorJS main loop，令 PlaySession heartbeat 标记 `paused=true`；工具栏内不能恢复，只有重新点击游戏画面区域，或在设置/弹层未占用 Player 时按 `P`，才继续运行，并在暂停画面中央明确提示“点击游戏画面继续”。EmulatorJS 原生底栏及触屏右上角的原生虚拟手柄菜单入口始终隐藏且不能被靠近边缘或画面点击自行唤出；点击“模拟器设置”显示 Retrom 自绘的居中底部工具栏，固定提供控制、显示、Core 设置、画面模式、音量、静音和收起，并把前三项桥接到当前 EmulatorJS 实例的真实设置面板。“控制”使用与文字同一 flex 基线的项目矢量图标，不能依赖会产生字体基线偏移的 emoji。画面模式固定为“清晰增强/锐利像素/增强锐化/平滑增强/原始画面”，首次使用、偏好不可读或偏好值未知时默认“锐利像素”（无 shader、像素缩放），选择即时生效并按认证用户保存在本浏览器。Core 设置切到显示设置必须真正展示 Graphics Settings 及 shader 入口。点击自绘栏或设置面板不能误恢复游戏。自绘栏和可见的原生设置面板都不提供 EmulatorJS 退出入口，退出与左侧返回统一使用 Retrom 深色影响确认窗。默认键盘完整表和联机席位差异以运行时专题为唯一事实源；UI 不把键盘映射写入 gamepad control。
- 点击“调试信息”不暂停游戏，在屏幕右侧滑入只读诊断面板并保持顶部工具栏可见。面板以清晰分组展示每秒从 EmulatorJS 核心帧计数计算的 FPS、累计帧数、运行状态、画面分辨率，以及 Core、EmulatorJS/adapter 版本、输入模式、隔离能力、Player 模式、viewport、DPR 和锁定 artifact ID；关闭按钮与“调试信息”再次点击都可收起。窄视口下侧栏宽度不得超出 stage，减少动态效果时取消滑入动画；诊断数据只在当前 Player 内采样，不持久化或展示凭据、内容 hash、宿主路径。
- 创建手动存档时必须生成可解码、包含实际画面的 PNG：工具栏触发暂停时先从仍在运行的下一帧采集画面，最迟 750ms 暂停并读取状态；截图即使晚于暂停完成，也必须在独立 5 秒有界窗口内继续生成并供当前保存或原位重试使用，不能因暂停响应期限而被丢弃。截图优先读取 core framebuffer，避免物理 4K/高 DPR 的 viewport-sized shader canvas 编码超时或暂停后 WebGL 黑帧，核心能力不可用时才回退 EmulatorJS canvas；若游戏已经暂停则复用进入暂停瞬间缓存的最后一帧。全黑或近全黑的无效采集不得作为“截图成功”的依据。状态与截图仍作为同一次完整创建提交。
- 游戏进入运行态 2 秒无交互后，工具栏向上隐藏，鼠标在任意画面移动或键盘聚焦工具时立即展示，指针/焦点停留在工具栏、更多菜单或退出窗内时不得自动消失。左下角用低对比度短提示说明移动鼠标可恢复控制；加载、上传进度、toast 和退出窗都覆盖在 stage 上方，不能改变 canvas 的可用高度。
- `Escape` 仅退出浏览器全屏，不结束游戏。
- 显式退出先展示影响确认；操作区最左侧固定提供“创建存档”，复用工具栏的手动状态与非空截图原子创建事务。点击后先暂停并采集当前画面，保存期间显示实际上传进度并锁定弹窗内的取消、退出和背景关闭；成功后弹窗保持打开、按钮显示“已创建存档”且禁止重复提交，用户仍可取消后继续游戏或确认退出；失败时明确显示未创建不完整记录并原位提供“重试创建存档”。直接确认退出只结束 PlaySession，不创建或刷新任何游戏进度，并返回发起本次启动的详情页、存档页或首页。进入 Player Shell 和退出返回都使用浏览器历史替换，游玩页不得残留为可后退重新进入的历史项。安全取消获得默认焦点，非保存期间 `Escape` 只关闭确认窗而不退出游戏。DOS 程序菜单模式没有锁定可重放的具体程序，工具栏与退出窗的“创建存档”均禁用，状态显示“程序菜单模式不可存档”，退出窗提示用户回到详情选择具体程序后再启动；不能提交表面成功但无法恢复的记录。

浏览器拒绝全屏或深链接没有用户激活时的例外行为见 [运行时与游玩数据](./runtime-and-play-data.md)。

### 6.8 联机首页、房间与 Player

`/netplay` 只有 feature flag 开启且已登录时可进入。标题区提供唯一“创建房间”主操作并在提交中防双击；下方固定分“当前房间”和“最近联机”两区，分别覆盖 skeleton、空状态、容量/限流错误和终态卡片。Room card 展示短房号、状态、游戏/core、参与人数与进入入口，不暴露 Profile ID、Launch 或 credential。

房主新建后进入 DRAFT 游戏选择页。该页复用游戏库的标题、搜索、集合/平台筛选、排序、响应式卡片与空状态；只增加 SUPPORTED/UNSUPPORTED eligibility、blocker 文案和“选择”。SUPPORTED 表示当前 READY VariantRevision 命中 manifest 的 EmulatorJS/core artifact profile、协议允许的内容类型与有效依赖快照，不表示该 ROM 被逐游戏登记；若同一游戏有多条 core profile 才打开窄对话框。筛选以 `history.replaceState` 维护 `q/platformId/platformInstanceId/availability/sort`，`/` 快捷键聚焦搜索，不能复制一套漂移的游戏库布局。首个 server render 必须从 App Router `searchParams` 得到同一规范化筛选并作为 Client Component 初值，而且只读取最多 100 款的首个服务端页；WAITING/STARTING/RUNNING/终态房间不读取游戏目录。用户实际向下滚动且末尾哨兵进入视口后才读取一个续页，哨兵再次离开并进入才可继续；任一时刻只允许一个续页请求，并保留可点击的重试/继续加载入口。不得在 server render 循环读取全部页，也不得在 hydration 后才从 `window.location` 补写状态而造成 HTML 漂移；刷新和前进/后退必须恢复同一结果。

WAITING 房间展示游戏锁定摘要、复制本站房间链接、P1–P4 座位卡与底部操作。未占座访客只能选择支持范围内的空 P2–P4；成员 ready 后先取消才能换座。房主可在 WAITING 移出访客、更换游戏、关闭房间，只有至少两人且全员 ready 时“开始联机”可用。房间快照按版本单调前进，较旧的 mutation 响应不得覆盖 SSE 已显示的成员状态；ready 恰逢另一成员更新而冲突时刷新并至多自动重试一次，不向用户暴露可自行恢复的“房间信息被修改”。SSE 断线提示不得遮盖座位；连续失败转为 5 秒轮询并保留可重试错误。STARTING 为每人自动创建自己的 Launch 并 `location.replace` 到 Player，不展示第二个启动按钮；终态原位说明 reason 并返回联机首页。

联机 Player 复用无侧栏 stage 与工具栏视觉，但元信息明确显示“联机 · Pn”。它隐藏创建存档、普通暂停、换盘、Core/控制重映射和模拟器设置；P1 只看到“全局暂停/继续联机”，P2 只看到网络状态。暂停 overlay 写“联机已暂停/等待房主继续”；初始同步和运行期断线都在 10 秒恢复窗口内显示“连接中断，正在恢复”，恢复时不离开 Player。只要 Player 页面未刷新、关闭或主动离开，切换窗口、浏览器失焦、最小化、组件重挂载和页面内操作都必须保留当前 Launch、WebSocket 与参与者身份，不得发送 suspend/disconnect、返回房间或重复申请 Launch；失焦只释放本地按键，旧控制器被新连接接管时只能本地释放，不能结束共享 Session。退出确认明确“会结束所有参与者且不会产生存档”，确认后返回本房间。所有联机按钮、seat、dialog、SSE error 和终态必须可键盘操作、有可读 label/status/live region，不能只靠颜色表达。

### 6.9 账户入口与账户设置

- `/setup` 只在实例 `PENDING` 时显示初始化表单，要求管理员用户名、显示名、密码及主机生成的一次性 setup code；提交成功后直接建立管理员会话并替换到首页。`READY` 实例不得重新进入初始化流程。
- `/login` 只显示通用的“用户名或密码错误”，不能泄露账号存在、停用或锁定状态；达到限流时保留用户名、清空密码、显示剩余等待时间。`test` 模式必须常驻非生产警告，不能仅用颜色区分。
- 邀请与重置 URL 的 secret 固定放在 fragment。页面必须在首个客户端 effect 读取后立即用 `history.replaceState` 清除 fragment，只把 secret 保留在组件内存；刷新、复制地址、Referer、日志、`localStorage`、`sessionStorage`、IndexedDB 和错误报告均不能再次得到 secret。无 secret、过期、撤销、已使用和账号已停用都显示可理解终态，不自动猜测修复路径。
- `/register` 先校验邀请并显示邀请角色，再收集用户名、显示名和新密码；成功后自动登录。`/reset-password` 成功后撤销该用户全部既有认证会话；目标仍为 ENABLED 时签发轮换后的新会话并自动登录，目标为 DISABLED 时只显示密码已更新但账号仍停用，不自动启用或登录。
- `/account` 只读显示用户名、显示名称、角色和状态，并允许当前用户修改自己的密码；本版本不修改用户名或显示名称。改密码需要当前密码，成功后除轮换后的当前会话外全部登出；页面不提供自助删除、角色修改或启停账号。
- 账户相关浏览器偏好使用 `retrom:v2:user:<userId>:` 命名空间。退出、认证失效或切换用户时清空前一用户的内存状态和对应客户端缓存；不得把 A 用户的平台图钉、DOS 偏好或 Player 残留呈现给 B 用户。

## 7. 管理后台页面

### 7.1 游戏入库

父级“游戏入库”进入总览页，不直接显示上传表单。总览只回答“当前入库是否健康、哪里需要处理、最近发生了什么”：

- 页首用“待审核条目 / 异常任务”两张优先处理卡直接暴露阻塞项；数量、说明和行动入口必须组成一个完整卡片，不能只展示抽象 KPI。“待审核条目”、等待审核 KPI 与流水线人工审核数始终使用实际处于 `REVIEW_PENDING` 的条目总数，已发布或已丢弃条目不得因所属任务聚合延迟而继续计入。
- KPI 固定为进行中批次、等待审核、异常条目和历史完成批次；浏览器上传/重新配置 ImportJob 与 PegasusImport 分别按顶层操作计一次，Pegasus 逐游戏审核交接 ImportJob 不得重复计入。完成批次来自真实累计值，不能伪装成本周统计；主动取消不属于异常批次。
- 流水线按“上传与校验 → 识别游戏 → 运行检查 → 获取游戏信息 → 人工审核 → 发布”六阶段稳定展示，并只使用当前接口能够证明的任务/条目数。“识别游戏”展示非终态顶层批次的已知条目数，“运行检查”展示真实异常条目数，“发布”展示实际 `PUBLISHED` 条目数，不得对最近三条记录求和或把 Pegasus 准备完成冒充全部游戏已发布。
- 最近任务使用紧凑卡片行并合并普通导入与 Pegasus 顶层批次，只显示目录/安全相对路径、创建/更新时间、条目数、信息源、当前阶段和最直接的下一步；一个 Pegasus 目录操作只能出现一行，点击后进入对应 Pegasus 详情。普通完整运行态进入任务进度，Pegasus 完整运行态进入本地扫描详情。

“导入游戏”是聚焦的新建任务页：

- 以“选择内容 → 确认配置 → 上传并验证文件”三步表达上传准备，不在页面内再切换任务或历史 Tab；第三步依次呈现 UploadSession 上传、`UPLOAD_FINALIZE` 校验和 ImportJob 创建结果，不能把三者伪装成同一个后台阶段。
- 支持拖放、选择文件和选择目录；两个选择按钮作为一个操作组在拖放区域水平居中，并保留浏览器目录上传的相对路径。“选择目录”先打开应用内 Dialog；“浏览本机目录”优先通过 File System Access API 打开系统目录选择器并递归读取目录句柄，Chrome / Edge 走该路径时不出现“上传 N 个文件到此网站”的二次确认。Brave 禁用目录句柄 API，能力检测失败时回退 `input[webkitdirectory]`，允许其显示不可由页面替换的原生安全确认。目录也可直接拖入窗体；两种点选路径与拖放结果都回到同一窗体展示根目录名、文件数、总大小和最多四条相对路径预览，只有“使用此目录”才提交到下一步。Dialog 圈定焦点、Escape/取消关闭并把焦点还给触发器，浏览器安全确认不替代产品确认。
- 分块上传齐备后显示独立的“正在验证与入库文件”阶段，通过当前 `finalizationNo` 对应的 UPLOAD_FINALIZE Job 快照/SSE 显示文件计数和 bytes；只有 UploadSession 进入 COMPLETE 才启用“创建导入任务”。缺失/损坏 part 列出精确文件与 partNo，允许仅重传这些分块；再次完成会显示递增的终结轮次并保留旧轮次历史，不能把旧失败 Job 改成新输入。取消 FINALIZING 需表示为有界取消，不伪装已立即删除正在处理的文件。
- 必选目标游戏目录，页面初始不默认选中任何目录，必须由用户主动选择以避免误导入；选择后立即展示推导出的基础平台、默认 Core、EmulatorJS/Core artifact 和 Arcade DAT。
- 元信息源为 Hasheous 哈希查询或“不刮削”；DAT 不出现在元信息源选择中。
- 提交区固定展示将被冻结的任务快照；未选择内容时主按钮禁用并说明原因。

“任务进度”是运行态工作台：

- 只列用户通过浏览器上传或重新配置创建的普通 ImportJob；Pegasus 逐游戏审核交接任务不在这里重复出现，页面提供“本地扫描任务”入口查看其顶层批次。
- 提供关键字、目标游戏目录和任务状态筛选，并用固定高度摘要胶囊快速切换全部、运行中、需处理、等待审核和已完成。
- 列表按游标每次最多加载 20 条，滚动到已加载内容末尾再拉取下一页；只对当前已加载且尚未终结的任务每秒刷新一次，多个批次可同时推进，全部终结后停止轮询。
- 任务使用卡片行显示当前阶段、保守估算的完成比例、待审核/异常条目分布、更新时间和唯一的下一步；横向信息较多时由列表自身滚动，不能造成页面横向溢出。
- 异常入口复用进度条下方的“N 异常”文本：仅 N 大于零时可点击并展开，零异常不渲染无效按钮；异常 reason code 支持鼠标悬停和键盘聚焦查看具体说明。
- 任务行不提供只展开内部 UUID 的“技术详情”；与处理问题无关的任务 ID 不占用列表空间。
- 展开任务时在同一卡片下方显示六阶段摘要，不插入内部任务 ID；进入待审核必须携带 `importJobId`，完成任务可直接查看审核历史。
- 分组前被拒绝的文件（如多 primary、nested archive、RAR/TAR、加密/分卷/SFX 7z，或不允许 archive wrapper 的 CHD/ISO/CSO）在本页按文件名和稳定 reason 展示“重新配置并导入”。该入口复用服务器 CAS 中尚未解决的拒绝文件，回到带只读文件摘要的三步导入页并允许重新选择游戏目录；不能要求浏览器重新上传，也不能绕过 archive 安全门禁。合法单 ROM ZIP/7z 则显示来源格式与将物化的唯一成员。被拒绝文件没有 ImportItem，不能错误地提供“进入审核/重新归组”。
- 识别阶段发现同基础平台的未删除游戏已使用完全相同内容时，任务仍可正常完成，不计入异常。卡片摘要显示“已跳过 N 个已导入条目”，详情列出 `ALREADY_IMPORTED` 文件和可点击的已有游戏；不提供审核或发布入口，也不能只显示一个没有操作空间的“需要处理”。
- 审核决策与字段 diff 不放在本页，避免把 Worker 运行态和业务审计混在一起。
- 总览“需要处理”的计数行必须是可键盘操作的链接；流程图描述各阶段职责或真实计数，不得为已完成任务统一显示“等待新内容”。

完整任务和恢复规则见 [导入、刮削与审核](./import-and-review.md)。

### 7.2 待审核与审核历史

`/admin/reviews` 首先是可浏览的全局待审队列，不得直接把第一条详情冒充整个页面。队列支持关键字、导入批次、Pegasus 批次、游戏目录、Blocker 和更新时间排序；服务端每页最多返回 20 条，用户滚动到已加载列表末尾才继续取页。同一次停留在底部预加载区只自动读取一页，哨兵离开并再次进入后才能继续自动读取；任一时刻只允许一个续页请求，键盘和失败重试继续使用“继续加载”按钮。每行详情入口必须关闭 Next.js viewport 自动预取；只有用户实际点击“审核/处理”时才读取详情，不能让长队列同时触发多份 RSC 详情、认证上下文和封面请求。“当前已加载 / 可以发布 / 运行异常 / 未找到信息”是作用于已加载集合的可操作筛选按钮，数量必须来自相同集合并随加载和筛选同步更新。每行展示封面缩略图（无封面用占位图）、来源文件/目录、草稿标题、文件总大小、主内容 MD5、目标游戏目录、Validation 状态、信息来源和更新时间；桌面队列的各行必须复用同一列轨，目标游戏目录和信息来源等列不能因 Validation/Blocker 文案或操作按钮宽度不同而左右漂移。Pegasus metadata 已读取时显示“Pegasus · Collection / 等待管理员核对”，不能因 `candidateCount=0` 误归为“未找到信息”。列表不展示含糊的“批次详情”或直接下拉 UUID；普通任务页进入审核带 `importJobId`，Pegasus 任务详情进入审核带 `pegasusImportId`，固定批次筛选在“清除全部”后仍保留。

详情页顶部使用“当前条目摘要 + 审核决定”左右结构，条目摘要显示来源、目标目录、运行检查和游戏信息命中状态，并在容器最右侧保留固定的“第 5 秒运行截图”槽；截图槽在宽屏占摘要内容宽度的 17%（最小 120px），是原 34% 宽度的一半。当前 READY 或阻断 Validation 的实际截图均可显示，待运行或已过期状态使用明确占位，不复用旧图冒充当前结果。阻断条目取得截图后，状态文案改为“已取得运行截图”，审核决定明确说明管理员可以据此人工放行。审核决定集中展示实时保存状态与四个操作，不再复制“可以发布”提示。下方使用“能不能发布 / 来源文件”左栏和“发布成什么”右栏，宽屏下右栏与左侧两个容器堆叠后的总高度一致；右栏内部以中间元信息、最右媒体预览的顺序组织，也不展示重复的 Hasheous 候选摘要或信息来源卡片。标签选择器属于中间元数据表单并排在其他字段之后，不得作为媒体/元数据双栏之前的同级区块重复占用整栏高度；双栏内全部字段和媒体必须保持在发布面板内容边界内。Pegasus 来源封面作为默认封面，在用户选择候选或人工上传封面后退居后备；Pegasus VIDEO 在媒体预览中使用 `object-fit: contain` 与 `object-position: 50% 50%` 水平、垂直居中完整展示且不自动播放，审核通过时默认保留。简介标签与文本域保持常规表单间距，额外的栏高只用于扩展文本域，不能在二者之间形成空白。封面栏使用剩余高度等比放大封面，图片底边与栏内容底边对齐，不得以固定最大高度在下方留下大块空白；缺少封面时占位区遵循同一高度。1280px 下顺序折叠为单栏并按内容自然增高，不得沿用宽屏等高约束裁切元数据、封面或视频。选中条目后 URL 更新为 `/admin/reviews/:itemId`，返回按钮保留原队列筛选上下文。若条目在列表加载后被另一页面或管理员处理，详情接口的 404 视为待审状态已经失效：页面返回原筛选队列、清除该队列的浏览器快照并提示“已处理或不再可用”，不得落入通用后端故障页或继续恢复旧卡片。

首次刮削成功时，页面把候选基础信息和 READY 封面自动填入草稿并立即通过当前 ETag 实时保存。之后每次“重新查询游戏信息”只产生一个对比对话框：最外层固定为左右两栏，左栏是当前信息，右栏是最新结果；每一栏内部的上半部再分为左侧短元信息（标题、开发商、发行商、类型、玩家数和年份等）与右侧 3:4 封面，下半部展示该栏完整简介。对应字段一致显示绿色边框，不一致显示红色边框；右栏短字段、简介和新封面可编辑或替换，左栏保持只读。取消丢弃本次结果，应用覆盖当前客户端状态、清除不兼容的旧候选素材选择并触发实时保存；页面下方不得不断追加查询结果卡片。

“重新运行检查 / 运行游戏、丢弃条目 / 通过并发布”按视觉顺序排列为两行两列，四个按钮使用完全相同的列宽和可点击高度；`运行游戏`位于`重新运行检查`右侧，使用克制的浅紫次操作样式，不能与主发布按钮争夺层级。“重新运行检查”只保存草稿并刷新服务端 Validation 与页面状态，不调用 `window.open`、不创建审核 Preview，也不因结果 READY 自动运行游戏。“运行游戏”必须从原始 click 同步打开独立子窗体，再异步创建审核预览，避免浏览器弹窗策略把它阻断；阻断条目仍允许尽最大可能交付主 ROM 与当前已有依赖。每次核心真实触发 `EJS_onGameStart` 后均在第 5 秒自动截图，不以依赖状态为前置条件；审核预览优先读取核心自身保存的最后一帧，以保留停止刷新的 ROM/BIOS 缺失错误画面，2 秒内不可用时回退到 canvas 截图。阻断条目取得与当前 Validation 一致的截图后，“通过并发布”解除置灰，管理员可用截图人工判断。重新检查生成新 Validation 时旧截图立即失效，不得继续放行。弹窗被阻止、运行失败、未触发游戏开始或截图上传失败都提供可操作提示，不把旧截图当成成功。

页首摘要卡片使用稳定高度，内部第 5 秒运行截图不写死独立高度，而是拉伸占满摘要卡片提供的可用空间；等待、阻断与真实截图三种状态不能改变摘要卡片的外框尺寸。真实图片只在截图框内 `contain` 等比缩放，不能根据原始宽高比撑高最外层摘要卡片；摘要卡片与右侧“审核决定”顶部对齐且互不拉伸。

最终决策仍位于页首“审核决定”卡片，不显示与运行检查重复的“可以发布”，也不收集发布说明或丢弃原因。决策前先冲刷尚未落盘的实时保存；提交时按钮显示处理中，成功后 toast 反馈并替换到当前筛选下的相邻条目，队列为空则返回列表。目标目录/default DOS entry 改变或 CoreArtifact/DAT/BIOS 配置漂移后，旧 Validation 与截图明确标为“已过期”；当前 READY Validation 或当前阻断 Validation 的第 5 秒截图任一存在时可发布。截图放行后的正式 Variant 必须显式保留人工 override 证据，不能伪装成严格依赖检查通过。若相同内容在当前未删除游戏中已存在，正文常驻提示并链接已有游戏；点击发布弹出危险确认框，主按钮命名为“仍然发布为新游戏”并说明可能产生重复条目。页面加载后才出现的重复项由 approve 的 `409` 打开同一确认框，不能降级为普通 toast 或要求用户重新上传。

“能不能发布”直接显示游戏文件、运行检查和依赖检查三条普通语言结论，不提供只包含内部 ID 的技术详情。运行检查错误详情按内容自然增长到 360px 上限，超过后只在详情内部显示可由鼠标和键盘操作的垂直滚动条，不能继续拉高左栏并反向撑大右侧发布信息或封面区域。来源为 ZIP 时“来源文件”默认展开，展示成员文件名、大小和 CRC32，并在固定高度内纵向滚动；来源文件已有 SHA-256 时用“大小 / 截断 hash”展示并用 tooltip 提供完整值。页面不使用无来源的分隔线。

Arcade 详情在运行检查区域增加“Arcade 运行依赖”卡片，根为 CONTENT `<machine>.zip`，后续节点严格按服务端 `requiredBy/depth` 形成与 DOM/Tab 一致的树序。每个节点展示 Parent 或 BIOS/Base、期望逻辑名、由谁需要、必需 entry 数量和文本状态；长 machine name 必须换行并用 tooltip 给出完整值。没有任何 Parent/BIOS/Base 节点时，卡片角标固定显示“无额外依赖”，不得沿用整条 Validation 的 blocker 状态显示“需要处理”；兼容性 blocker 仍由上方运行检查结论展示。`SATISFIED_BY_CONTENT` 显示“由游戏文件满足”，`SATISFIED_EXTERNAL` 显示“已匹配”；只有 Parent `MISSING/MISMATCH` 显示“补充/重新上传 Parent ROM”，BIOS 缺失只显示“前往 BIOS 文件”，Merged/CHD/cycle 不显示伪修复按钮。

Parent 操作打开可用键盘关闭和焦点回退的 modal，只接受一个 ZIP，展示原文件名和大小，并明确“本地文件名可以不同，系统按内容校验”。先显示通用分块上传进度，再通过 Job SSE 以 `aria-live` 显示安全扫描、内容匹配、来源快照和完整重验证阶段；断线恢复不取消任务。active Attachment 期间禁用重复上传和发布。成功且全部满足时提示运行检查通过并启用发布；接受 b 但仍缺 c 时关闭 modal、保留页面并展示下一可修复节点；内容错误/不安全时保留旧树和 entry 摘要，提供重新上传；retryable 只显示“重试校验”并复用 bytes；stale 提示刷新后按新依赖操作。离开页面不取消任务，返回后根据 Review GET 的 activeAttachment 恢复 SSE；Discard 才请求取消。若 Parent 完成后的系统版本推进与发布请求交错，页面重新读取审核详情；只有目标目录、发布字段和选择未发生变化、最新状态已可发布且没有 active Attachment 时，才透明使用新 ETag 再提交一次。其他并发编辑或第二次冲突仍显示人工核对提示，不循环重试。

依赖树在 2560×1440、4K 和 1280px 折叠布局中不得使页面横向溢出；颜色不是唯一状态信号，选择文件、提交、关闭、BIOS 跳转和重试均可用键盘完成。

系统不提供盲目批量 Discard，也不把截图人工放行或重复内容确认自动化。每个条目的草稿、候选、Validation 和最终 ReviewEvent 仍独立；快速审批只把服务端再次证明为严格 READY 的冻结子集交给后台逐项原子发布。需要管理员判断的条目继续依靠可见队列、批次筛选、任意跳转和决策后自动聚焦下一项逐条确认。

“审核历史”是独立的只读审计页；列表不展开无解释的技术 UUID，点击整行以对话框展示审核完成瞬间的标题、简介、开发/发行、类型、玩家、年份和封面快照。最终审核事件引用的 READY 候选媒体在条目离开待审状态后仍可读取；历史媒体确实缺失时显示明确占位，不渲染裂图。完整输入/输出、配置和 provider 证据仍由只读事件详情 API 保留，历史页不能修改旧事件或复用为待审核队列。

### 7.3 游戏管理

列表页先用等宽摘要卡展示全部游戏、运行异常、缺少封面、资料不完整和用户不可见数量；摘要基于完整管理集合计算，不随当前页分页漂移。下方工具条在固定高度内依次提供即时名称搜索、基础平台、依赖平台的游戏目录、标签、用户状态、运行状态和排序；桌面端“排序”必须紧跟“运行状态”并与其保持同一行，不得单独换行。任一条件变化只更新结果表、URL 与页码，不触发整页刷新，也不插入会推动页面的筛选标签。`/` 在非编辑控件中聚焦搜索框。

游戏以紧凑表格展示 70×84 封面缩略图（无封面显示包含标题/平台的占位）、标题/平台/年份/目录、用户状态、目录默认核心当前运行状态、推荐运行方式与最近更新时间。每页固定 6 条并提供上一页/下一页；1280px 下宽表只能在带可见焦点的自身容器中横向滚动，封面列与管理操作列 sticky，页面本身不能横向溢出。正常与异常状态都带文字，不只依赖颜色；“导出当前列表”仅导出当前筛选后的结果。管理按钮进入 `/admin/games/:gameId`。

管理详情不是用户游戏详情复用表单。页头下依次为封面/身份/状态概览、所属目录/推荐运行方式/当前文件/最后验证/关联存档摘要，再进入固定四区；不显示“基本信息 / 媒体 / 游戏文件与运行 / 管理操作”锚点导航，用户按页面自然滚动浏览：

1. “发布信息”：标题、描述、年份、开发商、发行商、类型、玩家数；保存创建新的 MetadataRevision，必须携带当前 ETag。初始进入、用户没有修改任何字段，以及保存成功后，“保存新版本”都必须禁用；只有当前表单与已保存基线有实际差异时才启用。
2. “媒体”：只展示当前封面与视频预览及各自替换入口；背景图和游戏截图没有用户侧消费入口，不占用管理工作台空间，既有历史资产不会因页面收敛而删除。封面容器始终保持 3:4，在双栏中按可用高度等比放大，底边与“媒体”内容容器对齐，图片居中裁切填满；视频槽占据封面之外的全部可用宽高，视频保持原始宽高比完整适配、不裁切，并在槽内水平、垂直居中。上传成功创建新 Asset，不原地覆盖旧 Blob。
3. “内容与运行版本”：先展示 Game 当前/历史 GameContentRevision 及用户文件清单，再按 Core 展示稳定 GameVariant、当前/历史 VariantRevision、CoreArtifact、DAT、派生文件、依赖诊断和兼容状态；替换游戏文件先走 upload 会话与可观察 Job，只有新内容对目录默认 core 验证 READY 且配置快照未漂移时才原子切换 Game content 与目标 Variant 两个 current，失败保留旧版本并提供 retryable 重试。
4. “管理操作”：重新刮削只生成候选预览，完成后自动打开与审核页一致的对比窗口；最外层保持“当前信息 / 最新候选”左右两栏，每栏内部上方为“短元信息 + 3:4 封面”、下方为完整简介。应用时未提供的字段和媒体保持当前值，确认后才创建 metadata revision。移动目录必须先主动选择目标并点击预览，若返回 `VALIDATION_PENDING` 就在原对话框展示可返回的任务进度并等待，任务完成后自动用新幂等键重新预览，绝不提前移动；软删除独立置于默认折叠的红色边框区，展开后才显示标题确认与存档/审核历史影响，历史引用不级联删除。

在 1920px 基线下，“发布信息 / 媒体”采用 `58% / 42%` 双栏，双栏高度由左侧发布信息的自然内容高度决定，右侧媒体面板必须与其同高且不能反向撑高左侧；运行区、管理操作和移除区全宽。较窄桌面可顺序折叠为单栏并各自使用自然高度。分区标题只显示“发布信息”“媒体”“游戏文件与运行环境”“管理操作”“从游戏库移除”，不增加“信息版本 · N”“媒体资源”“运行状态正常”“维护工具”“危险区域”等装饰标签；版本数量留在顶部概览，兼容状态留在运行摘要，避免标签重复信息层级。

所有长任务进入任务进度并可回到此页；成功/失败反馈必须对应实际 revision/job ID。页面不得提供直接编辑 CoreArtifact/DAT hash、宿主路径或物理 Blob 的字段。

文件上传使用隐藏原生 input 和有明确中文名称的按钮触发，不能把浏览器本地化的 “Choose File” 作为正式界面。主区域使用“推荐运行方式、兼容状态、最后验证”等用户语言；完整 revision/artifact/DAT ID 只在“技术详情”展开区显示。成功与错误反馈使用不改变页面高度的浮层，避免操作后工作台抖动。

### 7.4 游戏目录

页面标题、后台菜单统一使用“游戏目录”；API、数据库与领域模型仍使用 PlatformInstance。全新数据库初次进入显示真正的零目录空状态，不自动打开创建 Drawer。页头依次提供“排序说明”“补齐推荐目录”和“新建游戏目录”：补齐按钮显示当前缺失数，点击一次直接提交严格空对象并在完成前禁用排序、补齐与新建操作；没有缺失项时显示“推荐目录已齐全”，推荐状态不可读取时禁用并提示暂不可用。成功使用固定位置 toast 说明新增数及已由等价/停用/删除目录覆盖的数量并刷新服务端投影；失败保留原列表并明确说明未创建任何目录。空状态同时提供“补齐推荐目录”主操作和“手动新建目录”次操作。

“新建游戏目录”打开宽 520px 的右侧 Drawer，按“选择游戏平台—定义目录信息—选择推荐运行方式”三步填写并展示创建预览；Drawer 标题只显示“新建游戏目录”，不再重复“新建平台实例”标签。创建表单不展示网址标识等技术字段；不可变 slug 由服务端生成，初始顺序自动追加到末尾。

页头下方固定高度筛选区提供目录名称/平台/说明即时搜索、游戏平台、启用状态和排序方式；筛选只改变列表，不整页刷新，也不插入推动页面的条件标签。其后只提供“全部”“已启用”“已停用”三个可操作的快捷筛选按钮，不展示无对应筛选行为的空目录或 Arcade 统计胶囊。列表每行固定约 88px，依次展示全局顺序、名称/说明、游戏平台、扩展名、游戏数、推荐运行方式、启用状态和操作菜单；名称/说明列相对旧布局收窄，为位于游戏平台和游戏数之间的扩展名列留出空间。扩展名以紧凑、可换行的等宽标签展示基础平台实际接收的 payload 格式，不显示普通 ROM 上传 wrapper 的 ZIP/7z。名称和用户说明从操作菜单进入紧凑行内编辑，说明编辑框保持单行控件高度并在内部滚动，不能撑高列表行。推荐运行方式直接使用下拉框，选择后仍执行影响预览与确认；启用状态使用 checkbox，并允许非空目录切换，以控制关联游戏是否出现在用户侧。操作菜单中非空目录的删除禁用并解释原因，空目录可经确认删除。

排序不暴露数字输入，使用拖拽手柄，并提供上下方向键等价操作；仅在无搜索/筛选且排序方式为“展示顺序”时允许调整，筛选态明确提示仅查看。排序结果通过带所有目录版本的原子接口保存。排序、内联编辑、核心切换和启停成功后就地更新，不插入会推动表格的成功提示条，失败才显示错误。

默认核心的列表态以“推荐运行方式”下拉框显示当前值。选择另一核心会自动请求影响预览；预览不提交，无论受阻游戏数是否为零，提交前都必须在应用对话框中再次明确确认。

推荐补齐不会弹出逐项确认或选择器，也不把 release 模板当成不可修改的系统目录：补齐后仍可按普通目录重命名、换核心、停用或在为空时软删除；后续补齐必须尊重这些选择而不创建替身。按钮、toast、空状态和请求中状态均有非颜色文本与 `aria-live`，手机触控目标不小于 44px。

### 7.5 运行依赖与 BIOS

BIOS 文件页默认展示当前游戏库实际所需项，并可在页面内无刷新切换完整 BIOS 目录。页首固定显示当前范围、缺失/阻断、需要核对和已就绪四项摘要；关键字、运行方式和状态筛选以及“需要处理/必需/可选”快速筛选只更新下方结果，不插入推动内容的标签。列表先展示会阻断或需要核对的项目，再展示已就绪与可选项；当前接口不能证明的“影响 N 款游戏”不得用示例数字冒充，改用真实的当前游戏库引用、阻断和可选语义。STATIC 文件的期望/当前 MD5 直接展示，`HASH_WARNING` 明确说明仍可启动。已安装的 Arcade `DAT_MACHINE` ZIP 把文件名显示为可聚焦按钮；点击打开宽对话框，左侧为该 Requirement 锁定 DAT 版本要求的完整面板，右侧为安装时已安全扫描并落库的 ZIP 实际内容面板，不增加居中的第三栏。两侧各自以文件列表展示；`name`、`size`、`crc` 是位于列表上方的横向三列表头，每个文件在下方占一个仅略高于文字行高的紧凑行并按相同列序展示对应值，字段名不得重复放到每行左侧。匹配、内容别名、校验不一致、缺失和额外文件通过整行背景色区分，行内不显示状态徽标或状态文案；鼠标悬停时 tooltip 显示具体状态，辅助技术仍可读取同一说明。两栏共享纵向滚动位置以便目视比对。HTTP 读取不重新解压用户内容。

Arcade DAT 不在 Web 后台暴露列表、上传、差异、启用或回滚入口。BIOS 页说明 DAT 随核心版本自动准备；若内置目录尚未完成索引，审核和导入页面把它呈现为 release 依赖/Ready 故障，并指向部署者可执行的 `make prepare-deps` 与健康检查，而不是链接到不存在的管理页。固定版本、启动门禁和历史证据规则见 [BIOS 与 Arcade DAT](./bios-and-arcade.md)。

### 7.6 用户管理
`/admin/users` 以用户名、显示名、角色、状态和创建时间展示账号，不返回密码参数、会话 token hash、邀请/reset secret 或私有资料摘要。页首提供用户名/显示名即时搜索以及角色、状态筛选；宽表的身份列与操作列 sticky，1280、2560 与 3840 CSS px 下均不能产生页面级横向滚动。

点击用户行打开有焦点陷阱和返回焦点的右侧 Drawer。管理员只可修改角色和启停状态，不能修改 username、displayName、Profile 或密码；改变角色、停用、启用和删除都使用带用户名与影响摘要的应用确认对话框，并提交列表返回的 ETag。服务端 `412` 时保留编辑内容、刷新真实状态后要求重新确认。当前用户不能停用、降级或删除自己；最后一个可登录管理员不能被降级、停用或删除；删除采用软删除并立即撤销该用户认证会话、账户链接和未结束 Launch。

“创建邀请”和“生成重置链接”成功后使用阻断式一次性 secret 对话框：只显示一次完整 URL，复制按钮有明确反馈，关闭时从 React 状态和 DOM 清除。邀请列表展示角色、创建者、过期时间和已使用/已撤销状态，并支持显式撤销；管理员不查看或代填用户密码。只读 `setup-code`、离线 `admin-reset` 和 restore 安全栅栏只由主机 CLI 提供，不在 Web 后台提供绕过入口。视觉和交互基线见本章顶部的账户与用户管理设计稿。

### 7.7 服务器 BIOS 与 Pegasus 导入

“游戏入库”子菜单固定为“导入游戏、本地扫描、任务进度、待审核、审核历史”。“本地扫描”只命名该导航入口，页面领域标题仍使用“服务器导入”。`/admin/imports/server` 并列显示“扫描并导入 BIOS”和“扫描并准备 Pegasus 审核事项”两张等权能力卡，共用一段只读 root 说明；无 root 时两张卡均禁用并显示部署说明，不提供绝对路径输入。Pegasus 卡片直接说明“不会自动发布”，并显示所有历史计划当前待逐项审核总数。两类任务在同页历史区明确标记类型且各自分页，不把不同状态机拼成一张假统一表。`/admin/bios` 的“从服务器目录批量导入”跳到 `?action=bios` 并只打开 BIOS Drawer；`?action=pegasus` 只打开 Pegasus Drawer。

创建 Drawer 使用 root radio、面包屑和直接子目录分页浏览，展示 `<root label> / <relative path>` 与完整 catalog 范围；“允许使用更优候选替换”默认关闭并说明同分/更差不会替换。pending 时锁定选择；Drawer 有 focus trap、Escape 和关闭后焦点恢复。

`/admin/imports/server/:id` 通过 Job SSE 展示真实阶段/计数，断线保留内容并重连，离页不取消。详情摘要区分导入、无需变更、未找到、需核对和失败；结果及候选每页最多 50 条，服务端筛选写入 URL，候选弹层展示相对路径、hash/DAT entry 证据、rank 与未选原因。取消确认明确不回滚已提交 Installation，retry 只在服务端声明可用时出现。

BIOS FULL_CATALOG 首屏和续页固定 100 条；距底部 600px 自动拉取，Set 去重且同时只有一个请求。切换 scope/query/filter 时 abort 旧请求并清空 cursor；追加失败保留旧页并可用相同 cursor 重试。IntersectionObserver 不可用和纯键盘场景必须可用“加载更多”，`aria-live` 播报新增/完成。1280×800 只允许结果表自身横向滚动，页面不得溢出；2560×1440 与物理 4K、150% scale 场景遵循统一后台画布，且减少动画模式关闭非必要过渡。

Pegasus Drawer 为 760px 右侧三步流程：“选择目录 → 检查与映射 → 确认审核计划”。第一步复用 root radio、面包屑和直接子目录浏览，只展示 root label 与相对路径；开始扫描后可关闭 Drawer，重新打开时恢复该 SCANNING/AWAITING_MAPPING 计划。Drawer 打开期间必须锁定背景滚动并保留滚动条宽度；同一计划的轮询摘要更新不得重建 Drawer、转移焦点或重置尚未提交的映射。第二步展示每个 Collection 的游戏数、扩展名和明确的游戏平台目录选择；不设默认映射，所有 Collection 都选择后才可继续，提交用计划 ETag 并按最多 100 条分批。该步骤在 Collection 列表之前提供“批量添加默认标签”：管理员选择既有活动标签并显式应用后，以 union 语义追加到全部当前未跳过 Collection（包括尚未选择处理方式者），不得覆盖已有选择；下方 Collection TagPicker 继续支持逐项增删，切换为 `SKIP` 必须清空该项标签。第三步以清晰摘要确认来源、处理/跳过数量、默认标签覆盖的 Collection/游戏数、可处理/源内容阻断、封面/视频、预计读取量和“全部进入待审核，由管理员逐项决定”的发布方式；主按钮为“开始准备审核事项”，正文明确后台不会创建游戏，不让浏览器解析 metadata 或决定兼容性。

`/admin/imports/server/pegasus/:id` 展示阶段、计数和映射快照，通过 SSE 更新并在断线时有界轮询；处于 `AWAITING_MAPPING` 时，详情头必须提供“继续映射”，直接为当前计划打开第二步 Drawer，不得要求重新选择目录或重新扫描。未保存的映射仍须重新选择；已经完整保存映射的计划恢复后直接进入第三步确认。过滤条件 `q/outcome/warning/collectionId` 写入 URL。条目每页最多 50 条，展示 Collection、目标游戏平台、来源相对路径、准备/审核结果、已有/新游戏链接以及 cover/video 的 READY、MISSING、WARNING 文本状态。任务完成且仍有待审核项时，页首显示独立紫色审核行动区，说明“内容已准备好，但尚未进入游戏库”，主操作“审核 N 个游戏”进入 `/admin/reviews?pegasusImportId=:id`；每个 `REVIEW_PENDING` 行另提供“审核并决定”或“处理运行问题”。快速审批只在统一待审核页对这个筛选范围提供，Pegasus 详情不复制按钮或发布状态机。摘要按“扫描范围 / 等待审核 / 已发布·已丢弃·已存在 / 源内容阻断·任务失败”分组，避免把任务准备完成误读为已发布。

`/admin/reviews` 页首在“审核历史”旁提供“快速审批”。点击后以应用内确认对话框加载当前 URL 筛选的完整服务端预览，不受当前已加载页影响；对话框突出可自动发布数，并分列说明阻断截图人工放行、重复内容、活动补传和其他不 READY/已过期排除数。零 candidate 时主按钮禁用并说明下一步；存在其他 active batch 时显示其进度，不允许启动第二个批次。确认期间筛选或候选漂移时保留对话框并刷新数字，要求再次确认，不能静默使用新集合。

批次启动后对话框关闭，筛选区上方显示非跳动状态卡：状态文本、`processed/candidate`、发布/跳过/失败/取消计数、进度条，以及只在可用状态出现的取消或重试按钮。“停止未处理项目”必须先用应用内 Dialog 说明已发布游戏不会撤销，再提交取消。URL 记录 `bulkApprovalId`，刷新或返回可恢复轮询；终态清除当前用户所有 `reviews:` 队列快照并刷新服务端列表。结果区最多先列 50 个条目，标题链接到对应 Review 或 Game，跳过/失败有非颜色结果文本。手机上页首操作换行、预览对话框单列、状态卡计数两列；所有按钮至少 44px，Dialog 具备焦点圈定、Escape/取消和触发器焦点恢复。

阻断或失败行先显示可理解的具体原因，展开“查看具体原因与处理建议”后展示稳定错误码、检查 Core/machine、缺失或不匹配条目、parent/BIOS/多盘依赖明细及对应修复动作；内部失败另展示失败阶段、内部操作、底层 cause code、Pegasus Item ID、来源相对路径、观察数量/上限、可用的内部 ImportJob/ImportItem ID 和受限技术详情。BIOS 阻断提供 BIOS 管理入口。不得只显示“运行检查阻断”或没有排查上下文的 `PEGASUS_LIBRARY_IMPORT_FAILED`。可重试失败在页头提供“重新运行检查”，直接复用原计划和映射恢复诊断，不要求重新选择目录。取消不删除已生成审核事项或回滚已发布游戏；普通 retry 只为服务端声明可重试的终态提供，delete 只允许已结束且不再引用外部 source 的计划。

游戏详情 Hero 先展示 cover。存在 VIDEO 时，视频必须 muted、inline、loop、`preload="metadata"`；仅在页面前台且 Hero 可见累计 2 秒后尝试自动播放，`playing` 后以 200ms 淡入。播放拒绝、媒体错误、stalled 或 5 秒无 `playing` 时保持封面并提供显式播放；用户暂停后本次页面不再自动恢复。`prefers-reduced-motion` 下完全禁用自动播放和淡入。游戏库卡片/列表不加载或自动播放视频。管理员媒体区提供占据封面外全部剩余空间的独立 VIDEO 槽，只接收 MP4/WebM；视频尺寸可未知，使用 `object-fit: contain` 与 `object-position: 50% 50%` 等比居中完整适配且不自动播放，上传、替换和删除都产生不可变媒体 revision。

### 7.8 标签管理与跨页面接入

`/admin/tags` 位于“游戏管理”之后，标题为“标签管理”，说明“建立后才能用于游戏、导入和扫描”。筛选工具栏并列提供“添加常用标签”和主操作“新建标签”；常用标签按钮原子补齐领域模板，已有同名活动项跳过，完成后报告新建/已存在数量，重复点击不产生重复项。其前固定显示活动标签、已关联游戏、待审核引用三项真实摘要，以及名称、状态和排序筛选。桌面表固定为名称、状态、已发布/已删除游戏、待审核、扫描映射、最近更新和操作；1280 以下仅表容器横向滚动并 sticky 名称/操作，390px 转为同字段卡片。

创建/重命名使用 520px 右 Drawer，打开后聚焦名称，显示 code point 计数与规范预览；错误或 ETag 冲突保留输入。删除使用危险 Dialog，展示 usage 影响并要求逐字输入当前完整名称；成功后活动列表消失，切换到“已删除”仍可查看只读 tombstone，不提供恢复。loading skeleton、无 taxonomy、筛选无结果、可重试错误、名称冲突、版本冲突和 1,000 上限都使用独立文本状态。Drawer/Dialog 必须圈定焦点、支持 Escape、锁定背景滚动并在关闭后把焦点还给触发器。

通用 TagPicker 是受控 combobox/listbox：ArrowUp/Down 移动、Enter 选择、Escape 关闭；每个已选 chip 的移除按钮读出完整名称，移除后焦点回到输入。listbox 必须挂载到顶层浮动层、跟随输入框滚动/缩放并根据视口可用空间自动向下或向上展开，不得被普通导入面板、Pegasus Collection 滚动列表、Drawer 或 Dialog 的 `overflow` 边界裁剪。到 20 个时禁用未选项并由 `aria-live` 朗读；没有活动标签时提供标签管理链接，不在任何 picker 内自由创建。业务页面负责获取、owner ETag 和提交冲突恢复。

跨页面位置固定如下：

- 普通导入的“确认配置”选择批次默认标签并在提交摘要展示；reconfigure 只预填原 snapshot 中仍活动者。
- Pegasus 第二步可先把一组默认标签批量追加到所有未跳过 Collection，再为每个 `IMPORT` Collection 单独增删；第三步展示覆盖数量和本批标签，详情展示冻结 snapshot；`SKIP` 没有选择器值。
- 审核队列在标题下最多显示两个 Tag 并支持 `q/tagId`；详情的“发布信息”区编辑完整集合，和其他草稿字段串行自动保存，决定前必须冲刷成功。
- 管理游戏列表在标题单元格显示最多三个 Tag 并支持 `q/tagId`；详情 Hero 显示全部，发布信息区使用独立“更新标签”操作。成功后页面全部后续动作采用响应的新 Game version；DELETED Game 也可清理标签。
- 首页、最近、存档和联机条目最多显示两个活动 Tag；收藏页把游戏标签与紫色 FavoriteFolder chip 放进两个带 label 的区域。Player 不显示也不接收标签。

标签 chip 为中性 taxonomy 样式，不以颜色表达领域值；列表过多使用带可访问计数的 `+N`。统一响应式验证覆盖 390×844、1280×800、2560×1440，以及物理 4K、150% scale 场景，所有页面不得产生 document 横向溢出，axe serious/critical 必须为零。完整领域边界见 [`game-tags.md`](./game-tags.md)。

## 8. 多盘界面闭环

多盘不增加新的一级导航，复用“导入游戏、待审核、游戏管理、游玩页”四条现有路径。新建导入先读取平台 capability；只有服务端返回 `MULTI_DISC_M3U_V1` 时才显示“多盘游戏（M3U + CHD）”。目录树含 M3U 时可自动选择该模式，但必须允许退回 STANDARD；内容布局使用与正文同尺度的紧凑 checkbox，不能继承普通文本输入框的满宽和 44px 高度。提交前显示可处理组、完整组、待补齐组、非法目录和未关联文件的真实数量。每个分组按 M3U 父目录展示 ordered disc、PRESENT/MISSING、忽略文件和稳定错误；按钮数量只计算会形成 ImportItem 的合法完整/缺盘组。平台或默认核心变化使能力消失时立即清除预检并回退 STANDARD，不保留已失效的提交状态。

任务进度卡的状态、进度、问题摘要和右侧主动作使用固定列边界，“需要处理”和“已完成”不能因动作数量不同而横向错位。多盘明细由任务摘要中的紧凑“多盘”入口渐进展开，不在右侧动作列重复显示“查看多盘详情”；右侧只保留审核、查看结果等当前主任务。

审核详情在来源文件上方显示只读“多盘内容”卡，按盘序列出 source basename、canonical label、大小/hash 和缺失状态。缺盘时 Approve 禁用，只允许一次选择当前全部缺失 basename；补传沿用通用 Upload/Job SSE、支持断线恢复和 retryable Job retry，终态重新获取 Review。新 snapshot 生效后原卡就地刷新，旧 snapshot 不可编辑。游戏管理详情显示当前 content kind、ordered canonical discs 与 playlist hash；“替换游戏文件”先打开保留原管理页上下文的对话框，MULTI 选项只在当前目录 capability 允许时显示。多盘替换必须选择完整目录并复用导入预检，但只允许恰好一个完整盘组，缺盘组不能像导入一样继续；失败不改变 current revision。

Player 在 loader 启动前显示“正在准备多盘内容 · N 张光盘 · 总大小”，盘组校验完成后在“创建存档”前显示 `光盘 N / M`。换盘菜单按顺序列出全部盘，支持 Tab、方向键、Home/End、Enter/Space 和 Escape，当前盘有文本/图标双重状态；换盘期间使用 `aria-live=polite`，失败用 alert 并保持原盘号。存档卡和启动入口显示保存时的“光盘 N”；从存档继续不要求用户重新选盘，若锁定盘组不兼容则原位阻断。

## 9. 无障碍与键盘

- 所有图标按钮有可读 label；状态不能只靠颜色。
- `Tab` 顺序与视觉顺序一致，焦点样式清晰。
- 搜索框由容器 `:focus-within` 提供可见焦点；筛选字段都有可见 label；无搜索、筛选或排序参数时不显示“清除全部”，存在任一活动条件时在固定高度摘要中显示“筛选条件已应用”与“清除全部”。
- 应用对话框使用 `role="alertdialog"`、可读标题/说明和 `aria-modal`；打开后焦点进入对话框，Tab 不离开对话框，关闭后焦点返回触发控件。
- Drawer 与一次性 secret 对话框同样约束焦点；密码输入有与视觉标签一致的 accessible name，错误摘要通过 `aria-live` 宣告但不回读 secret。
- 表格内下拉和上传按钮也必须满足 42px 最小高度；隐藏文件 input 的可见触发器必须是可聚焦按钮。
- 下拉框状态文本包含“目录默认/缺 BIOS”等语义。
- 启动后保留 `Escape` 的浏览器全屏语义，并提供明确的退出游戏按钮。
- 动画尊重 `prefers-reduced-motion`。
