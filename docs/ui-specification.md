设计稿是已审定的页面结构、视觉语义和主流程基线，不代表最终封面素材，也不是可复制进产品的 HTML/安全配置。评审导出为了独立打开可加载外部图标脚本并使用宽松 sandbox CSP；正式 Next.js/Player 实现绝不能沿用这些 CDN、inline script 或 CSP，必须遵循 [HTTP API 契约](./http-api-contract.md#2-受信内网写请求) 的 nonce/CSP 策略。稿内示例标题、数量和日期只是视觉内容，不是数据库 seed 或 API fixture。

本文负责完整状态和尺寸契约；静态图未展示的错误/空状态以本文为准。实现若改变导航层级、直接启动行为、阻断状态或审核流程，应先更新本文档和设计稿源文件，再重新生成 HTML/快照。

## 2. 信息架构

### 2.1 用户侧导航

- 首页
- 游戏库
- 我的存档
- 管理后台（侧边栏底部）

游戏详情不是一级导航，不出现在侧边栏。它通过游戏库卡片、首页最近游玩或存档的“查看详情”进入；详情打开时“游戏库”保持高亮。

### 2.2 管理后台导航

- 游戏入库
  - 导入游戏
  - 任务进度
  - 待审核
  - 审核历史
- 游戏管理
- 游戏目录
- 运行依赖
  - BIOS 文件
  - 街机数据目录

“游戏入库”是可点击的父级总览，不是折叠标题。四个子菜单始终位于同一缩进层级，并用左侧竖向导引线、短横连接线和较小行高明确表达从属关系；进入任一子页时仅该子项使用强高亮，父项保留弱上下文高亮。“运行依赖”同样作为父级上下文，BIOS 文件与街机数据目录分别对应独立路由和子项高亮。

进入管理后台后左侧菜单整体切换，并在底部提供“返回用户侧”。基础平台、Core 和 PlatformCore 由代码种子管理；平台目录由用户在后台维护。

## 3. 视觉方向

- 现代桌面应用框架，不大面积使用像素字体或霓虹效果。
- 左侧深色导航，右侧低对比中性色内容区。
- 紫色为主操作色，青色为运行/系统状态辅助色。
- 内容画布使用暖中性 `#f5f3ef`，正文 `#182033`、辅助文字 `#5f697b`；主操作紫 `#6250d2`、成功青 `#0f737c`、警告棕黄 `#8a580c`，状态文字与底色组合必须达到 WCAG AA 正文对比度。
- 封面、截图和游戏画面体现复古；表单与表格保持现代和清晰。
- 正文使用系统无衬线字体，封面小标题可局部使用等宽字体。
- 表格不使用密集竖线，卡片圆角 12–16px，常规图标 16px。
- 普通页面不保留占高的全局顶部栏或重复面包屑；来自 `/health/ready` 的服务状态缩为侧栏底部“管理后台 / 返回用户侧”右侧的状态点，正常为绿色、异常为红色，hover 或键盘聚焦显示可读状态与异常详情。侧栏图标使用同一线性 SVG 体系，不混用 Unicode 符号。
- 主界面优先使用用户能直接理解的中文状态；资源 ID、hash、artifact/revision/job 等工程证据放入“技术详情”渐进披露，不能挤占主任务信息。

## 4. 桌面与 4K

- 目标窗口宽度 1280px 及以上；一期不承诺移动端。
- 常规侧栏 224px，内容区从页面顶部开始并使用 24px 内边距；缩进子菜单不能压缩到省略核心页面名称。
- 常规桌面内容画布最大 2160 CSS px；`2600px` 以上 viewport 可扩展到 2560 CSS px并居中。画布内再按任务设置内容宽度：常规桌面用户首页不超过 1880px、游戏详情不超过 1760px、游戏库不超过 2320px、常规后台表单/表格不超过 1960px；Player、三栏审核工作台，以及 `3840×2160` 首页仪表盘除外。真正的 4K 首页使用应用内容区至少 95% 的宽度，并通过卡片轨道、分栏和留白控制阅读长度，而不是把单行正文拉满。
- `1280–1599px`：224px 侧栏、24px 内容内边距，游戏库与游戏管理按 270–320px 卡宽自动排布，存档卡片 3 列；管理宽表只能在自身带可见滚动提示的容器内横向滚动，不能造成页面级横向溢出，行首标识与行末主操作使用 sticky 固定且键盘可达。
- `1600–2599px`：248px 侧栏、32px 内容内边距，游戏卡继续按共享宽度自动排布，存档 4 列。
- `2600px+`：280px 侧栏、44px 内容内边距，游戏卡继续按共享宽度自动排布，存档 5 列。
- 4K 基准正文 16px；表格/徽标/辅助文本不低于 12px，输入框和按钮不低于 14px、42px 高。
- 详情 Hero 为“封面 / 元信息 / 启动配置”三列，启动面板不漂移到物理屏幕最右侧。
- Player Shell 不受普通内容最大宽度限制。stage 无圆角、无外边距并固定占满 `100vw × 100dvh`；58px 工具栏叠加在画面上方，不能占用 canvas 可用区。
- EJS canvas 的 CSS 宽度为 `min(100vw, 100dvh × 核心报告的画面宽高比)`，CSS 高度由同一宽高比反推并在 viewport 水平/垂直居中；因此竖屏游戏必须贴满可用高度，横屏游戏必须至少有一边贴满屏幕，另一轴只保留必要 letterbox。优先读取 `gameManager.getVideoDimensions("aspect")`，drawing buffer 只作为尚未取得核心比例时的回退；ResizeObserver/画布尺寸观察在 viewport 或比例变化时重算，不得把竖屏内容按横向 backing buffer 留出上下黑边。
- UI 验收覆盖最小桌面 `1280×800` CSS viewport、`2560×1440` CSS viewport、3840×2160 且系统缩放 100% 的 4K viewport；首页还须覆盖物理 4K 屏在高系统缩放和浏览器工具栏占用后的代表性 `1920×950` CSS viewport。

## 5. 全局状态

每个列表和详情资源均定义：

- Loading：骨架或局部加载。
- Empty：原因和下一步操作。
- Error：可理解错误和重试。
- Disabled：说明不可用原因。
- Warning：允许继续但明确风险。
- Blocking：解决前不能继续。

后台异步任务使用 SSE 更新，不以整页轮询闪烁替代。

状态色按语义统一：已就绪/可用/完成使用成功青，处理中/待验证使用信息紫，可继续但需要注意使用警告棕黄，阻断/不兼容/失败/删除使用危险红，未知或停用使用中性灰。业务状态必须先映射语义再选择颜色，不能把所有非 `READY` 状态统一显示为警告，也不能在缺少运行证据时给所有卡片固定显示“可运行”。文字标签必须与颜色同时出现。

高风险或不可逆操作统一使用应用内影响确认对话框，不调用浏览器 `window.confirm`。对话框包含动作标题、普通语言说明、结构化影响摘要、明确的取消按钮和与风险一致的主按钮；默认焦点落在安全操作，`Escape` 关闭且不提交。默认运行方式、游戏目录移动和 DAT 启用等先预览再确认；删除存档、空目录和未启用 DAT 候选也使用同一外观。普通成功/失败使用页面内反馈条，跨页面完成态可追加右上角固定 toast；toast 不参与页面布局并在 2 秒后自动消失，不能以持久提示推动或遮挡页面。审核字段使用带 ETag 的防抖实时保存，页面显示“等待保存 / 正在保存 / 已保存 / 保存失败”，因此不再提供手动保存按钮或未保存离页分支。

列表筛选器必须显示可见字段标签，不以 placeholder 代替 label；搜索与选择条件提交后使用固定高度摘要显示“筛选条件已应用”、当前页结果数和“清除全部”，不再生成可能换行并推动结果区的条件标签。提交通过客户端路由只替换结果区和 URL 状态，不做浏览器整页刷新。依赖筛选变化时清除已经失效的子条件。工程筛选名在用户界面转换成“运行检查、处理状态、排列顺序”等普通语言；内部 ID 和枚举只放在技术详情，审核源文件的 hash 属于用户核对文件所需信息，可以在文件大小后紧凑展示并用 tooltip 补全。

## 6. 用户侧页面

### 6.1 首页

首页标题后固定为五层。3840×2160、100% scale 下五层可用高度按 `46:19:19:12:4` 分配并铺满应用内容区：宽度至少占内容区 65%，最末层底边距离 viewport 底部不超过 48px；物理 4K 高缩放对应的 `1920×950` CSS viewport 下也必须让五层完整落在首屏。两种布局都不得产生 document 纵向滚动条；紧凑态优先压缩页面留白、层间距和媒体高度，不能把正文与卡片字号压缩到影响可读性。首页主容器在相同 viewport 下必须与现有游戏库主容器采用相同最大宽度和居中规则，使其距离左侧菜单栏与屏幕右边的间距分别一致；该约束只调整首页，不改变其他页面的最大宽度与水平位置。更小的普通桌面允许页面纵向滚动。首页不展示待审核等管理员 KPI，不按浏览器时间拼接问候，也不显示无法证明的同步时间。

1. 第一层是“最近玩的游戏 + 快速开始”。左侧以 `started_at_ms DESC, id DESC` 选择最后启动的 PlaySession；旧会话稍后结束或补写 heartbeat 不能反向覆盖它。只有 `source_launch_session_id` 等于该 PlaySession 对应 LaunchSession 的未删除手动存档，才能把主操作从“再玩一次 / 本次将从游戏开头启动”切换为“继续游玩 / 本次将从存档位置启动”；此时主视觉右侧同时展示该存档的 16:9 截图和“将从这里继续”，没有本次会话存档时不占用该区域。宽屏布局中的封面、存档截图、文字和操作间距必须按主视觉容器宽度连续缩放，跨越响应式断点时不能突然缩小；达到可用高度上限后才允许停止放大。中间游戏信息与主操作必须以封面右边缘为定位基准，宽屏下间距保持在 23–33px，连续拉宽过程中的间距变化不超过 9px，不能随剩余空间增大而被推向画面中央。4K 布局中封面高度至少占主视觉媒体区的 75%，存档截图宽度至少占媒体区的 24%；主操作和启动说明固定在媒体区底部，底边留白不超过 50px，3:4 封面底边与主操作按钮底边对齐，游戏信息在剩余空间垂直居中。其他会话或无法证明来源的历史存档不能改变主操作；但只要该游戏存在任意未删除历史存档，标题右侧就显示“查看存档”并进入 `/saves?gameId=<当前游戏>`，否则显示“暂无可恢复存档”。主操作直接启动并默认全屏，游戏详情保持次要入口。右侧快速开始原位提供游戏库、最近游玩和我的存档；下方“按平台浏览”展示按可见 PlaySession 数量降序的前 4 个基础平台，热度相同时按平台名称和 ID 确定顺序。平台入口进入 `/library?platformId=<平台>`。
2. 第二层横向展示按 `lastPlayedAtMs DESC, gameId DESC` 排序的最近 10 款游戏，包含封面（缺失时占位）、标题、基础平台、归属目录、最近游玩时间和累计有效时长；“查看全部”进入 `/recent`。内容超宽时保留可见水平滚动条，在轨道上滚动鼠标纵向滚轮时同步横向移动，键盘用户仍可聚焦并滚动轨道。
3. 第三层“最新添加”复用最近游玩的横向卡片与滚轮交互，展示启用目录中按 `Game.created_at_ms DESC, Game.id DESC` 稳定排序的最近 10 款已发布游戏。卡片包含当前封面、标题、基础平台、归属目录和添加时间；“查看游戏库”进入 `/library?sort=ADDED_DESC`。
4. 第四层横向展示全部有启用 Core 的基础平台，服务端按名称和 ID 确定性排序。用户可用图钉置顶，置顶顺序保存在当前浏览器本地，不修改服务端平台或目录排序；平台入口同样进入游戏库的精确平台筛选。
5. 第五层是单行“我的资料库”摘要，只显示可见游戏数、未删除手动存档数和累计有效游玩时长，不使用抢占主任务视觉优先级的大统计卡。

最近游玩、最新添加与主卡使用当前 MetadataRevision 的封面；主卡没有封面时显示可读占位。最后一次游玩产生的存档即使引用旧 GameVariantRevision，也按该 SaveState 锁定环境恢复。

### 6.2 游戏库

`/library` 先按 cursor 取完全部启用目录中的 `PUBLISHED` 游戏，再在客户端完成浏览和排序；不能只展示接口第一页。页面从上到下包含：

- 标题使用“我的游戏 / 游戏库”的用户侧层级。
- 固定结构的紧凑筛选面板：第一行是即时搜索、游戏集合（PlatformInstance）和排列顺序；第二行以带完整游戏数的平台胶囊展示基础平台，末端固定显示当前结果数。选择平台后，游戏集合只保留该平台的目录；切换到不匹配的平台时清除失效的目录条件。该紧凑工具栏使用“搜索游戏”“所有游戏集合”“最近游玩”等可见控件文案，并为每个控件保留明确 accessible name，属于第 5 节可见标签规则的页面特例。
- 搜索、平台、集合和排序全部在客户端即时更新，仅用 `history.replaceState` 同步 `q/platformId/platformInstanceId/sort`；不提交表单、不整页刷新、不插入筛选标签，也不改变工具栏高度。未聚焦编辑控件时按 `/` 可直接聚焦搜索。
- 排序提供最近游玩、最近加入和名称 A–Z；未游玩游戏排在已游玩游戏之后，所有顺序最终以标题和 Game ID 稳定兜底，刷新不能随机换位。
- 结果标题说明封面是主要识别入口，右侧显示“卡片视图 · `/` 搜索”的键盘提示。

卡片保持 270–320px 固定辨识宽度和 3:4 竖向封面；少量结果从左向右自然排列，不能拉伸填满整行，更多结果再自然向右、向下扩展。真实封面等比裁切填满入口；缺封面时由前端使用标题和推荐 Core 生成 Retrom Classics 海报占位，不读取任何临时设计资源。封面左上角显示基础平台，正文展示标题、平台目录和最近游玩时间；尚无 PlaySession 时明确显示“尚未游玩”。

封面 hover 或键盘聚焦时在底部显示“查看游戏详情”，点击封面或标题进入详情，不直接启动。标题右侧省略号菜单只收纳“查看游戏详情”和“查看相关存档”等低频入口。列表只显示 `PUBLISHED` 游戏时不重复贴“已发布/可运行”徽标；只有存在真实异常投影时才显示状态。缺少必需 BIOS 时仍可见并标记“缺少 BIOS”，不能把生命周期 `PUBLISHED` 推断为运行就绪。

接口响应的 `generatedAtMs` 是最近游玩相对时间的统一时钟；列表项同时提供推荐 Core、`createdAtMs` 和可空 `lastPlayedAtMs`，避免每张卡追加请求。

### 6.3 游戏详情

详情页使用一屏优先布局：面包屑下方依次是 Hero、七项信息条和“你的存档”。在至少 `1600×1000` 的桌面 viewport 中，普通长度的 Hero 与最近 4 份存档应完整落在首屏；更大 viewport 仍受 1760px 内容宽度约束，不能把文字阅读距离无限拉长。Hero 左侧使用 3:4 封面并在下方显示基础平台/年份，中间展示基础平台/游戏目录、标题、年份/发行商/类型、完整简介和累计游玩时长，右侧是启动卡。简介不做行数截断，必须使用整个中栏宽度并允许 Hero 随内容增高；不能在 4K 下只占左侧固定宽度或依赖 hover 才看全。信息条固定展示游戏平台、游戏目录、发行年份、开发商、发行商、类型和玩家数，缺失值明确显示 `—`。

启动卡优先展示最近一份可用存档：包括保持原比例的 16:9 截图、保存时间、锁定 Core 和“从存档继续”，同时保留“重新开始游戏”。没有可用存档时改为单一“开始游戏”。卡片右上角只显示当前运行状态；底部显示普通启动采用的运行方式。DOS 启动程序属于游戏内容选择，仍可在主路径显示。

启动面板完整能力包含：

- 高级区中的核心下拉框，默认选中平台目录推荐核心。
- Core 主状态：目录默认、兼容、需验证、缺少依赖、不兼容；“缺少依赖”再按 reason 明确写“缺少 BIOS”或“缺少 parent ROM”，不混用。若锁定旧 DAT 快照仍可运行但后台重校验为 `PENDING/FAILED`，另显示“待重校验/重校验失败”提示，不把主状态误降为不可运行。
- DOS 启动程序下拉框。
- ROM、parent、BIOS 和环境预检摘要。
- “开始游戏”按钮。

规则：

- 点击“开始游戏”后直接进入加载中的运行壳、自动启动并默认全屏；不会再到一个带 Start 按钮的等待页。
- 全屏目标固定为当前文档根节点并在原始 click handler 中同步请求；不得对隐藏/稍后才 mount 的播放器节点请求，也不得等 launch API 返回后再请求。
- “需验证”核心在同一次启动流程中投递/复用 Variant 验证 Job；加载壳显示“验证核心兼容性 / 生成依赖包”，成功后自动继续创建 Launch，不增加确认页或第二个开始按钮。用户可退出本次等待并退出全屏，但这只断开当前订阅；同 digest Job 可能被其他 Launch 共用，不能从 Player 取消它。
- 缺 BIOS/不兼容时按钮禁用并显示具体文件或原因。
- BIOS hash 不一致是 Warning，允许一次点击继续。
- 用户显式切换核心后，浏览器按游戏记住该选择，后续从该浏览器进入游戏详情时优先用于普通启动；选回推荐核心即清除偏好。该偏好不修改平台目录，存档启动仍锁定存档创建时的运行环境。
- DOS 启动程序或显式“显示程序菜单”只在 Launch 成功创建后按游戏写入浏览器偏好；仅改变下拉框或启动失败都不写。再次进入详情优先恢复该选择，候选已被新 revision 删除/禁用时回退审核默认；审核默认本身不能安全直启时直接回退程序菜单。从状态存档继续不读取也不改写此偏好。
- 使用非默认核心时，“更换运行方式”后显示红色“（未采用默认核心）”，说明文字同步以危险色提示当前游戏已采用浏览器偏好。
- “更换运行方式”使用居中对话框，打开时不改变 Hero 高度。对话框明确说明普通重新开始使用所选 Core，而存档恢复使用存档锁定 Core；选择只在点击“应用”后写入浏览器偏好，点击遮罩、`Escape` 或“取消”放弃本次选择。

详情下方固定展示最近 4 份存档，使用两列横向卡片；截图保持完整 16:9 比例，正文只突出锁定 Core、保存时间、运行环境提示和“从此继续”。点击截图打开不裁切的全屏预览。标题区始终显示总数，“查看全部”在当前详情页打开右侧 Drawer，按保存时间倒序列出该游戏全部未删除存档并支持直接继续；关闭 Drawer 后焦点返回触发按钮。独立“我的存档”页面仍可使用 `/saves?gameId=<当前游戏>` 精确筛选，但不再是详情页查看全量存档的必经跳转。

### 6.4 我的存档

`/saves` 先按 cursor 取完全部未删除手动存档，再在客户端形成完整统计、最近保存和按游戏分组的存档库；不能只展示接口第一页。页面从上到下包含：

- 标题右侧固定显示完整数据集的存档总数和涉及游戏数，不随筛选条件缩减。
- “最近保存”突出完整数据集中最新的一份可用存档，展示大幅保存画面、游戏、基础平台、锁定 Core、保存时间和保存时累计时长；主操作“从这里继续”直接启动并默认全屏，次操作进入游戏详情。该区域不随下方筛选变化；没有可用存档时原位说明并引导查看异常原因。
- 固定高度筛选区支持游戏/存档名称搜索、精确游戏筛选、可用状态筛选和保存时间正/倒序。筛选在客户端即时更新并使用 `history.replaceState` 同步 `q`、`gameId`、`availability`、`sort`，不整页刷新、不追加条件标签，也不推动下方分组跳动；右侧固定显示当前结果数。
- 结果按游戏分组，组头展示基础平台、实际使用过的锁定 Core、存档数、最近保存时间和游戏详情入口。大屏默认预览 5 份，较窄桌面默认预览 4 份，更多存档通过组内“展开全部/收起存档”控制；只有一份存档时用空槽明确说明，而不是把单卡无限拉宽。
- 卡片以保存时刻为主标题，展示保存画面和当时累计游玩时长；自动生成的“手动存档 + 时间”名称不再重复显示，用户自定义名称作为补充信息显示。正常卡片不重复显示“可以继续”；只有存档或运行依赖不可用时才显示红色状态和具体 blocker。
- “从这里继续”置于截图正中央，默认隐藏并在卡片 hover 或键盘 `focus-within` 时显示。不可用存档保留原位但禁用启动。
- 重命名和删除收纳到时间右侧的省略号菜单。重命名在卡片内保持单行高度完成，删除使用统一应用对话框二次确认并说明引用保护期；成功后就地更新列表和统计，使用固定定位 toast，不整页刷新、不插入推动页面的成功提示条。

列表响应的 `generatedAtMs` 是服务端渲染和客户端相对时间的统一时钟；每项同时提供基础平台、平台目录、锁定 Core、可用状态和截图 URL，避免客户端追加请求拼装卡片。

### 6.5 最近游玩

`/recent` 返回并展示全部有游玩记录的可见游戏，不再截断为最近 50 款；它是一款游戏一行的聚合视图，不是逐次 PlaySession 日志。页面按设计稿从上到下包含：

- 三个等宽摘要卡：最近游玩的游戏数、累计有效游玩时长和总游玩次数；摘要始终基于完整历史，不随当前筛选缩减。
- 固定高度筛选区：按标题/平台目录搜索、基础平台筛选、最近时间/累计时长/游玩次数/标题排序，以及全部、最近 7 天、最近 30 天时间范围。筛选在客户端即时更新结果，不整页刷新、不追加条件标签，也不推动下方列表跳动；右侧在固定位置显示当前结果数。
- 结果按当前浏览器本地日界线分成“今天”和“更早”；每行展示横向封面、标题、基础平台/平台目录、最近启动时间、累计有效时长和游玩次数。缺少封面时使用与其他用户侧列表一致的占位图。
- 每行右侧的“再玩一次”直接使用推荐或该浏览器为游戏记住的核心启动并返回 `/recent`；“查看详情”和封面/标题进入游戏详情。筛选无结果时原位展示可恢复的空状态，完整历史为空时说明先从游戏库启动游戏。

接口响应的 `generatedAtMs` 是服务端渲染和客户端 7/30 天滚动窗口、今日分组的统一时钟，避免水合前后跨分钟或跨日造成列表跳动。默认顺序为 `lastPlayedAtMs DESC, gameId DESC`，所有其他排序也必须有稳定的 Game ID 兜底，不能因刷新产生随机换位。

### 6.6 游玩页

正常启动后页面已经在运行或加载 EmulatorJS，不显示二次 Start/Play Now。

- 默认请求浏览器全屏，并隐藏普通侧边栏和顶部导航。
- 加载层只展示 Variant 验证/依赖物化、预检、Core/WASM、ROM、BIOS、存档恢复等进度。验证 Job 失败时退出全屏并返回来源上下文，不自动无限重建 Job。
- 顶部 58px 深色半透明工具栏使用紧凑左右结构：左侧返回按钮先打开退出确认，随后显示完整游戏标题与“运行核心 · 基础平台”；右侧依次是存档同步状态、创建存档、暂停/继续、全屏和更多操作。同步状态以绿/紫/黄状态点配合“已同步 / 正在保存 / 需要处理”等文字表达；BIOS Warning 使用独立黄色提示点，点击后显示可读原因，不能占用一整段工具栏宽度。
- 主操作只保留“创建存档”、暂停状态、全屏和更多菜单；“模拟器设置、查看快捷键、查看运行提醒、退出游戏”收进更多菜单。点击顶部工具栏任意位置或其中任一操作都自动暂停 EmulatorJS main loop，令 PlaySession heartbeat 标记 `paused=true`；工具栏内不能恢复，只有重新点击游戏画面区域才继续，并在暂停画面中央明确提示“点击游戏画面继续”。EmulatorJS 原生底栏始终隐藏且不能被靠近底边或画面点击自行唤出；点击“模拟器设置”显示 Retrom 自绘的居中底部工具栏，固定提供控制、显示、Core 设置、音量、静音和收起，并把前三项桥接到当前 EmulatorJS 实例的真实设置面板。点击自绘栏或设置面板不能误恢复游戏。自绘栏和可见的原生设置面板都不提供 EmulatorJS 退出入口，退出与左侧返回统一使用 Retrom 深色影响确认窗。
- 创建手动存档时必须生成可解码、包含实际画面的 PNG：工具栏触发暂停时先从仍在运行的下一帧采集画面，再暂停并读取状态；若游戏已经暂停则复用进入暂停瞬间缓存的最后一帧，不能读取暂停后已清空的 WebGL canvas。全黑或近全黑的无效采集不得作为“截图成功”的依据。状态与截图仍作为同一次完整创建提交。
- 游戏进入运行态 2 秒无交互后，工具栏向上隐藏，鼠标在任意画面移动或键盘聚焦工具时立即展示，指针/焦点停留在工具栏、更多菜单或退出窗内时不得自动消失。左下角用低对比度短提示说明移动鼠标可恢复控制；加载、toast、存档冲突条和退出窗都覆盖在 stage 上方，不能改变 canvas 的可用高度。
- `Escape` 仅退出浏览器全屏，不结束游戏。
- 显式退出先展示影响确认；确认后刷新持久存档、结束 PlaySession，并返回发起本次启动的详情页、存档页或首页。进入 Player Shell 和退出返回都使用浏览器历史替换，游玩页不得残留为可后退重新进入的历史项。安全取消获得默认焦点，`Escape` 只关闭确认窗而不退出游戏。
- 若另一会话已推进同一 PersistentSave，当前保存以冲突停止，不能覆盖服务器版本或自动死循环；加载层/退出面板必须保留本地 bytes，提供“下载当前保存”和“退出后重新启动”，在用户处理前不谎报“保存成功”。

浏览器拒绝全屏或深链接没有用户激活时的例外行为见 [运行时与游玩数据](./runtime-and-play-data.md)。

## 7. 管理后台页面

### 7.1 游戏入库

父级“游戏入库”进入总览页，不直接显示上传表单。总览只回答“当前入库是否健康、哪里需要处理、最近发生了什么”：

- 页首用“待审核条目 / 异常任务”两张优先处理卡直接暴露阻塞项；数量、说明和行动入口必须组成一个完整卡片，不能只展示抽象 KPI。
- KPI 固定为运行中任务、等待审核、异常条目和历史完成批次；完成批次来自真实累计值，不能伪装成本周统计。
- 流水线按“上传与校验 → 识别游戏 → 运行检查 → 获取游戏信息 → 人工审核 → 发布”六阶段稳定展示，并只使用当前接口能够证明的任务/条目数。
- 最近任务使用紧凑卡片行，只显示目录、创建/更新时间、条目数、信息源、当前阶段和最直接的下一步；完整运行态统一进入任务进度页。

“导入游戏”是聚焦的新建任务页：

- 以“选择内容 → 确认配置 → 上传并验证文件”三步表达上传准备，不在页面内再切换任务或历史 Tab；第三步依次呈现 UploadSession 上传、`UPLOAD_FINALIZE` 校验和 ImportJob 创建结果，不能把三者伪装成同一个后台阶段。
- 支持拖放、选择文件和选择目录；两个选择按钮作为一个操作组在拖放区域水平居中，并保留 Chrome 目录上传的相对路径。
- 分块上传齐备后显示独立的“正在验证与入库文件”阶段，通过当前 `finalizationNo` 对应的 UPLOAD_FINALIZE Job 快照/SSE 显示文件计数和 bytes；只有 UploadSession 进入 COMPLETE 才启用“创建导入任务”。缺失/损坏 part 列出精确文件与 partNo，允许仅重传这些分块；再次完成会显示递增的终结轮次并保留旧轮次历史，不能把旧失败 Job 改成新输入。取消 FINALIZING 需表示为有界取消，不伪装已立即删除正在处理的文件。
- 必选目标平台目录，页面初始不默认选中任何目录，必须由用户主动选择以避免误导入；选择后立即展示推导出的基础平台、默认 Core、EmulatorJS/Core artifact 和 Arcade DAT。
- 元信息源为 Hasheous 哈希查询或“不刮削”；DAT 不出现在元信息源选择中。
- 提交区固定展示将被冻结的任务快照；未选择内容时主按钮禁用并说明原因。

“任务进度”是运行态工作台：

- 提供关键字、目标游戏目录和任务状态筛选，并用固定高度摘要胶囊快速切换全部、运行中、需处理、等待审核和已完成。
- 列表按游标每次最多加载 20 条，滚动到已加载内容末尾再拉取下一页；只对当前已加载且尚未终结的任务每秒刷新一次，多个批次可同时推进，全部终结后停止轮询。
- 任务使用卡片行显示当前阶段、保守估算的完成比例、待审核/异常条目分布、更新时间和唯一的下一步；横向信息较多时由列表自身滚动，不能造成页面横向溢出。
- 异常入口复用进度条下方的“N 异常”文本：仅 N 大于零时可点击并展开，零异常不渲染无效按钮；异常 reason code 支持鼠标悬停和键盘聚焦查看具体说明。
- 任务行不提供只展开内部 UUID 的“技术详情”；与处理问题无关的任务 ID 不占用列表空间。
- 展开任务时在同一卡片下方显示六阶段摘要，不插入内部任务 ID；进入待审核必须携带 `importJobId`，完成任务可直接查看审核历史。
- 分组前被拒绝的文件（如多 primary、nested archive、RAR/TAR、加密/分卷/SFX 7z，或不允许 archive wrapper 的 CHD/ISO/CSO）在本页按文件名和稳定 reason 展示“重新配置并导入”。该入口复用服务器 CAS 中尚未解决的拒绝文件，回到带只读文件摘要的三步导入页并允许重新选择平台目录；不能要求浏览器重新上传，也不能绕过 archive 安全门禁。合法单 ROM ZIP/7z 则显示来源格式与将物化的唯一成员。被拒绝文件没有 ImportItem，不能错误地提供“进入审核/重新归组”。
- 识别阶段发现同基础平台的未删除游戏已使用完全相同内容时，任务仍可正常完成，不计入异常。卡片摘要显示“已跳过 N 个已导入条目”，详情列出 `ALREADY_IMPORTED` 文件和可点击的已有游戏；不提供审核或发布入口，也不能只显示一个没有操作空间的“需要处理”。
- 审核决策与字段 diff 不放在本页，避免把 Worker 运行态和业务审计混在一起。
- 总览“需要处理”的计数行必须是可键盘操作的链接；流程图描述各阶段职责或真实计数，不得为已完成任务统一显示“等待新内容”。

完整任务和恢复规则见 [导入、刮削与审核](./import-and-review.md)。

### 7.2 待审核与审核历史

`/admin/reviews` 首先是可浏览的全局待审队列，不得直接把第一条详情冒充整个页面。队列支持关键字、导入批次、平台目录、Blocker 和更新时间排序；服务端每页最多返回 20 条，用户滚动到已加载列表末尾才继续取页。“当前已加载 / 可以发布 / 运行异常 / 未找到信息”是作用于已加载集合的可操作筛选按钮，数量必须来自相同集合并随加载和筛选同步更新。每行展示封面缩略图（无封面用占位图）、来源文件/目录、草稿标题、文件总大小、主内容 MD5、目标平台目录、Validation 状态、候选数量和更新时间。列表不展示含糊的“批次详情”或直接下拉 UUID；任务页的“进入待审核”必须带 `importJobId` 筛选进入该批次。

详情页顶部使用“当前条目摘要 + 审核决定”左右结构，条目摘要只显示来源、目标目录、运行检查和游戏信息命中状态；审核决定集中展示实时保存状态以及丢弃/发布按钮，不再复制“可以发布”提示。下方使用“能不能发布 / 来源文件”左栏和“发布成什么”右栏，宽屏下右栏与左侧两个容器堆叠后的总高度一致；右栏内部以中间元信息、最右当前封面的顺序组织，封面不再单独占据表单底部，也不展示重复的 Hasheous 候选摘要或信息来源卡片。简介标签与文本域保持常规表单间距，额外的栏高只用于扩展文本域，不能在二者之间形成空白。封面栏使用剩余高度等比放大封面，图片底边与栏内容底边对齐，不得以固定最大高度在下方留下大块空白；缺少封面时占位区遵循同一高度。1280px 下顺序折叠为单栏。选中条目后 URL 更新为 `/admin/reviews/:itemId`，返回按钮保留原队列筛选上下文。

首次刮削成功时，页面把候选基础信息和 READY 封面自动填入草稿并立即通过当前 ETag 实时保存。之后每次“重新查询游戏信息”只产生一个对比对话框：最外层固定为左右两栏，左栏是当前信息，右栏是最新结果；每一栏内部的上半部再分为左侧短元信息（标题、开发商、发行商、类型、玩家数和年份等）与右侧 3:4 封面，下半部展示该栏完整简介。对应字段一致显示绿色边框，不一致显示红色边框；右栏短字段、简介和新封面可编辑或替换，左栏保持只读。取消丢弃本次结果，应用覆盖当前客户端状态、清除不兼容的旧候选素材选择并触发实时保存；页面下方不得不断追加查询结果卡片。

“丢弃条目 / 通过并发布”位于页首“审核决定”卡片，不再显示与运行检查重复的“可以发布”，也不收集发布说明或丢弃原因。决策前先冲刷尚未落盘的实时保存；提交时按钮显示处理中，成功后 toast 反馈并替换到当前筛选下的相邻条目，队列为空则返回列表。目标目录/default DOS entry 改变或 CoreArtifact/DAT/BIOS 配置漂移后，旧 Validation 明确标为“已过期”；只有当前 READY Validation 可发布。若相同内容在当前未删除游戏中已存在，正文常驻提示并链接已有游戏；点击发布弹出危险确认框，主按钮命名为“仍然发布为新游戏”并说明可能产生重复条目。页面加载后才出现的重复项由 approve 的 `409` 打开同一确认框，不能降级为普通 toast 或要求用户重新上传。

“能不能发布”直接显示游戏文件、运行检查和依赖检查三条普通语言结论，不提供只包含内部 ID 的技术详情。来源为 ZIP 时“来源文件”默认展开，展示成员文件名、大小和 CRC32，并在固定高度内纵向滚动；来源文件已有 SHA-256 时用“大小 / 截断 hash”展示并用 tooltip 提供完整值。页面不使用无来源的分隔线。

一期不提供批量 Approve/Discard。每个条目的草稿、候选、Validation、ETag、幂等键和最终 ReviewEvent 都独立，必须逐条确认；提高大量 ROM 审核效率依靠可见队列、批次筛选、任意跳转和决策后自动聚焦下一项，不能用一次点击盲目发布整个批次。

“审核历史”是独立的只读审计页；列表不展开无解释的技术 UUID，点击整行以对话框展示审核完成瞬间的标题、简介、开发/发行、类型、玩家、年份和封面快照。最终审核事件引用的 READY 候选媒体在条目离开待审状态后仍可读取；历史媒体确实缺失时显示明确占位，不渲染裂图。完整输入/输出、配置和 provider 证据仍由只读事件详情 API 保留，历史页不能修改旧事件或复用为待审核队列。

### 7.3 游戏管理

列表页先用等宽摘要卡展示全部游戏、运行异常、缺少封面、资料不完整和用户不可见数量；摘要基于完整管理集合计算，不随当前页分页漂移。下方工具条在固定高度内提供即时名称搜索、基础平台、依赖平台的游戏目录、用户状态、运行状态和排序；任一条件变化只更新结果表、URL 与页码，不触发整页刷新，也不插入会推动页面的筛选标签。`/` 在非编辑控件中聚焦搜索框。

游戏以紧凑表格展示 70×84 封面缩略图（无封面显示包含标题/平台的占位）、标题/平台/年份/目录、用户状态、目录默认核心当前运行状态、推荐运行方式与最近更新时间。每页固定 6 条并提供上一页/下一页；1280px 下宽表只能在带可见焦点的自身容器中横向滚动，封面列与管理操作列 sticky，页面本身不能横向溢出。正常与异常状态都带文字，不只依赖颜色；“导出当前列表”仅导出当前筛选后的结果。管理按钮进入 `/admin/games/:gameId`。

管理详情不是用户游戏详情复用表单。页头下依次为封面/身份/状态概览、所属目录/推荐运行方式/当前文件/最后验证/关联存档摘要，再进入固定四区；不显示“基本信息 / 媒体 / 游戏文件与运行 / 管理操作”锚点导航，用户按页面自然滚动浏览：

1. “发布信息”：标题、描述、年份、开发商、发行商、类型、玩家数；保存创建新的 MetadataRevision，必须携带当前 ETag。初始进入、用户没有修改任何字段，以及保存成功后，“保存新版本”都必须禁用；只有当前表单与已保存基线有实际差异时才启用。
2. “媒体”：当前封面/背景/截图及替换入口；封面容器始终保持 3:4，在双栏中按可用高度等比放大，底边与“媒体”内容容器对齐；图片居中裁切填满。上传成功创建新 Asset，不原地覆盖旧 Blob。
3. “内容与运行版本”：先展示 Game 当前/历史 GameContentRevision 及用户文件清单，再按 Core 展示稳定 GameVariant、当前/历史 VariantRevision、CoreArtifact、DAT、派生文件、依赖诊断和兼容状态；替换游戏文件先走 upload 会话与可观察 Job，只有新内容对目录默认 core 验证 READY 且配置快照未漂移时才原子切换 Game content 与目标 Variant 两个 current，失败保留旧版本并提供 retryable 重试。
4. “管理操作”：重新刮削只生成候选预览，完成后自动打开与审核页一致的对比窗口；最外层保持“当前信息 / 最新候选”左右两栏，每栏内部上方为“短元信息 + 3:4 封面”、下方为完整简介。应用时未提供的字段和媒体保持当前值，确认后才创建 metadata revision。移动目录必须先主动选择目标并点击预览，若返回 `VALIDATION_PENDING` 就在原对话框展示可返回的任务进度并等待，任务完成后自动用新幂等键重新预览，绝不提前移动；软删除独立置于默认折叠的红色边框区，展开后才显示标题确认与存档/审核历史影响，历史引用不级联删除。

在 1920px 基线下，“发布信息 / 媒体”采用 `58% / 42%` 双栏，运行区、管理操作和移除区全宽；较窄桌面可顺序折叠为单栏。分区标题只显示“发布信息”“媒体”“游戏文件与运行环境”“管理操作”“从游戏库移除”，不增加“信息版本 · N”“媒体资源”“运行状态正常”“维护工具”“危险区域”等装饰标签；版本数量留在顶部概览，兼容状态留在运行摘要，避免标签重复信息层级。

所有长任务进入任务进度并可回到此页；成功/失败反馈必须对应实际 revision/job ID。页面不得提供直接编辑 CoreArtifact/DAT hash、宿主路径或物理 Blob 的字段。

文件上传使用隐藏原生 input 和有明确中文名称的按钮触发，不能把浏览器本地化的 “Choose File” 作为正式界面。主区域使用“推荐运行方式、兼容状态、最后验证”等用户语言；完整 revision/artifact/DAT ID 只在“技术详情”展开区显示。成功与错误反馈使用不改变页面高度的浮层，避免操作后工作台抖动。

### 7.4 游戏目录

页面标题、后台菜单统一使用“游戏目录”；API、数据库与领域模型仍使用 PlatformInstance。页头提供“排序说明”和“新建游戏目录”，后者打开宽 520px 的右侧 Drawer，按“选择游戏平台—定义目录信息—选择推荐运行方式”三步填写并展示创建预览；Drawer 标题只显示“新建游戏目录”，不再重复“新建平台实例”标签。创建表单不展示网址标识等技术字段；不可变 slug 由服务端生成，初始顺序自动追加到末尾。

页头下方固定高度筛选区提供目录名称/平台/说明即时搜索、游戏平台、启用状态和排序方式；筛选只改变列表，不整页刷新，也不插入推动页面的条件标签。其后只提供“全部”“已启用”“已停用”三个可操作的快捷筛选按钮，不展示无对应筛选行为的空目录或 Arcade 统计胶囊。列表每行固定约 88px，依次展示全局顺序、名称/说明、游戏平台、游戏数、推荐运行方式、启用状态和操作菜单；名称和用户说明从操作菜单进入紧凑行内编辑，说明编辑框保持单行控件高度并在内部滚动，不能撑高列表行。推荐运行方式直接使用下拉框，选择后仍执行影响预览与确认；启用状态使用 checkbox，并允许非空目录切换，以控制关联游戏是否出现在用户侧。操作菜单中非空目录的删除禁用并解释原因，空目录可经确认删除。

排序不暴露数字输入，使用拖拽手柄，并提供上下方向键等价操作；仅在无搜索/筛选且排序方式为“展示顺序”时允许调整，筛选态明确提示仅查看。排序结果通过带所有目录版本的原子接口保存。排序、内联编辑、核心切换和启停成功后就地更新，不插入会推动表格的成功提示条，失败才显示错误。

默认核心的列表态以“推荐运行方式”下拉框显示当前值。选择另一核心会自动请求影响预览；预览不提交，无论受阻游戏数是否为零，提交前都必须在应用对话框中再次明确确认。

### 7.5 BIOS 与 DAT

BIOS 文件页默认展示当前游戏库实际所需项，并可在页面内无刷新切换完整 BIOS 目录。页首固定显示当前范围、缺失/阻断、需要核对和已就绪四项摘要；关键字、运行方式和状态筛选以及“需要处理/必需/可选”快速筛选只更新下方结果，不插入推动内容的标签。列表先展示会阻断或需要核对的项目，再展示已就绪与可选项；当前接口不能证明的“影响 N 款游戏”不得用示例数字冒充，改用真实的当前游戏库引用、阻断和可选语义。STATIC 文件的期望/当前 MD5 直接展示，`HASH_WARNING` 明确说明仍可启动。已安装的 Arcade `DAT_MACHINE` ZIP 把文件名显示为可聚焦按钮；点击打开宽对话框，左侧为该 Requirement 锁定 DAT 版本要求的 name/size/CRC 完整列表，右侧为安装时已安全扫描并落库的 ZIP 实际条目完整列表，不增加居中的第三栏；每个列表项直接标识匹配、内容匹配但改名、校验不一致、缺失或额外文件。两栏共享纵向滚动位置以便目视比对。HTTP 读取不重新解压用户内容。

街机数据目录页把每个 Arcade Core 当前实际启用版本放在首屏卡片中，真实展示来源、EmulatorJS/bundle 版本、machine/BIOS 数、匹配状态和启用时间；候选与历史版本另行列表。上传入口使用右侧 Drawer，流程固定为“上传 → 解析 → 后台差异比对 → 查看差异 → 启用”，未选择文件时开始按钮禁用，Drawer 支持 Escape、遮罩和显式取消关闭。解析候选必须显示待解析/解析中/失败/已取消，差异阶段必须显示尚未生成/排队中/比对中/可以启用/已失效/比对失败等明确文本状态。排队和运行时用禁用的“差异比对中…”替代查看/启用；失败或因同 CoreArtifact 另一 DAT 启用而失效时提供“重新生成差异”，无需重新上传。运行中的用户 DAT 可请求取消解析，已取消候选只提供删除与重新上传，不显示“重试”造成旧解析任务复活。

查看差异、启用和预览回滚使用同一个宽对话框，展示当前与目标版本、四组真实增删改摘要、目录/Variant 重校验影响、解析警告和分页差异明细；只有带启用/回滚意图时才显示提交动作，普通查看仅关闭。页面不展示只包含内部版本 ID 或原始 JSON 的“技术详情”，用户通过来源、处理状态、收录内容、匹配情况和可读差异完成判断。浏览器只读取后端物化结果，不现场解析原始 DAT。完整规则见 [BIOS 与 Arcade DAT](./bios-and-arcade.md)。

## 8. 无障碍与键盘

- 所有图标按钮有可读 label；状态不能只靠颜色。
- `Tab` 顺序与视觉顺序一致，焦点样式清晰。
- 搜索框由容器 `:focus-within` 提供可见焦点；筛选字段都有可见 label；无搜索、筛选或排序参数时不显示“清除全部”，存在任一活动条件时在固定高度摘要中显示“筛选条件已应用”与“清除全部”。
- 应用对话框使用 `role="alertdialog"`、可读标题/说明和 `aria-modal`；打开后焦点进入对话框，Tab 不离开对话框，关闭后焦点返回触发控件。
- 表格内下拉和上传按钮也必须满足 42px 最小高度；隐藏文件 input 的可见触发器必须是可聚焦按钮。
- 下拉框状态文本包含“目录默认/缺 BIOS”等语义。
- 启动后保留 `Escape` 的浏览器全屏语义，并提供明确的退出游戏按钮。
- 动画尊重 `prefers-reduced-motion`。
