# 审核完整性与运行诊断：候选验证

2026-10-12 在独立 `review-integrity` PFB 实施。Retrom 基准为 `e2e55759ff290ba29f07a4c471baec6751f3db68`，runtime 基准为 `fca4138a53e446c9933c660df2909a0e73ac7841`，两仓库使用 `codex/review-integrity`。Provider 基座为正式 `v0.62.0`；运行工具为本 PFB 的不可变源码快照。此记录针对本次改动，不提升此前全平台兼容矩阵的状态。

## 行为与边界

管理员可从普通游戏详情或游戏管理详情点击“退回审核”。既有 Game 从 `published` 转为 `pending_review`，仅更新状态、版本和更新时间；ID、文件、媒体、运行配置、标签以及私人收藏、最近和存档关系保留。普通用户无按钮，直接调用返回 403。退回后公开详情和新游玩 Run 返回 404，管理员仍可审核试玩；存档暂时不可恢复，重新审批后恢复可用。版本冲突不会覆盖较新状态。

审批前由 runtime 检查当前所选核心、已保存 DAT 条目实际要求的游戏成员及选定 Parent、独立 BIOS。缺件、大小错误和无法检查的内容阻止手动及快速审批；同名同大小但 CRC 不同仍仅提示，人工可直接批准，快速审批跳过，试玩保持可选。检查位于文件准备与 CLI 边界，发布事务内再次检查同一 Game 版本。正常启动保留已有规则，没有新增必需成员完整性门禁。

共用检查覆盖 FBNeo、MAME 2003、MAME 2003 Plus、MAME Current。仅检查当前游戏实际引用的 Parent 成员，忽略可选成员及 NO_DUMP，BAD_DUMP 中明确存在的 CRC 成员仍要求提供。独立 BIOS 按自身要求检查，不因游戏包内含有固件而省略。原始包及 BIOS 字节保持不变，无特定游戏映射或自动修补。

同时将 FBNeo 事实数据同步为发货 `v0.62.0` 配套 DAT 的 8,424 条记录，修正旧事实数据与实际核心名录的差异。DAT SHA256 为 `b7192ff1aa025b8281979d96e12c8cf82e4df43a3afb81af6b668a4a7bbb90f9`；刷新需匹配已登记的摘要。没有修改核心二进制、Provider pin、数据库表或 migration。

## 追加验证：原生启动失败原因

同一 PFB 补齐 EmulatorJS 与 Retrom Provider 的原生诊断采集、结构化失败和前端展示。普通 EmulatorJS 启动也开启原生日志，但不启用 EmulatorJS 调试输出；在静默控制台前收集 stdout/stderr。MAME Current 将启动失败保留为 `MAME_BOOT_FAILED / CONTENT`，携带原生证据。缓冲最多保留 8 条、每条 500 字符，失败信息优先于进度，版权、无害选项警告及调用栈不进入用户提示；路径、URL 和敏感数据沿用统一清理。完整结构化诊断仍可供调试事件读取。

前端显示中文错误摘要和核心原因，保留换行、长文本换行与既有有界弹窗。`FATAL_ERROR` 后的 mount Promise 拒绝不会覆盖具体失败。没有增加启动时 DAT 完整性检查，也没有修改数据库、核心二进制、原始 ROM 或 BIOS。缺件样例继续处于待审，审批返回 400，审核试玩仍可创建 Run。
