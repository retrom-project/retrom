# ShiinaRio 核心接入

ShiinaRio（椎名里緒）使用独立的 `retrom-runtime / shiina-rio` Target，核心为 [OpenShiina fork](https://github.com/retrom-project/OpenShiina)。fork 在同一仓库共享原生与浏览器 C# 解释器、格式解码及渲染代码，新增通用 Browser 工程；runtime 负责内容读取、输入、生命周期和存档。Retrom 通过现有扫描、审核、发布和 Launch 流程使用它。

导入已安装的完整游戏目录，选择 `SHIINA_PROJECT`、`RIO.INI` 和 OpenShiina。保留用于版本识别的游戏 EXE、WAR、补丁包与散落的影片文件；浏览器不执行 Windows EXE。安装器、光盘镜像和缺少伴随文件的单个 WAR 不能直接视为可运行项目。加密方案必须匹配具体发行版，文件扩展名或重命名 EXE 不能证明兼容。

桌面 Chrome 需要跨源隔离、SharedArrayBuffer 和 OffscreenCanvas。解释器在专用 Worker 中运行，使用有界的 64 KiB 文件桥接；原始游戏文件通过公共 Content I/O 按稳定的项目摘要和逻辑路径读取。默认按需模式不在启动前物化整个 WAR。选择“下载完成后开始”时，公共持久缓存必须先校验全部项目文件，上报进度，直到退出才释放使用租约；完整缓存失败会明确中止启动。

高分辨率作品需要较多内存。当前浏览器构建允许 WASM 线性内存增长至 4 GiB，初始大小仍为 32 MiB；实测 Sorcery Jokers 的 Chrome 游戏渲染进程峰值约 2.5 GB RSS。该测量包含浏览器和原生解码内存，不能等同于托管堆或游戏虚拟内存，也不保证低内存设备可运行。

游戏使用原生存档，公共语义为 `GAME_SAVE`、格式为 `shiina-game-save-v1-storage-v1`。先在游戏内 SAVE，再同步到 Retrom；新 Launch 在引擎启动前导入原生文件，随后在游戏内 LOAD 并继续。全局设置和启动续玩文件不等于手动进度；当前进度准入仅验证了 Sorcery Jokers 的手动槽位。宿主不解析核心私有封包，压缩由 Provider 公共边界执行一次。

标准手柄方向移动指针，A 为鼠标左键确认，B 为右键，LB 降低指针速度。键盘与鼠标输入保持独立。暂停、失焦和退出释放按键，退出取消读取并清理 Worker、音频和缓存租约。

首次验收限定桌面 Chrome、日文 Sorcery Jokers v1.01。中文《千金逼我嫁／黙って私のムコになれ！》样本未通过加密方案和脚本解码，保留审核失败状态。其他作品、汉化版、引擎版本、手机与 Safari 均需单独验证。真实剧情、性能及候选状态见 [项目验收](project-acceptance.md)；runtime 的声明、能力和核心指纹仍是唯一运行事实源。

当前为 PFB 候选接入：核心有可重复构建的归档、来源和许可证，runtime 显式登记开发输入。正式发布需依次固定不可移动的核心 Release、runtime Release 和 Retrom Provider pin，并复验相同产品链。候选路径和摘要不得写入正式锁定文件。

真实影片曾暴露重复保留完整 MPEG 导致内存耗尽、逐条解释原生 3:2 像素放大例程导致约 0.7 FPS，以及默认 2 GiB WASM 上限使 OP 后章节分配失败。核心分别使用可独占影片输入、签名匹配的等价像素内核和更高的内存上限修复。像素内核与原生代码比较九个真实影片帧及整幅随机图像，每次 6,220,800 输出字节和 12 个暂存字节全部相同；未匹配签名仍走解释器。最终候选完整重播 OP，再持续推进后续章节两分钟并进入章节选择，没有复现内存错误。
